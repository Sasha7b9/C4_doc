First we setup our server:
Code: Select all
TheNetworkMgr->SetProtocol(kGameProtocol);
TheMessageMgr->SetMaxPlayerCount(TheEngine->GetVariable("maxPlayers")->GetIntegerValue());
TheMessageMgr->SetSnapshotInterval(TheEngine->GetVariable("tickDelay")->GetIntegerValue());
TheNetworkMgr->SetPortNumber(kGamePort);
TheMessageMgr->BeginMultiplayerGame(true);

Now the client:
Code: Select all
TheNetworkMgr->SetProtocol(kGameProtocol);
TheNetworkMgr->SetPortNumber(0);
TheMessageMgr->BeginMultiplayerGame(false);
NetworkAddress address = MessageMgr::StringToAddress(host);
address.SetPort(kGamePort);
TheMessageMgr->Connect(address);

When a client connects, server sends him a world info (this time just a world name):
Code: Select all
player->SendMessage(ServerWorldInfoMessage(currentWorld->GetWorldName()));

Client receives this message, loads the world and sends his current style to the server (for example it's color):
Code: Select all
const ServerWorldInfoMessage *mServerWorldInfo = static_cast<const ServerWorldInfoMessage*>(message);
LoadWorld(mServerWorldInfo->currentWorld);
TheMessageMgr->SendMessage(kPlayerServer, ClientPlayerInfoMessage(currentPlayer->playerStyle));

Server receives client's style, creates a model and a controller for it and sends everyone (including this client) a message to do the same thing:
Code: Select all
const ClientPlayerInfoMessage *mClientPlayerInfo = static_cast<const ClientPlayerInfoMessage*>(message);

ServerPlayerSpawnMessage mServerPlayerSpawn(gamePlayer->GetPlayerKey(),
                                            mClientPlayerInfo->currentPlayerStyle,
                                            lastPos,
                                            -1); //this is a starting controller index, if -1 then controller's index is not changing

mServerPlayerSpawn.currentControllerIndex = PlayerSpawn(&mServerPlayerSpawn)->controller->GetControllerIndex();
TheMessageMgr->SendMessageClients(mServerPlayerSpawn);

Clients receive this message and create the same model and a controller locally, followed by changing controller's index:
Code: Select all
const ServerPlayerSpawnMessage *mServerPlayerSpawn = static_cast<const ServerPlayerSpawnMessage*>(message);
GamePlayer *gamePlayer = PlayerSpawn(mServerPlayerSpawn);
if (gamePlayer == currentPlayer)
  currentWorld->chaseCamera.ChangeCameraTarget(currentPlayer->controller->GetTargetNode()); //just attach our camera to our model

So the models with controllers are created identically:
Code: Select all
GamePlayer *PlayerSpawn(const ServerPlayerSpawnMessage *mServerPlayerSpawn)
{
  MyController *controller = new MyController(mServerPlayerSpawn->currentPlayerKey,
                                              mServerPlayerSpawn->currentPlayerStyle,
                                              mServerPlayerSpawn->currentPosition,
                                              mServerPlayerSpawn->currentControllerIndex);

  GamePlayer *gamePlayer = static_cast<GamePlayer*>(TheMessageMgr->GetPlayer(mServerPlayerSpawn->currentPlayerKey));
  if (gamePlayer)
    gamePlayer->controller = controller;

  return(gamePlayer);
}

Controller's constructor just does something like this:
Code: Select all
if (controllerIndex >= 0)
  SetControllerIndex(controllerIndex); //here we set our controller index if it's not -1
model = Model::New("dummy");
model->SetController(this);
TheWorldMgr->GetWorld()->GetRootNode()->AddNewSubnode(model);

At this stage controller on a server and on a client is created and has the same index. Now we can start sending some state info:
Code: Select all
void MyController::SendSnapshot()
{
  TheMessageMgr->SendMessageClients(ServerPlayerStateMessage(GetControllerIndex(), serverPos));
}

And receive this info:
Code: Select all
void MyController::ReceiveMessage(const ControllerMessage *message)
{
  switch (message->GetControllerMessageType())
  {
    case kMessageServerPlayerState:
    {
      const ServerPlayerStateMessage *mServerPlayerState = static_cast<const ServerPlayerStateMessage*>(message);
      clientPos = mServerPlayerState->currentPosition; //just put controller in this position without any interpolation or prediction

      break;
    }

    case kMessageClientPlayerState:
    {
      const ClientPlayerStateMessage *mClientPlayerState = static_cast<const ClientPlayerStateMessage*>(message);
      serverAct = mClientPlayerState->currentAction;

      break;
    }
  }
}

Information about key presses is sent like this:
Code: Select all
void MovementAction::Begin()
{
  if ((TheGame->currentPlayer) && (TheGame->currentPlayer->controller))
  {
    TheGame->currentPlayer->controller->clientAct = (TheGame->currentPlayer->controller->clientAct | movementFlag);
    TheMessageMgr->SendMessage(kPlayerServer, ClientPlayerStateMessage(currentPlayer->controller->GetControllerIndex(), currentPlayer->controller->clientAct));
  }
}

Allmost the same for End();

And some initial state sender:
Code: Select all
void Controller::SendInitialStateMessages(Player *player) const
{
  player->SendMessage(ServerPlayerSpawnMessage(PlayerKey, currentPlayerStyle, GetControllerIndex()));
}

When a player disconnects the game, server and client behaves identically:
Code: Select all
case kPlayerDisconnected:
{
  if (gamePlayer->controller)
    delete gamePlayer->controller->GetTargetNode();
}

The same for Timeout.

Re: Multiplayer basics

by Eric Lengyel » 07 Sep 2009, 02:09

A controller doesn't have a valid controller index until you explicitly assign one to it. You must call World::NewControllerIndex() on the server and use it to set the index for the controller when it is created on all machines. In the demo game, a message is sent from the server to everybody (including the server itself) whenever a new controller needs to be created, and that message includes the controller index returned by World::NewControllerIndex(). When the controller is created, the code on each machine calls Controller::SetControllerIndex() to set the index for that new controller.

You should not need to call MessageMgr::Synchronized() when receiving ordinary controller messages. This function just tells you whether the messages you're currently receiving are part of the initialization phase when a client connects to a server (not synchronized), or where you're currently in normal gameplay (synchronized).
