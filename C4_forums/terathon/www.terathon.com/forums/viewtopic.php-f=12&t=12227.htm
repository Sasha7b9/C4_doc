Re: Does it use deferred rendering?

by MACK » 22 Sep 2012, 16:10

A few people have occasionally asked if it is possible to have their own renderer.
I don't think it has ever been successful.
The C4 engine is not really designed that way AFAIK.

It would be much better if you used C4 rendering, and work with it.

The Shader system is much more robust than you might think.
And the planned lighting and atmospheric shaders will be also be a huge plus.

The road map for next major version is:
Custom light shaders, independent of existing material shaders.
Custom atmosphere shaders (for fog effects, etc.)
Custom post-processing shaders.
New ambient lighting features.
New built-in post-processing effects.
High-dynamic range (HDR) rendering.
Particle system editor.
New underwater rendering capabilities.
Foliage painting tools (grass, bushes, rocks, etc., mixed at specified densities and randomly placing on terrain under brush).


And like I said, that is on top of the already incredible shader system that is platform independent.

by DaveH » 22 Sep 2012, 23:14

Hey thanks for the nice feedback.
It's fractal, I build the first five iterations on the CPU, then use 11 iterations on the GPU to define the final accurate height, the rest is a series of IF statements according to slope angle and weeks of work refining the shader values. The grass is drawn to a texture by drawing polygons vertically in a random way, it's all about random numbers. The thing about deferred rendering is the sky is only drawn where it's seen and I have the ray direction from the camera so everything can be worked depending on time of day etc. The night sky as seen on my other video has stars with random fractal positions, it's not that hard once you have the basic fast equations. To carry on I "just" need a slim game API to help save time. I thought that c4 was getting a lot of praise for it's programming cleanness to enable me to use it.
I'm getting 50-80 frames a second on a gtx260 at 1920x1080 res.

Now that I have seen a little more about how it works,
A deferred system is probably not even needed. The sample video suffers from a sort of "pixelation" effect in the rendering that does not happen with C4's system.

It is possible that C4 could achieve even better terrain appearance for Dave -- by allowing C4 to generate the voxels from his fractal data.

First, DaveH could generate the voxel data by creating height maps from his fractal system.
He would have to supply the Terrain Palette though...

The rest would be handled almost automatically by the system.

Dave,
Have you tried creating height map data using your Fractals?
You could attempt a proof of concept for this using the C4 demo (freely available).
Start by converting the fractal data to a height map, and then import the height map and convert to voxel in C4.

by MACK » 23 Sep 2012, 12:04

Hello DaveH,

Glad you will give C4 a try.

You might not be losing as much as you think with the loss of "infinite" rendering distance.
The reason I say that is that you stated the fractals were pre-computed 5 levels.
Therefore, even your system, has a predetermined "set" of data which it uses.
Perhaps you have it so that additional areas are computed once the player camera "moves".
If that is so, then you will be happy to learn, that some programmers already do this.

If you do some searching on the forums here, you will find several people have successfully created "Infinite" landscapes by dynamically creating them as the game plays.

Therefore, you could achieve the same thing with a little effort.
However, there are some "limits"... to the size of the world that C4 can reasonably handle.
