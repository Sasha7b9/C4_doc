Rock wall Horizon map

by Jesse Meyer » 24 Sep 2011, 19:26

Hey guys,

I built a small test this weekend for Horizon maps. I had some issues last time I tried but this go around, I was pleasantly surprised! Each HM is about 5k in size and the accompanying diffuse, compressed is 650kb.

I have decided to freely distribute these files. Use them however you wish - just don't sell them!
You can download them here: http://www.filedropper.com/rock_1

The normal map comes from a high poly source I built, and actually looks very close to HM's quality but minus the self shadowing. From a performance / quality trade off - I think it's best to compress the normal map and and use that exclusively for generic purposes. EDIT : You can half the HM resolution at import while retaining the same perceptive quality.

Without Horizon Maps (diffuse, normal, compressed)
2k in memory

With HM (same w/ two full resolution HMs)
15k in memory (so, 7k~ if you half)

Drastic in memory difference, but the self shadows are soooo cooool!

Re: Rock wall Horizon map

by Jesse Meyer » 25 Sep 2011, 11:48

Eric - Go for it! I feel honored!

Botagar - I should've documented how I made this texture. Honestly it was straightforward. The idea was (in Blender) I made a cube and subdivided the hell out of it - applied a distort modifier to it which feeds from a pseudo-random noise (or clouds, your own, etc) texture and from there the process was recursive.

So here's a step by step breakdown:

Cube to rectangle (ensure the triangle distribution is even)
Tessellate
Apply distort modifier - tweak feeding texture
Rinse or Repeat to tessellate

To save some time I only made 5 or so unique bricks and merely rotated them around so they visually do look unique. After that I pulled some of the proportions around to ensure the textures would bake nicely (Xnormal rocks!).

The final result is a tiling texture, but it wasn't right after the bake - I opened up GIMP and went to work. If I edited the normal map, I made sure to re-normalize (standard procedure).

Hope that helps!

Re: Rock wall Horizon map

by Eric Lengyel » 26 Sep 2011, 01:06

Jesse Meyer wrote:Is there any way the shader editor could present the number of instructions the current selected shader costs?


The number of instructions for the same shader can vary significantly from one GPU to another, and a higher number of instructions does not necessarily mean that a shader is slower then one with fewer instructions. I don't want people using the number of instructions as a measure of performance when they should be using actual timings instead.
