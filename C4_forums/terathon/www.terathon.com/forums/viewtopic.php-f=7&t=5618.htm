Application::ReceiveMessage is used for messages taht aren't ControllerMessages. Before calling ReceiveMessage message gets tested for various fields. One of such fields is messageType. If message type = kControllerMessage then engine assumes that it is ControllerMessages.
ControllerMessages are processed by trying to find controller by controlerIndex specified in ControlerMessage, then calling controller->ReceiveMessage(msg) one found controller.

I think it was written under influence of the Demo Game but that point about empty constructor is valid.
Thing is that you don't have anything to put into constructor at that point (because data is contained in message, but message hasn't been unpacked yet) hence the empty constructor should be used That empty instance is used to unpack rest of binary blob.

I believe that what You saw was just handing some constants or flags that where part of original message to make use of further Message subclassing (splitting messages into more subtypes).
