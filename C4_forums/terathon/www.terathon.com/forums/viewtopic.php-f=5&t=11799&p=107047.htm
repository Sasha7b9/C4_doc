Re: Block Compression Format

by Eric Lengyel » 03 May 2012, 12:48

When you check "Use block compression", the texture tool chooses the appropriate S3TC format based on the overall texture content. Basically, you get DXT1 compression (or BC1 in the new naming scheme) if your texture has no alpha channel, and you get DXT5 compression (or BC3) if your texture does have an alpha channel.

If you're importing a normal map, two things are possible: 1) If your raw image is a height map and you want the texture tool to make the normal map (the recommended case), then you should usually check "Use block compression", and the texture tool will put the x and y components of the normal in the green and alpha channels and use DXT5 compression. If you also create a parallax map, then compression cannot be used. 2) If you are importing a normal map that has already been generated from a height map (that is, it looks purplish already), then you can still compress it, but you must have the "Treat RGB channels as vector" option checked as well so that the texture tool knows to rearrange the channels.

For more information, see this wiki article:

What I mean is that a pre-made normal map can have much sharper details than you get in a height map. At least that is my experience from trying both normal maps and height maps generated with FilterForge. Importing the height map into C4 will result in a much softer look with the sharp details missing. Like if you'd run a blur filter over an image in PhotoShop. In some cases using an imported height map simply did not produce the final result I wanted.
