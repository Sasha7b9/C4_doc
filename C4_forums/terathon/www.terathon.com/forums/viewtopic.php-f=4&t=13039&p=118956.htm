Re: A little help understanding where GCC fits in

by Eric Lengyel » 18 Jul 2013, 23:34

In theory, binaries created by two different compilers for the same platform should be compatible if both linkers conform to the Application Binary Interface (ABI) defined for that platform. In practice, that isn't always the case, especially if you're dealing with language features that require a lot of compiler-specific support code (like exception handling). You just have to try mixing the binaries and see if everything works out.

On unix, using gcc is as trivial as installing it, then calling 'gcc myfile.c -o my_program_name'. Bigger projects need a build system to automate the process, but C4 comes with a Make-based system. The debugger is my best buddy. gdb is full featured. If you compile with debug symbols, and you invoke it with the right paths, it'll find your source files and match shit up. Watches? Got that. Inspection? Got that. How about interactive programming? A command like "print myObject->SomeMethod()" will call that method. It's got more features than I could possibly shake a stick at, and I don't use but maybe the most obvious 5%.

And I use Netbeans, like I said. It has a full set of bindings to gdb. So I don't have to invoke gdb with the ungainly command line invocations necessary to tell it where all of the appropriate files are. It also tracks all of your breakpoints, interprets structs and objects, and everything else that I expect of a debugger. What is it that VS debugger does that you expect gdb doesn't do?

I'm not some greybeard from the mainframe batch processing era. I grew up on Sega Genesis and N64, my first machine was a 486-DX2.
