Re: Tips and Tricks thread

by jimbobjames » 13 Sep 2008, 01:44

Here are some tips that I think might be useful for people starting out with C4.

----------------------------------------------------------------------------------------------------

1) Understand that the C4 "world" and the C4 "application" are different things.

World: You create and edit your game "world" using the C4 World Editor. The data structure which stores the world information is called the "scene graph" and can be accessed by right clicking on a viewport in the world editror and selecting scene graph. Example worlds which are shipped with C4 - like Water.wld, Lasers.wld and Mirror.wld - can be found under Data/Tutorial/world. You open a world using Ctrl-O / Cmd-O or using the Tools menu.

Application: The "Application" refers to your game code which you write and compile to a dll (on windows) and which is then used by the C4 engine (C4.exe) when you start it. Example applications which are shipped with C4 are SimpleChar.dll, SimpleBall.dll and Game.dll. etc. You tell C4 which Application to load when it starts, be editing this line in the file "Data/Engine/variables.cfg":

$applicName = "YourApplicationName";

So you can use the same application (code) to try out several different worlds. Set the $applicName to "Game", then open any tutorial world in the world editor and press Ctrl-P to try it out. The game world changes, but the game behaviour remains the same.

Likewise, you can try out different applications (code) in the same world. Just change $applicName to SimpleBall, then SimpleChar, then Game and each time, try out the world called "SimpleBall". So each time the world is the same, but notice how the Ball's behaviour changes depending on the application that you tell C4 to load.

2) Learn about Controllers. The key to C4 in my opinion is to understand that everything - i.e. every so called "Node" in the scene graph - that has a behaviour has an associated Controller. There is a tutorial on creating your own Controller over here. I highly recommend trying to write your own Controller - you can copy an existing controller, like say the "SimpleBall" Controller, rename it and then just make the changes you want in the Move or Travel functions.

and perhaps

3) When using the forums, you can click on "new posts" to get a list of posts which you haven't read yet. Clicking "active posts" is also sometimes useful.

1. The debugger is probably the most standard method of finding errors.
2. No exceptions are used in C4, ever.
3. C4 comes with a console window, so it is a simple matter of dumping text to it. You can also use file classes & the standard debugger.
4. C4 produces a C4Log hypertext file every time it is run. It lists attached input devices, GL extensions, system information and plug-ins.

by mschifter » 16 Aug 2012, 09:44

This definitely falls under the "Tip" category. It's not in the documentation (Eric added it in the support forum), so here goes...

You can't call FindNode() for a model until after that model has been preprocessed. Add the model to the scene first and preprocess it, and then you can call FindNode().


If you are using a MergeAnimator on a model, you must use FindNode() inside the PreProcess method of the controller. If you use it later, such as in the Move function, it will simply not work, and you will get just the second blend animator's output. SetTargetNode() makes no difference.

by ska » 30 Sep 2012, 21:30

Terrain tips!

*Make the base terrain with a decent number of triangles. Use the smooth brush to let all the terrain smoothed.

*In Places that you want more detail (like some canyon, or smaller places that the player need to pass through) create a new smaller terrain block with a higher resolution (more triangles). You can use the same terrain pallet for both blocks, and make the junction with the same texture (or use the paint space if you want) and the junction will be perfect.

*Use terrain block with lower resolutions for distant places, that the player won´t reach (like some scenery)

*In this places that are far way and have a lower resolution terrain block, try to use a palette with a bigger terrain texture size (you can change this on the texcord scale) SO your terrain will look more natural, and have less tiles.

by mschifter » 04 Oct 2012, 09:23

Some more Terrain tips:

Bryce 7.1 Pro has significantly more height map editing ability than the C4 Voxel editor, however it generates a triangle mesh as output. It has a Collada export feature, and several other formats for the mesh. There is a slider on output for adjusting mesh density so you can have multiple LODs for the entire terrain.

If you are looking for natural landscapes, there are a number of youtube bryce pro tutorials available that help you get the effects you want.

The level of sophistication of Bryce Pro for adjusting geometry as well as textures is very high. There is a learning curve to get going with the product, but the basics are taught by video and aren't tough.

As of this writing, Bryce 7 Pro is still free from [url]daz3d.com[/url]. Bryce 7 includes the ability to drop in model assets, and import formats are well-varied.

Another professional quality landscape editor that is now free is Vue 10.0.

These products will produce photorealistic basic landscapes -- their companies sell art assets to enhance their products and that's how they make their money.
