When a client joins a game, the server calls the SendInitialStateMessages() function for all controllers, and each controller should send whatever messages it needs to from inside this function. There are plenty of examples in the demo.

by Eric Lengyel » 02 Jul 2007, 17:04

Yes, that's how it currently works. The client machines don't calculate any collision detection, and rely on the server to tell them when collisions have occurred. With lag, this can result in some ugly cases where things don't go where they should for a little time before the collision message is received from the server, so I'm going to be changing things so that the client predicts collisions in more cases.
