UML Again

by DrVonBraun » 16 Jul 2013, 23:43

I havent completely given up the idea of using UML, I believe it must have some positive aspects otherwise it wouldnt be around. On the other hand, when I look at it it seems to me more like a justification for a new job description. You can't just use it on the side, you have to study it for months, probably take classes etc. It's more like a tool to create new jobs since it is basically eaual to a programing language in complexity.

However I think maybe when reducing it to a subset that is actually practical it can be used by a programmer to help with his job. My problem is when I want to use it, there's like 10 different diagram types, many of which are so similar that it's not always obvious what's the difference between them. Do I need all of them for a particular problem? Or only some? If so, which ones? And how do I know what diagram types are useful in a specific case? maybe the community of people who actually use it have already come to a consent which diagrams are useful and which are superfluous?

So my question is, for those who use it, what parts of it do you use? I find the sequence diagrams useful in many situations, but that's about it. Do you use other diagram types? If so which ones do you think are useful?

By the way, I have a program called Argouml installed which is a free UML 1.4 editor.

Re: UML Again

by cjacket » 17 Jul 2013, 00:06

The class diagrams and the sequence diagrams were the most helpful to me, but it depends on the size of your team. The more people with whom you need to communicate, the more useful UML can be communicating your ideas to team members. The use case is most helpful in the planning stages, but isn't as helpful to me in game design. With many UML programs you can actually create all the stubs for your software, but I haven't done that much. In reality, you really only want to define the public and protected interfaces of the classes to think through their interactions on a system level. Also, for sequence diagrams you normally would only need to do the most complicated processes.

Hi,

If you use a subset it can be very useful. Especially when you are starting to articulate how to go about writing code. However rather than using the UML editors I would say use the visual studio C# class diagram creator and probably some simple UML tool for sequence diagrams.

To a large extent mostly its been the class diagrams that have been the most useful as it allows me to have a bunch of functions defined as stub to see how it all fits together in a bigger vision. The sequence diagrams are helpful but then they can become cumbersome as each set of functionality will end up having one. For an individual I think it becomes too much work at once and you might end up spending too much time on this and not get anything done.

Other than that I don't think you need UML all the time but just some sort of documentation where you can plan how you are going about doing things.

Re: UML Again

by a2k » 17 Jul 2013, 10:16

Class diagrams are always the best place to start when learning UML, but as DrVonBraun discovered, it quickly becomes a mirror of the actual source code, which can easily be read and followed, and updating the class diagrams are a pain. That said though, if I had to deconstruct someone else's codebase I can see myself using class diagrams to make sense of things.

I like using sequence diagrams and use case diagrams for illustrating high-level functionality of some systems and functions. It helps after having stepped away from a project for a while and then seeing at a glance how the system was intended to work. Obviously, these would have to be updated as the systems change, so it has to be treated as a living document, or just kick out revisions.

To be honest though, I haven't used UML in a few years now, but I haven't built anything complex enough to warrant using UML, since following the code is pretty straightforward. I think clear, concise, well-named, well-commented code is more useful anyway.

The more gifted and talented engineers at my work typically don't use UML, and some shrug it off, but that's because they can retain all of the systems and their inner workings in their head (and that's also good for job security ). And if you can't do that, then that's a good argument for using UML.

by cjacket » 17 Jul 2013, 10:49

Depending on the version, you can actually have Visual Studio build class diagrams for you and keep them up to date, but the version that has that feature is quite pricey.

It sounds like you want something to help document your code so can understand it after you step away for a while. You can get some of this through code documentation.

If you use Visual Studio Pro or better you can purchase a tool that I like to use for auto-documenting my C++ code. The tool is called Automineer and it can be bought at http://www.atomineerutils.com/ . This plus Doxygen (a free open source code documentation utility)will let you build an html documentation of your code a lot like what Eric has for the API of the game engine. You can see doxygen at work by looking at the angelscript documenation sites at http://www.angelcode.com/angelscript/sdk/docs/manual/index.html
