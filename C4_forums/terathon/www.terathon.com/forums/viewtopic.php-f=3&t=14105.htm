Following a path with physics

by BORODA » 12 Feb 2015, 02:15

Hello.
I want to do a controller that moves along a path (bezier curve) and interacts with physics.
Moving along the path alone is a simple task. Just find the t (0...1) and calculate a point on the path, but this will not work with physics.
For example, there could be obstacles along the pass that needs to be jumped over.
I can think of 2 approaches currently, which, both, don't seem to be "the right way".
Approach 1:
1. Get the current position of the object on a path and get it's tangent.
2. Apply force to an object along the tangent direction.
3. Find a point on a bezier curve that is closest to a new object position and move the object to this position.
4. Rotate the object along the tangent of the new point.
5. Repeat.
The bad thing about this: when moving along a sharp turn there will be a slowdown because the nearest point on a curve will be closer than the distance that would be traveled without physics.

Approach 2:
1. Get the current position of the object on a path.
2. Find a next position of the object on a path using t.
3. Get the direction vector from start to end.
4. Rotate the object along the direction.
5. Apply force along the direction vector.
6. Find a point on a bezier curve that is closest to a new object position and move the object to this position.
7. Rotate the object along the tangent of the new point.
8. Repeat.
Second approach should be a bit more smooth with movement but it's more complex and potentially can break the physics interactions with small object that are at the edge of a path (due to possible shortcuts along the sharp turns).
Is there any way to do this "the right way"?


Thank you.

That's odd! I didn't know Google could limit access to samples by IP or region. Anyhow, the references the author makes are as follows.

Steering techniques [Reynolds 99]; The paper and code samples can be found here: http://www.red3d.com/cwr/steer/

Re: Following a path with physics

by datalol-jack » 13 Feb 2015, 05:27

Depending on how much physics you want, it can get complicated. One simple approach would be to follow a predefined path and enable sliding collisions around obstacles, with a physics volume a bit larger than your game object, so it only appears as if it's steering around the obstacle. For jumps, you could have triggers bound to obstacles that either give you a parabolic path of a jump over the item, or some predefined animated behaviour to scale and dismount the object. It has problems: obvious movement patterns and agents getting stuck between obstacles.

Alternatively, use navmesh pathfinding, I believe there's a community plugin for C4 for that on the forums. Defining your curved path on a navmesh means you aren't dealing with all possible environment configurations, just the passable bits, and both returns to path (run the algorithm from new location to the nearest next way-point, then resume on route) and jumps are possible to define.
