Sound in referenced worlds?

by David Vasquez » 17 Jul 2006, 01:45

When I attach a sound to a geometry that is directly instanced in the world, it plays correctly.

However, if I attach a sound to a geometry in a world that is then placed using a Reference marker, the sound does not play.

Here is the code I am using:

Code: Select all
OmniSource*      buttonSound(nullptr);
buttonSound = new OmniSource(upSoundName, soundRange);

if (buttonSound != nullptr)
{
   Point3D nodePosition = geometry->GetNodePosition();
   Zone *zone = geometry->GetWorld()->FindZone(nodePosition);
   buttonSound->SetNodePosition(
      zone->GetInverseWorldTransform() * nodePosition);
   zone->AddNewSubnode(buttonSound);
}


Is it possible to have sounds emanating from referenced worlds?

Re: Sound in referenced worlds?

by Eric Lengyel » 17 Jul 2006, 10:59

I think I see the problem. You're searching for the right zone using the node's local position instead of its world position. If you're just putting the sound at the same location as another node, the following code should work fine:

Code: Select all
OmniSource *buttonSound = new OmniSource(upSoundName, soundRange);

Zone *zone = geometry->GetOwningZone();
buttonSound->SetNodePosition(geometry->GetNodePosition());
zone->AddNewSubnode(buttonSound);


You could also just make the sound a subnode of the geometry and not even bother setting its position:

Code: Select all
OmniSource *buttonSound = new OmniSource(upSoundName, soundRange);
geometry->AddNewSubnode(buttonSound);


By the way, it's impossible for the new operator to return nullptr. It'll throw an exception if you run completely out of virtual memory (in which case it's unlikely that anything works on your computer).

by Eric Lengyel » 17 Jul 2006, 23:19

Huidafa wrote:Very good. I'll start using try/catch exception-style programming and get rid of those checks.


I really don't think that's necessary in any practical situation. If memory can't be allocated on a PC, then you're going to be in a heap of trouble, no pun intended, and you'll have no choice but to quit anyway. Consoles might be a bit different, but even they are moving towards virtual memory systems. By the way, you can call new(std::nothrow) if you want a nullptr back instead of an exception, but it's the same situation again: if allocation ever fails, you're basically screwed.
