by Eric Lengyel » 11 May 2006, 14:16

You can get the view direction in several different ways. In the character's local space, the x-axis points in the direction he's facing, so if you grab the world transform and look at this first column, you'll get a view vector. The world transform won't be updated until after the Travel() function has finished, though, so you might want to do something like this from within the controller:

Code: Select all
Node *node = GetTargetNode();
Vector3D view = node->GetSuperNode()->GetWorldTransform() * node->GetNodeTransform()[0];


If you're using the SoldierController in the sample game, then his upper body will be twisted up to 45 degrees to look around, so you'd want to call FighterController::GetLookAzimuth() to get the world-space angle from the x-axis. This will also be the azimuth assigned to the stock cameras.

You're dividing by the radian angle in the last line. When I change it to the following, I get correct numbers:

Code: Select all
float angDeg = angRad * K::degrees;


(K::degrees is a special constant that converts radians to degrees -- it's equal to 180/pi.)

Note that if the stock character is strafing, then his transform is rotated 45 degrees toward the direction of movement, but his upper body is twisted back so that you're looking straight ahead.

by Eric Lengyel » 13 May 2006, 22:59

gogo wrote:Eric, your comment about the strafing offsets begs the question, how do I know at this point that I am strafing?


Just call FighterController::GetMovementFlags(). If either kMovementLeft or kMovementRight is set, then you're strafing. Note that it's possible that both of these are set (if both keys are down), in which case they cancel each other out.

gogo wrote:The collision normal depends as much on the geometry of the collider as it does on movement angle, no? I assume if I'm strafing right, the transform will be -45 about Z, and strafe to the left is +45 about Z. Is this correct?


That's correct.

gogo wrote:So, now I have the angle between my view and the collision point. I need to determine which side of me the collision happened on. I know that the view vector is [1,0,0] in character space, so if I get the collision vector in character-space, I should be able to just check the sign of the Y component to get the side of the body the collision is on, right? So, should I do an Inverse World transform of the Target Node applied to the collision vector for this?


At the time that you're doing your calculations, the character's world transform hasn't been updated yet. But you can calculate the transform yourself as before by multiplying the supernode's world transform by the character's node transform:

Code: Select all
Transform4D charWorldTransform = targetNode->GetSuperNode()->GetWorldTransform() * targetNode->GetNodeTransform();


Then you could invert this and apply it to the direction to the contact point:

Code: Select all
Vector3D charContactDir = Inverse(charWorldTransform) * worldContactDir;


I think I would actually do a calculation in world space, though. You could just rotate your world-space look direction 90 degrees clockwise and take a dot product with the world-space contact direction. Then positive means right and negative means left. The following line ought to do it, assuming that the z-coordinates don't matter:

Code: Select all
float rightOrLeft = worldContactDir.x * worldLookDir.y - worldContactDir.y * worldLookDir.x;


gogo wrote:Finally, when I walk up stairs, I am (correctly) getting collision events. If I want to recognize them as such (in order to ignore them, in my case), what is the best way to do this?


A couple of possibilities come to mind:

1) Just have a maximum threshold for the z-component of the contact normal. If it's above a certain value (like Sqrt(2)/2 for a 45-degree incline), then ignore the collision.

2) The stairs in the demo all currently have an invisible ramp on them. You could check the geometry that you hit for the invisibility flag and ignore it if set:

Code: Select all
if (GetCollisionState() == kCollisionStateGeometry)
{
    // Get geometry node that we hit
    const Geometry *geometry = GetCollisionData()->geometry;

    // See if it's invisible
    if (geometry->GetObject()->GetGeometryFlags() & kGeometryInvisible)
    {
        // ignore this collision
    }
}
