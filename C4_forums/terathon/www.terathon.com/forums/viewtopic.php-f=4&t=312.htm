by DanPartelly » 08 Jun 2006, 06:40

Genralizing, the problem you face is a pretty complex one, which have implication over network synch as well. You need to develope a general algorithm which deals with object relevance . In a single player this is simplier than in multiplayer.
For a multiplayer, an object can be relevant to more than one client, so things gets complicated. This will affect netwrk replication as well.

Not that you will have to deal with different game objects in different ways.
For exampel, a rotation controller may be disabled as long as the rotating object is not visible, but for other type of objects determing relevance is a bit more complicated than this.

You need to modify both the engine and game code to implement such a system, and it has a lot of pitflalls youll find along the way

Again , this is not something you can handle like that. The problem must be generalized. You say "player gets away from you". What you ? Who you ?
On a multiplayer machine there are more *you* =), each with his different set of relevant objects.

Kepp in mind, single player is just a particular case of multiplayer. Seeks general solutions, and theyll reward you. Seek a single player only solution, and youll see hell over the network =)
