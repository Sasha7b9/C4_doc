Re: Version 1.5 Beta Now Available

by Eric Lengyel » 29 Dec 2008, 19:15

smariobros wrote:there are some way to model the terrain without textures and map the textures after the modelling process?
I'm have problems with the visualization of the terrain without textures in the 3D viewport, with or without lights on


The terrain has a different tangent space configuration than everything else, so ordinary tangent-space lighting doesn't work. What you can do is create a custom shader that uses the special terrain processes (e.g., Terrain Diffuse Reflection instead of Diffuse Reflection), and it will be lit correctly without a terrain palette applied.

smariobros wrote:and about physics, rigid bodys will have suport to joints and like? what types of primitives we'll have?


Rigid body physics has not been released yet. No details will be available until it's done.

Re: Version 1.5 Beta Now Available

by Eric Lengyel » 29 Dec 2008, 20:53

jwatte wrote:
terrain is not supported on ATI R300 and R400 series graphics hardware or on Intel graphics hardware


I presume this is because of 2048x2048 maximum texture size? Or is there some deeper techincal reason?
If only for textures, then you "could" theoretically run on that hardware, by dropping the top MIP map level?


No, the texture resolution has nothing to do with it. The engine already drops down to the highest mipmap size supported by the hardware when it loads a texture map.

The reason R300 and R400 hardware is not supported is because they are missing essential capabilities such as (to name one example) the ability to compute derivatives in the pixel shaders. Without this, it's not possible to correctly filter samples fetched from a texture palette.

Re: Version 1.5 Beta Now Available

by jwatte » 30 Dec 2008, 17:23

In general, if you are experiencing a lot of texture magnification, it means that replacing with a bigger texture will cause more texture data to be read, and put more stress on your memory subsystem. If you have a slower graphics card (64-bit, 128-bit or integrated) then this can sometimes be quite noticeable.

Also, if a texture is not DXT compressed, it will take 8 times the memory space as a texture that is DXT compressed, and thus render 8 times slower, all else being equal (which, of course, it's not usually). DXT compression can be a huge speed-up in some situations!
