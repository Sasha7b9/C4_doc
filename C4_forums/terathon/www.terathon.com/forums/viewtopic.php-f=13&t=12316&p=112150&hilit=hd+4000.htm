No Intel chips are officially supported by C4 Engine, however, I was wondering what experience user's have had with this particular chipset. Are there any users out there willing to report back on their experiences?

Re: Intel HD Graphics 4000

by Eric Lengyel » 28 Oct 2012, 23:56

We have actually been in close contact with several Intel engineers and developer relations personnel over the IVB drivers, and I've been told that some of my emails concerning driver quality have been run up to the VP level. This all started a few months ago when I first tested with IVB and posted a couple unfavorable tweets about the results. (They tell me that the tweets created a pretty big stir, which would seem to be supported by the number of Intel people who contacted me.) I have seen some efforts on their end specifically to make the C4 Engine work, but I have not been impressed with their knowledge of OpenGL or ability to correctly interpret the specification. The most recent driver that I saw still did not fare too well in my testing, but I believe there is a new driver available now that I haven't tested yet -- I'll give it a run and see how it does. The hardware itself seems much more capable than previous chips from Intel, so they just need to get the OpenGL driver into respectable shape.

Re: Intel HD Graphics 4000

by orhun » 06 Nov 2012, 12:01

One of the suggestions made in "Enabling High Performance Graphics Rendering on Optimus Systems" by Nvidia seems to work on one of my test laptops with Windows. My hope is AMD has something similar. Note: I haven't tried it with C4, yet.

Global Variable NvOptimusEnablement (new in Driver Release 302)
Starting with the Release 302 drivers, application developers can direct the Optimus
driver at runtime to use the High Performance Graphics to render any application–even
those applications for which there is no existing application profile. They can do this by
exporting a global variable named NvOptimusEnablement. The Optimus driver looks for
the existence and value of the export. Only the LSB of the DWORD matters at this time. A
value of 0x00000001 indicates that rendering should be performed using High
Performance Graphics. A value of 0x00000000 indicates that this method should be
ignored.
Example Usage:
Code: Select all
extern "C" {
 _declspec(dllexport) DWORD NvOptimusEnablement = 0x00000001;
}
