Re: Character Controller class not working

by Benjamin Dobell » 20 Jan 2015, 12:16

By the way, I'm guessing the error is referring to the constructor and not the class itself.

In C++ if you don't define a constructor a default constructor (a constructor without arguments) is generated for you. In the case of sub-classes, the generated default constructor tries to call the parent's default constructor. But CharacterController does not have a default constructor.

Even adding a "using namespace C4" inside of the game's namespace doesn't help, and I just don't think the look-up rules defined by the C++ language are very well designed. It's a lot easier to just stuff everything into the C4 namespace, and then you don't have to worry about the conflicts.


You're in control of the classes in the C4 Engine and your game, so it works for you. But if we stick code in C4's namespace then I'd say we're just asking for trouble. All we need to do is use a class name that you then add to C4 in a future update and we've got a mess on our hands. Sure we can refactor our class name, but this is one of the problems namespace are supposed to solve.

In addition to:

Code: Select all
using namespace C4;


there's always:

Code: Select all
using C4::<type>;


Also, we may wish to integrate a third-party library that has name clashes with C4 classes. If we stick our stuff in the C4 namespace then I believe we'd need to explicitly reference the library's namespace all over the place as I don't think "using OtherNamespace::Type;" works when we're actually inside the C4 namespace (in headers etc.) - NOTE: I haven't actually checked this.

Of course, there's also the possibility we might explicitly want to name our class the same name as a C4 class, which is impossible if our game code is in the C4 namespace.

I'm not precisely familiar with the mess you're referring to regarding Fixed, Zone, Window etc. so perhaps I'm missing something. For all C4 projects I've worked on, we've always had our own namespace for game code and I don't recall this being problematic. It is very possible that we did have to namespace prefix certain C4 classes from time to time, but if we did the inconvenience was so minor I don't remember it. I feel as though the benefits (safety) of having your own namespace outweigh any inconvenience caused by the few times you may need to disambiguate a type.
