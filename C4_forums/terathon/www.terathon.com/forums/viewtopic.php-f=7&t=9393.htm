Re: C4's network messaging..

by CptnWaffles » 29 Jun 2010, 11:37

I had an issue like this recently where the message was being sent but I couldn't figure out where / if it was being received by the client. In my case, it was a matter of having a message type the conflicted with the engines message types. For example, the engine has a bunch of messages that enumerate from 1 to kMessageBaseCount. If your message uses a number in this range, the engine will interpret your message as a different type and send it in the wrong direction. To keep this track clean and clear you should keep all of your enumerated message types in the same file and have them start counting at that kMessageBaseCount.

Code: Select all
enum
{
    kMessageServerInfo = C4::kMessageBaseCount,
    kMessageSynchronized,
    kMessageDeath,
    ... (etc.)
};


Hopefully this helps!

void WF4Game::SpawnPlayer(WF4Player *player,long contindex)
{
   WF4World *world = static_cast<WF4World *>(TheWorldMgr->GetWorld());
   if (world)
   {
      const Marker *marker = world->GetSpawnLocator();
      
      const Vector3D direction = marker->GetWorldTransform()[0];
      float azimuth = Atan(direction.y, direction.x);
      long pindex;      
      if (contindex == -1) pindex = world->NewControllerIndex();
      else pindex = contindex;
      WF4BaseCharController * pc;
      pc = nullptr;
      pc = static_cast<WF4BaseCharController*>(SpawnObject("marine",marker->GetWorldPosition(),marker->GetWorldTransform().GetMatrix3D(),pindex));
      player->SetController(pc);
      pc->SetPlayer(player);

      if (TheMessageMgr->Server())
      {
         TheMessageMgr->SendMessageAll(SpawnPlayerMessage(player->GetKey(),pindex),false);
      }
      if (player == TheMessageMgr->GetLocalPlayer())
      {
         world->ChasecamPlayer(player);
      }
   }
}
Controller* WF4Game::SpawnObject(String<> itemname, Vector3D position, Matrix3D orientation,long controllerindex)
{
   WF4DefMap* def = WF4Defs->GetDef(itemname);
   if (def != nullptr)
   {
      WF4ConstBase * cb = WF4Defs->GetConstructor(def->GetValue("CONTROLLER"));
      if (cb != nullptr)
      {
         Controller* ct;
         ct = cb->NewConst();
         ct->SetControllerIndex(controllerindex);
         ct->Spawn(position,orientation,def);      
         return ct;
      }
   }
   return nullptr;
}

I got it working:

The solution was to not spawn the object on the server and THEN send the message to clients to do so. The controller index had to be requested from the world, the spawnplayermessage sent to all including the server and then let the server spawn the actual controller. This ensured no messages from the spawning would be sent to the nonexistent controller on client side before the controller was spawned by the spawnplayermessage.
