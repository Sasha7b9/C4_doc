Re: Wingball 0.5.2 Released

by Adam Golden » 03 Oct 2010, 12:22

yaure wrote:By the way Adam, if you can just make the DSA ext a variable, then we can just edit variable.txt in future updates. Its probably better to leave it on by default then.

Yep, I was actually right in the middle (like, while you were typing that) of figuring out what code I can use to enable/disable the extension, to do exactly that. I saw the other post about how to disable it, and clicking OK on the extensions window does it, so it can't be that hard. I'll be making it default to disabled, and have a variable to toggle it (which will eventually be a checkbox in graphics options). I'd rather have people 5fps slower and then discover they can get better performance clicking a checkbox, than to be 5fps faster and have black terrain.

Edit: I'll also be defaulting multisampling to a value of 1 to avoid Frank's main issue, which I believe would also happen with older drivers anyway. Between the two of those things changing, the frame rate shouldn't be affected for new installations, if not faster overall.

Edit: Done. DSA in future revisions will default off, and can be toggled with the "DSA" variable. Here's how I did it for anyone interested. All you have to do is drop this in, call "InitDSA();" in your Game constructor, and add C4API to export GraphicsMgr::GetExtensionData in C4Graphics.h. This is already tested.

Edit: (assumes you've made the change noted by Eric below)
Code: Select all
void Game::InitDSA()
{
   if (!TheEngine->GetVariable("DSA")) TheEngine->InitVariable("DSA", "0");
   if (TheEngine->GetVariable("DSA")->GetIntegerValue())
   {
      const GraphicsExtensionData *data = GraphicsMgr::GetExtensionData();
      data[kExtensionDirectStateAccess].enabled = true;
      GraphicsMgr::Delete();
      GraphicsMgr::New();
   }
}
