Re: Version 2.6 Beta 2 Now Available

by Eric Lengyel » 10 Jul 2011, 13:44

yaure wrote:the docs for DeferredTask still say
Deferred tasks can be persistent or nonpersistent. A persistent task continues to exist after it has been triggered, but a nonpersistent task is automatically destroyed after being triggered. By default, a deferred task is persistent. The persistence state can be changed using the DeferredTask::SetTaskFlags function.

this has changed to fire one time only, right?


The persistence of a task is not related to how many times it fires. The documentation is accurate. All tasks fire one time and one time only unless you explicitly call TheTimeMgr->AddTask() again. The persistence state simply determines whether the task self-destructs after it fires.
