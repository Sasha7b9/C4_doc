Can imposters imposter imposters?

by Jesse Meyer » 30 Mar 2015, 21:09

I need to reason about objects closer to the camera individually, but the further away from the camera, I prefer to handle sets of objects at a time to avoid the 'death by a thousand paper cuts'. If I have a group of 20 trees that occupy a tiny percentage of screen space off in the distance, I'd rather them all drawn together as a single imposter, and as the camera approaches, they turn into individual imposters, then finally into their 3D meshes. This a reasonable solution?

Re: Can imposters imposter imposters?

by Eric Lengyel » 30 Mar 2015, 21:32

This would probably be a viable optimization strategy, but the engine does not support it at this time. I suspect that the speed increase would be small because the engine already batches all impostors for a particular tree into a single draw call, and the overlap for multiple impostors in a small area of the screen wouldn't cost much.

Re: Can imposters imposter imposters?

by Eric Lengyel » 30 Mar 2015, 21:56

cbken wrote:Another feature that was discussed some years ago that I'd really like to see is a user definable cut off distance for objects. When farther away than the cut off it would not be rendered at all. This would help to keep the draw calls down and is especially useful for small objects and details.


You're in luck. This is something I'm actually adding to the engine right now, along with vegetation painting tools. There will be multiple "detail rings" with variable distances, and you will be able to specify which ring any particular geometry belongs to. So you can have grass disappear closer to the camera, and larger rocks disappear farther away, for example. There will also be an automatic clustering feature that can combine many instances of the same object (like a bush) into a single draw call that renders the cluster with GPU instancing.
