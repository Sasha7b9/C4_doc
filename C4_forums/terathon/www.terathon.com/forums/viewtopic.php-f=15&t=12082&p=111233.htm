looking for advice on Level of Detail with Blender workflow

by Baalfeus » 31 Jul 2012, 02:53

Hi all.

Im struggeling a bit with creating LoD versions of my models in Blender and am looking for a good workflow to make them, maybe someone has some tipps. I'm using the latest version of Blender (2.63). Here's some of my thoughts, what I found out so far and some questions that arose:

1. From high to low poly:
I didn't yet find a good way to reduce polys from my LoD0 to create lower detail meshes. The decimate modifier messes up the UV-Layout. In blender i can then unwrap the lower level model and bake new textures, but I think C4 needs all LoD-meshes to share the same textures (correct me if I'm wrong) and thus texturing gets messed up once I import the model and combine the LoD's. Another approach would be to manually edge-slide some loops towards the next closest loop and remove doubles then. My problem with this is, that I didn't find a way, that the edges slide on the UV too and thus leaving holes in the UV, so this isn't a viable option either. The new dissolve-tool works to some extent, but the mesh it creates is rather ugly too and only would work maybe for LoD1, but not 2 and 3. The only working way I found out so far would be to manually merge vertices, but that would be a pain to do for every model.

2. From low to high poly:
So if poly-reduction is such a problem, maybe the other way would be better, but there too are problems. My first thought was to create the LoD3 first and then use the multires modifier to create the higher resolution models. But with multires i can only tab-edit the lowest resolution model really and the higher LoD's would be limited to sculpting, which takes away control over the resulting mesh mostly. Also i see problems with animating the models then, as some details in the higher versions might not get animated properly and with texturing, as higher detailed versions might need some adjustments to the UV's. Another big problem is, what happens if I want to change the model later, to maybe make a variation of a model. I would have to redo all LoD's manually again.

Maybe I miss something, so it would be interesting to hear, how you guys do this with blender.

What I really would like, is a way to create the high-res model first with all the details and animations and then let the software reduce polys while keeping the UV-layout and animations. But maybe Blender is just not there yet, which leads me to my last question:

3. Maybe use another tool:
Thinking about buying 3ds max if I don't find a good solution to do LoD's with blender, but the price is rather high, if it was only for creating LoD's. What are your experiences with 3ds, is it worth the money? Which other tools can you suggest that are suited for creating graphics and models for C4?

I'm not a blender user so i can't help you there but it is normal for the uvmaps to be modified by using a decimation tool because they are the exact same polygons just in a flat arrangement, if you take them from the model you will take them from the uv info. Re: looking for advice on Level of Detail with Blender workflow

by Javier Moya » 02 Aug 2012, 04:11

I can't tell you about blender, but as it's been said already, if you don't have an automatic polygon reduction tool, you'll have to go to the classic approach to get the lower LOD meshes: Make the first LOD, then unwrap, make the second LOD, then unwrap ... 3ds Max keeps the uv layout, so you just have to relocate some vertexes in the lower lods, maybe Blender does it in the same way.

3ds Max is a very powerful tool, hence its price. It has a modifier called 'Multires', which reduces the polygon count automatically and keeps the uv map. You can see it in action in this tutorial from the wiki:

http://www.terathon.com/wiki/index.php/Creating_Levels_of_Detail

Personally, I like to control the resulting mesh, so I don't mind using a non-automated approach. I often use this modifier just for organic-shaped meshes. And it is really interesting combined with the 'Skin Wrap' modifier, for skinned models.

It's true that Max price is really high if you just want that feature. Maybe, a programmer can make a 'Multires' tool for Blender for that money .

Btw, I'm not trying to sell you Max. I really want to check Blender (I'm pretty sick of the Microsoft-Autodesk-Adobe tandem, as many others).

Hope it helps.

Re: looking for advice on Level of Detail with Blender workflow

by jwatte » 07 Aug 2012, 03:31

Robert wrote:As far as i understood, you might be able to use one texture file for several UV maps, and have the different models use different coordinates of said map. However, i don't know if that works with C4. It might require manual placement and sizing of the unwrapped parts in blender (but it could also be possible to unwrap several different opbects to the same map automatically, i haven't tried though).
If that works, and if the UVs for the different objects overlap matchingly, perhaps then the same files can be used without wasting place ?


C4 actually uses "many maps in a map" for its terrain material. Doing that well is pretty hard, because filtering and tiling has to be moved partly to the shader. Perhaps you can find a way to re-use that work from the terrain material?

Another option is to just build it all yourself in the shader. You have all the data and operations you need to do it, but it would be a pretty large shader.

Finally, you could probably find some script for Blender to put all the textures into a single large texure atlas, and change the UV coordinates. Typically, you'll need to use a bigger atlas than just summing up the textures, because you need some amount of repeat of the texture along each edge, to make filtering of tiling work out right. The script would also have to cut up the geometry at texture tiles (where U/V cross 1, 2, 3, ...) so it could be re-projected into the atlas, so high tiling factors would generate lots of extra vertices.

Re: looking for advice on Level of Detail with Blender workflow

by Javier Moya » 26 Aug 2012, 11:02

I've been unable to open the max file because I'm currently working with Max 2011, but I was able to import the dae file. The first thing that I've noticed is that the model it's been exported with the autodesk built-in dae exporter. I recommended you to use the opencollada exporter, though I'm not sure if there is a version for Max2013. Other problems that I see:

-Both models, Lod0 and Lod1, should have an identical list of the bones in the skin modifier (the same order). When the skinwrap modifier is applied and converted into skin, it automatically sets the same list of bones as the source model, so there must be something wrong there.
-If I remove the skin modifier from the modifier stack, both models are scaled down to a 10% and turned down 90 degrees so the mouth points downwards. It's always recommeded to use the 'reset xform' tool from utilities panel before start working with bones.

Despite all of this, I was able to have the model working in the C4 model editor (animation included). The only problem that I've had is that it showed first Lod1 mesh instead of Lod0 mesh. This is because the LOD system finds more vertex in Lod1 mesh than in Lod0 mesh, which is weird.

My usual workflow is this:

-I make the model, first a rough model and then I make a fine tuning.
-Unwrap the UV map.
-If I'm happy with the model, I use the STL check modifier to look for errors on the mesh, and then I apply the reset xform tool.
-Then, I make the rig setup (max bones, biped or you can animated the parts too, as I did with the spider and skeleton models of The 31st).
-When the model is correctly weighted (skin modifier), you can create the LOD meshes, but I prefer to work on the animations first.
-At the end, I make the LOD meshes. If it is an organic model, I usually use the multires modifier (for mechanical models, I prefer to make the LOD meshes manually). Then, I use the skin wrap modifier and convert it to skin through the option 'convert to skin'.

Hope it helps.

by BlindLuke » 27 Aug 2012, 01:25

@Baalfeus
In Blender I would use high to low approach. Use a decimate a bit, until it tries to remove important edges. Then merge vertices by hand. Broken UV layout (as long as it does not need to be seamless) can be unwrapped automatically and texture can be baked from hi-res to low-res.

To make additional very-hi-res Lod, for organic models, you can use Multires modifier to subdivision surface (it stores UV only in first level, others are interpolated)

There should be some script, to mark important edges and preserve them during decimate.

A couple of advices about 3ds Max (and I guess they are still valid for other 3d big applications):

-Don't trust what you see in the viewports. A lot of things are going to work inside max, and it is great when the output is video editing, but it doesn't mean that they are going to work inside C4.
-I don't know the pros of using Max CAT plugin, but I would avoid using special and advanced tools while working for C4 (and videogame engines in general). I recommend to work with the basic bones tools. It's always better to keep things as simple as possible.

Do I have to do something to the bones before adding the skin modifier? - Like reset xform for bones or something like that? Tried Animation-Bone Tools-Reset Stretch/Scale, but that messes up the Rig, might there be a problem?

If you did correctly the rig setup, you shouldn't need to do this. The bone tools are useful for the rigging, before skinning. Once you have the skin applied, it is a pain in the ass trying to fix the bones after skinning, so plan your rigs carefully before skinning.
