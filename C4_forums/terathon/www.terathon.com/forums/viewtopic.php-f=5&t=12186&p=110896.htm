Re: Flipping handedness through quaternion?

by Eric Lengyel » 08 Sep 2012, 19:23

The quaternion / matrix conversion functions in C4 are not broken. The problem is your assumption that it's possible for a quaternion to represent a reflection using the same operation that one would use for a rotation. It is not. When you try to convert your matrix that flips the x direction, you're causing a division by zero.

A properly constructed quaternion (that is, cos(x) + B sin(x), where B is the unit 3D bivector corresponding to the plane of rotation through the origin) will never flip the handedness of a vector when applied as a rotation. It's impossible.

by thesaint » 09 Sep 2012, 04:43

Here is my code for the left-handed ONB case... Maybe someone has an idea how to make it work for right-handed ONBs in which case it currently flips handedness but otherwise works correctly. This algorithm is also validated against a lot of random samples and handwritten testcases. Yes, it's not C++ but just consider it pseudo-code, should be self-explaining.

Code: Select all
 
  static Quaternion fromLeftHandedONB(Vector3 right, Vector3 up, Vector3 forward, [Quaternion out = null])
  {
    _initTemporaries();
   
    // face "forward"
    Quaternion quatAlpha, quatBeta;
    double alpha = Vector3.angle(new Vector3.forward(), forward);
   
    if(alpha > Mathf.ZERO_TOLERANCE)
    {
      Vector3 alphaAxis;
     
      if(Mathf.abs(alpha - Math.PI) > Mathf.ZERO_TOLERANCE)
      {
        alphaAxis = Vector3.crossed(new Vector3.forward(), forward);
        quatAlpha = Quaternion.fromAxisAngle(alphaAxis, alpha);
      }
      else
      {
        quatAlpha = Quaternion.fromAxisAngle(new Vector3.right(), Mathf.PI);
      }
    }
    else
      quatAlpha = new Quaternion.identity();
   
    // rotate around "forward" until "up" matches
    var tmpUp = Quaternion.inverted(quatAlpha).rotateVector(new Vector3.up());
    alpha = Vector3.angle(tmpUp, up);
   
    if(alpha > Mathf.ZERO_TOLERANCE)
    {
      if(Mathf.abs(alpha - Math.PI) > Mathf.ZERO_TOLERANCE)
      {
        quatAlpha = Quaternion.fromAxisAngle(Vector3.crossed(tmpUp, up), alpha) * quatAlpha;
      }
      else
      {
        quatAlpha = Quaternion.fromAxisAngle(forward, Mathf.PI) * quatAlpha;
      }
    }
   
    quatAlpha.invert();
   
    return quatAlpha;
  }

by jwatte » 09 Sep 2012, 22:15

The code I built my implementation against was not designed for right-hand but for left-hand.


Math is math. It doesn't care about handedness. Handedness comes *only* when you interpret numbers in a physical context. A rotation matrix that rotates 90 degrees around the X axis will rotate the Y vector to become the Z vector. It doesn't matter if you put in "right-handed" or "left-handed" interpreted data, that same transformation will happen.

A matrix constructed as (right, up, forward) is left-handed and has a negative determinant.


With all respect for Eric's math skills, I think this is inaccurate communications. Matrices do not have inherent handedness. I cannot look at a rotation matrix and see whether someone will apply it to right-handed or left-handed data. Handedness only exists in interpretations of data in a specific context. As an example: If you use a left-handed coordinate system, where X is right, Y is up, and Z is forward, and construct a matrix in the right-up-forward coordinate system, then the matrix will not have a negative determinant, and will be indistinguishable from a matrix constructed in a right-handed X-right, Y-up, Z-hither coordinate system for the right-handed mirror of the left-handed transform (which is not a mirror transform.)

Again, 90 degree positive rotation around X takes Y onto Z, no matter whether you're using a right-handed or left-handed coordinate system in which to interpret your data.

I think what you mean to say is that a matrix that has a negative determinant (i e, contains mirroring) will flip the handed-ness of whatever data goes through it. As has already been correctly said, that is not an operation representable through a normalized quaternion used as a rotation. You have to first extract the scale from the matrix (which will be a mirroring scale.)
