Hello again. I'm still slowly wrapping my head around the networking code and seem to have hit a slight dead end at the moment in terms of movement messages. I'm following the Multiplayer game code and have almost everything in place. Here's my current process for movement:
1) CLIENT: The Movement Action sends a ClientMoveMessage (which is a Message) to the server
2) SERVER: The HandleMessage override in the ClientMoveMessage class then calls a function in the correct controller (based on the player sending the message).
3) SERVER: The controller then creates a ServerMoveMessage (which is a ControllerMessage) and broadcasts it to all clients including itself.
4) CLIENT: (Should) The same controller (but client side) should call ConstructMessage, in the controller class, and then ReceiveMessage, also in the controller class, and move the object.

Problem is, while I see the movement on the server, the client isn't getting anything. I'm able to watch the message make it as far as the server sending it to the player before sending the message to itself, but I can't see the client receiving anything. Is there any piece of the puzzle that I'm missing? If not, can I somehow track that message and see if it's getting lost somewhere?

Thanks for the help! Unfortunately, it's hard to make a co-op tower defense game networked when the client side refuses to respond to server messages.

This is Step 3: Called from within the AvatarController by the HandleMessage function of the ClientMoveMessage after it's transmitted to the Server. If the SendMessageAll doesn't transmit the message to the server as well, nothing moves when keys are pressed, otherwise only objects on the server move. It's taken pretty much directly from the Game project.

Code: Select all
void AvatarController::BeginMovement(unsigned long flag, float azm)
{
   const C4::Point3D& position = GetTargetNode()->GetWorldPosition();
   C4::Vector3D velocity = GetLinearVelocity();
   
   ServerMoveMessage message(kServerMessageBeginMovement, GetControllerIndex(), position, velocity, azm, flag);
   C4::TheMessageMgr->SendMessageAll(message);
}

Re: Client Not Receiving Messages

by Benjamin Dobell » 13 Jun 2010, 21:14

You'll want to debug (stick a break-point in) MessageMgr::ConstructMessage(). If the message is being constructed but not received then the message is failing to be decompressed, perhaps you haven't called the super-class' Decompress() method from ServerMoveMessage::Decompress().

EDIT: It's more likely that you may have forgotten to call the super-class' Compress() from ServerMoveMessage::Compress() in which case the MessageType won't be getting included in the sent ServerMoveMessage so when MessageMgr::ConstructMessage() is called it will be called with garbage data (more specifically whatever the first 8-bits[1] were that you compressed in the message).

EDIT-2: [1] - Kind of unrelated but I said the first 32-bits initially. MessageTypes are all actually trimmed to 1 byte when transmitted over a network so there are actually only 256 first-order message types available.
