Re: Unable to Read Memory

by datalol-jack » 01 Mar 2014, 14:57

Interesting. Are there any introductory guides available that cover this?


Try/throw/catch will do most of the time. For more advanced scenarios it is now fashionable to spawn a child thread which validates your actions before returning to the main program with either a green light or big disaster sign. Exception handling and threading are platform specific issues, so finding good generalised coverage can be tough. Having said that, here are a few resources which can give you an idea of what to do:

    http://www.exceptionsafecode.com/ -- talk by Jon Kalb on safe coding practices; includes videos and source files
    http://www.mindviewinc.com/Books/downloads.html -- free books by Bruce Eckel; check out the chapter dedicated to exceptions in vol 2
    http://bruce-eckel.developpez.com/livres/cpp/ticpp/v2/?page=page_2-- here it is available online
    http://www.terathon.com/docs/System/index.html -- threading and logging reference for C4
    http://www.terathon.com/docs/System/Thread.html -- C4's threading is cross-platform, so would be preferred to anything specific to Win or Linux you see online
    http://www.chromium.org/developers/design-documents/sandbox/Sandbox-FAQ -- if you really want to go all out, use this

C++11 standard may also have something on this, but I'm still scoping it and other recent additions like Boost out myself. YouTube is often a good source for quick tutorials on particular things too. The general idea is to isolate the risk carrying code from the main app for testing. Once done, you would throw out the whole scaffold for high performance software like games for release.
