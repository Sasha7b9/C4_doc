Re: Terrain Editing / Voxels

by Frank Skilton » 12 Mar 2011, 02:30

You can use an external heightmap based editor, make a standard heightmap based terrain and then import it into the engine via the .TGA format or better yet, .RAW. Now you have a nice base terrain, you can use the voxel tools in C4 to modify as necessary.

Even though the editing tools in C4 are voxel based, you can still import heightmap based terrains. I mention this as you seem to be under the impression that you need to use an external voxel terrain editor, which isn't true.

I think it would be great if C4 had a simple procedural terrain generating algorithm.

Maybe my approach when I made the Hell's Mouth demo map is useful for you. The first intention was to make a natural/manmade cave complex, so this was something similar to what you want to achieve (large number of tunnels). I've attached some screenshots of the early stages of development:

HMWIP01.jpg

HMWIP02.jpg

HMWIP03.jpg

HMWIP04.jpg

HMWIP05.jpg

HMWIP06.jpg


As you can see, I started with one terrain block, but this approach immediately caused perfomance problems. I used just one zone containing that terrain block and the geometries you see in the screenshots. I used occlusion spaces to try to improve the overall perfomance, but they didn't help very much, mostly because the tunnels where short and very close to each other, so it was difficult to take advantage of the occlusion spaces here. This led to the classic multiple zones approach, each one containing small terrain blocks. If I'm not wrong, this won't be a problem anymore when version 2.9 arrives ("New zone and portal architecture. Visibility graph decoupled from transform tree" feature). Anyway, I think that it's still useful to know how I made that cave complex.

The first two screenshots (HMWIP01.jpg and HMWIP02.jpg) show the general tunnel distribution. I started creating the platforms, which I used as a guide to raise the tunnels walls. I created a flat plane terrain block and I started raising the terrain up to the lowest platforms, using the cylindrical brush in horizontal plane. Then, with the same brush and plane mode, I continued raising the terrain up to the next level of platforms. This second level created walls for the lowest platforms. Here, I had to play with the brush parameters to make thinner or thicker walls. Once the "cave walls" were raised up to the maximum cave height, I created a last layer covering the whole complex. This last layer created a "floor/roof" at the top of the terrain, so I used the hole brush to eliminate those voxels. At this point, I started to work inside the complex, and went all over the tunnels, smoothing and detailing them (HMWIP03.jpg and HMWIP04.jpg). I added several temporal lights which helped me to shape the tunnels. I continued shaping the tunnels while I added geometries, so this "tunnel shaping phase" doesn't finish almost until the end of the work.

You can open the Hell's mouth demo map here: Data/Demo/world/Hellsmouth, and see the final version.

You can see another "terrain modeling job" here: http://www.javy3d.com/2009/portfolio.html, approximately in the middle of the page (screenshots called "TS-mangler-canyon1" through "TS-mangler-canyon9"), which show a kind of "spider canyon". This was another attempt with some perfomance problems, but they are good examples of what you can get with the current terrain tools (BTW, I'm in the process of updating my portfolio).

Hope it's helpful for you.

Re: Terrain Editing / Voxels

by Eric Lengyel » 14 Mar 2011, 04:02

Nidan wrote:It would be great to be able to grab a point and move it around like in blender


You need to think about the voxel terrain differently. The polygon mesh is just the end result. The terrain itself is a volumetric grid that contains density values, and those are what you are changing with the brushes. You modify the 3D voxel map, and a new polygon mesh is generated from the underlying data.

Nidan wrote:Also I have found that if i export in blender (as a 3dmax filetype) import into voxelogic then i can covert to raw voxel data. ( although i have not been able to get it to work 100% as i end up crashing c4 if the file was originally from blender, but no crashes when i make a file in voxelogic and import, i expect i am just doing something stupid)


Can you send me the file that causes a crash? That shouldn't happen, no matter what the input data is. You're running version 2.5.2, right?

Nidan wrote:Can anyone point out where i can find how the structure of raw voxel data is written/formatted?


The raw voxel data written by Acropora is just a big array of floating-point numbers (32-bit) stored in z-major, then y-major, order.
