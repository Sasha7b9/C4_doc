Well, here I am running into serious problems. I have a number of models in 3DS, all human shaped with a skeleton system there's a Skin Modifier on top of a Mesh or Polygon. Well in short: The export doesn't work. I am using the latest 3DS Max FBX exporter for version 2012 and the Autodesk FBX to collada converter since I read here that the Open Collada converter isn't very good.

Now, when exporting, I can import the DAE file into the world editor but I see only the skeleton. I made it so that the mesh is childnode of the pelvis bone (top of my hierarchy) or an unlinked node (in 3DS that is) but the result is the same: IN C4 WorldEditor I see only the skeleton. I read a lot here about the flaws of the Collada format and various exporters etc. Is there any hope I can fix this? Because this is a make or brake thing for me, I spend too much money on these characters and the clothes.

Re: Animated Character From 3DS Max Problem

by Javier Moya » 06 Jul 2012, 03:38

We use the Opencollada exporter in The 31st with no problems. All characters have been made in 3ds max. In our models, the mesh is always independent from the skeleton (we've used both biped and max bones).

I've already read about the problem of the dissapearing mesh, but I don't know what causes it. My creation process is really easy:

-When the model is finished I always reset the transform of the mesh (Tools->reset xform).
-Then I make the rig setup, biped or max bones (there must be just one parent) and skin modifier. I've used IK solvers on some models with no problem.
-Then I start animating.

I wouldn't mind to check one of your models, or you can publish it here so more people can check it out (if you don't mind, of course).

Hope it helps.

Well, for the time being, I see no other solution as to write my own importer, and here is the reason why: My setup is so that I'm using a character in TPose with the bone weights, a skeleton in TPose to attach the character to, several full body morphs in TPose without a skeleton which can be mixed with the basic character and then a set of 3DS scenes with the character/skeleton in one animation each.

My current workflow is so that I export these into a defined directory structure with OgreMax, then run a converter I wrote that reads these Ogre meshes/skeletons and stores them in several binary files with my own format. My current client reads these files and assembles the character.

I think I have to replicate this last step with C4 then I can leave the original exporter/coverter process intact. I also understand that C4 has no standard way to morph meshes, not sure if that's true, but if so I would need to assemble my own Geometry anyway. I looked into the Collada importer and it seems to me that the BuildGeometry() function is the central function to create a mesh out of raw input data. If that is so, I should be able to read my prepared input data and create a C4 Mesh from this. The only problem I see is assemblig a skeleton for C4 from the Ogre skeleton format, I haven't looked into how C4 handles skeletons yet but I hope its not too different from Ogre. Also what worries me a bit is that Ogre uses quaternions for node orientation and C4 uses matrices, I am not too good at 3D math, but I understand there are ways to transform between these two formats.
