Re: New Model Not in Models Pane

by Eric Lengyel » 18 Sep 2014, 15:53

GameWizard wrote:I will bring them into photoshop and save as tga. How many bits/pixel should I use, and do I do a compress RLE?


If your image has an alpha channel, then use 32 bits per pixel. Otherwise, you can use 24 bits per pixel, but 32 bits would also be fine. The engine can import with or without RLE compression. Your files will generally be smaller if you do use RLE compression, but otherwise it makes no difference.

Re: New Model Not in Models Pane

by Eric Lengyel » 18 Sep 2014, 19:21

GameWizard wrote:
Do the test box and vehicle show up in the model list?

Yes.


Then I can't explain why the player model doesn't show up with the information I've been given.

GameWizard wrote:So, when importing from the dae file, which has the texture names, why doesn't the editor do what is necessary to create materials, or do whatever is needed?


The editor does create the materials. If the model is white, then that probably indicates that the textures are not specified in the DAE file, or that the DAE file is not properly constructed (one of the reasons we developed OpenGEX). If you see the purple texture with green Xs, then that means the textures are in the material, but you need to import the textures separately. Textures can only be imported automatically if they are in the Import directory hierarchy and the DAE file refers to them in that location (containing "Import/" in the path name). Otherwise, the importer doesn't know where to look.

Re: New Model Not in Models Pane

by Eric Lengyel » 19 Sep 2014, 16:14

Thanks for the file. I've looked into this, and the DAE file does not correctly bind materials to the geometry. (The geometry does not identity the symbols used by the material bindings, so there's no way to associate the materials with the polygon meshes.) This is a bug in MakeHuman. You'll have to create the materials inside the C4 editor yourself and assign them to the character.
