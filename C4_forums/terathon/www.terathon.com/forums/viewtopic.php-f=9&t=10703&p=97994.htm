"Do not apply model animation" flag usage

by ca$per » 19 Apr 2011, 06:03

Hi!
Here is a situation we have.
There are about 90 character models with skinning. 90% of them has the same skeleton (both the hierarchy and names). But there are some specific parts on some models that have extra bones added, like capes, dresses etc.
The animations we have are mostly common for these characters. For example one idle animation for all. But the way C4 handles animation requires us to have exactly 100% same skeleton over all characters. This is next to impossible if we want to retain a good variety. But accounting, that most of extra bones do not act in animations it becomes more possible.
To make everything work, the fist idea was to set the "Do not apply model animation" flag on extra bones so the animation system wouldn't account for them. As a result, skinned parts that use these bones gets distorted even without animation being applied - just the model.
So the question is, if it's possible to make something about this?
If to be simple, we want our animations to use only those bones, that are set in them. And not touch other bones of the model at all, so they wouldn't distort. Right now we have to mark all "extra" objects in all 90 characters by examining each model in C4 (and you can imagine how hard it is to look throught all 50 objects each time and find extra ones only visually)... but this also doesn't help much.

Re: "Do not apply model animation" flag usage

by Frank Skilton » 19 Apr 2011, 09:29

We encountered the same problem in our game. We have a bunch of soldier characters who have different things attached to them via bones, as they are animated. E.g. back packs, ammo pouches etc. We also wanted to use the same skeleton amongst all characters, so we have simply done just that. We created a master skeleton that has every bone we need amongst all characters, and just use the required bones per character, and ignore any unneeded bones. They are still there and animate, but obviously can't be seen.

Not the most efficient way of doing things in terms of performance, but much better for the art pipeline. Having a unique skeleton per character was too time consuming for us to maintain.

Wish there was a better solution, but don't know of any.

Re: "Do not apply model animation" flag usage

by Grognard » 20 Apr 2011, 01:45

ca$per wrote:But what to do with distortion? That a collada exporter changes the order of nodes... And that when i set the above mentioned flag i also get distortions even without animations.


That's a totally separate issue. If the bones are there and attached to nothing, there is no problem and there is no performance penalty.

But if your nodes get exported differently then you are screwed. That is just how collada works (or fails to work).

So for example in maya if I select the nodes top down and export, that is the order they show up in. If I then do it bottom up and export same thing. AAAAAHHH! So your model doesn't work. That's because the collada info is basically a list of changes from a presumed start point, must be the stupidest idea anyone ever had. I wasted weeks on this nonsense before I figured out why it was going wrong.

Eric has said C4 will eventually move back to its own exporter. What would be really nice is to have a target format to write your own exporter to that doesn't have this problem. So you have joint names and positions and rotations for every frame exported then the engine can use that to go to its own internal format. That way you can have a robust exporter. For collada, it's actually impossible to have a robust exporter because the inherent issue is garbage in garbage out.
