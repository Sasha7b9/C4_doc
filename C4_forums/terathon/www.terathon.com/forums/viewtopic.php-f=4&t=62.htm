by Eric Lengyel » 11 May 2006, 03:41

More details will be in the release notes, but the gist of it is that no unmodified Object classes are written to the save game file. The whole node hierarchy is saved, and new or modified objects are saved. The unmodified objects that are referenced by the nodes are read from the original world. Since all of the geometry data is stored in objects, the size difference is huge.

by Eric Lengyel » 11 May 2006, 04:26

The current implementation only saves what's in the node hierarchy. To save generic data, you can use the trick of attaching custom properties to the root node. This can be done in your game code right before you save if wanted.

As for items 1, 2, and 3 above, I'm currently working on a quick load mode that will replace only the necessary objects in a scene. So no geometry reloading, no texturing reloading, and no shader rebuilding unless necessary.

Objects belonging to deleted nodes will not be referenced by anything after a restore, so they'll just automatically be released before the load function returns.
