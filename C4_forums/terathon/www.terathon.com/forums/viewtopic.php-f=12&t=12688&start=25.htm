by Eric Lengyel » 18 Mar 2013, 19:56

zergling wrote:Is C4 Engine 3.0 suffering the same issue?


Probably. C4 only communicates with the low-level X Windows library, so if something works on one distro and not another, then it means that the people responsible for the higher-level windowing system screwed something up. (This should not be surprising.) Unfortunately, we have very little manpower available to investigate these kinds of issues on the multitude of Linux flavors out there, so it could be a while before you see this resolved without involving the KDE folks directly.

Re: Questions on C4

by trebor » 14 May 2013, 06:55

The only issues I've had with C4 on Linux has to do with sound, this isn't a problem with C4 but is a problem with the way Ubuntu and Mint use pulse audio(which is extremely unpopular amongst the Linux crowd).


The problem roots in using ALSA directly instead of using PulseAudio. Really most problems with PulseAudio are caused by apps that want to access the sound hardware directly and blocking the sound mixing of PulseAudio.
I got rid of that by using the simple PulseAudio API in C4 instead of ALSA. It works fine for recording and playback and is trivial to implement.

Concerning the X-windowing problems it might be better to use SDL instead of using the Xlib directly. I have a good experience with SDL over Xlib concerning the windowing in other projects.

For my own experience I lost my keyboard input several times when disabling vsync in C4.
