by Eric Lengyel » 01 Jul 2006, 04:28

DanPartelly wrote:The time smotthing code, where did you added it to engine ? Whate xactl was modified ?


It's extremely simple, really -- the Time Manager just uses the average of the current frame's delta time and the last frame's delta time. It's in TimeMgr::TimeTask(). At constant frame rates, this changes nothing, but if the frame rate changes abruptly, it spreads the compensation out over two frames.

Debug recording feature?

by David Vasquez » 01 Jul 2006, 05:16

This has been discussed enough that I felt obligated to try Frank's suggestion.

The first five or six times the frame rate increased gradually as I approached the other side and the hill started to fill the screen.

However, one time there was a very noticeable jerkiness that was quite disturbing. I repeated the test a few more times, and encountered the odd timing anomaly twice more. This issue is rare, but when it does happen, it really does feel like there is something wrong with the game.

Anyways, as a constructive suggestion, a debugging tool which would make it much easier to share test results for issues like this would be a start/stop recording mode, which would write out the current game state and then start recording all of the player's movements when the record mode was started, and then write them out to a re-playable log file with the previously saved game state pre-pended, when the record mode was stopped.

This would permit testers to send in reproducible results from their testing activities, and making it much easier to illustrate position and movement dependent issues.

With large levels, there would be a lot of state that would have to be written out to make this work, such that there would have to be a delay when the recording was started, but it would still be useful.

If C4 can't support this for general use, I will look into how to add such a debugging tool for my own beta testers to be more effective at reporting hard-to-reproduce issues.

A recording tool could also be the first step towards some limited degree of test suite automation.

(Yes, I know about FRAP, but video files don't let you set breakpoints, and they are also large enough that I would prefer to only use them for bug reports where it's absolutely necessary.)
