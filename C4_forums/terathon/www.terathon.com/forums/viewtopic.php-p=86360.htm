Re: Version 2.1 Now Available

by Eric Lengyel » 09 Jul 2010, 15:30

Adam Golden wrote:does the vertex buffer also need to be rebuilt if a model containing one of its impostor nodes is moved?


Yes, but this wouldn't be automatic. Geometries that have impostors really shouldn't be moved.

Adam Golden wrote:do all models of one type with an impostor need to be under the same parent to have the same vertex buffer? for example, would trees of the same type on different terrain blocks still be rendered from the same buffer?


The models do not need to have the same parent node. They'll be rendered in one batch no matter what. A tree doesn't become a subnode of the terrain block, so that never affects the situation.

Adam Golden wrote:do models need to be registered for the grouping to function properly, or are those created with Model::New ready to go? i store pointers to models created this way in a List with other details for iteration, but i haven't been using ModelRegistration - should I be?


Impostors would generally be used with referenced worlds, as shown in the Tutorial/world/Impostor.wld example. So registration never comes into it.

Re: Version 2.1 Now Available

by Eric Lengyel » 09 Jul 2010, 15:32

TheRhinoDude wrote:I can see a lot of games where people want to do cut down / burn down trees in order to remove as part of forest-clearing gameplay or terrain deformation result. Is that possible with impostering as is in 2.1? Sounds like it's possible, but would have performance issues.

Would it be possible for remove to simply mark that index of the buffer as unused so that the imposter isn't rendered? It would still have the trivial render overhead of being there, but visually it would be gone. The best would be an option to rebuild when removing, so when removing the last tree, the app can say to rebuild then, so it rebuilds only once for N trees removed.


The best thing to do would be to simply disable the node in order to remove a tree from the scene. This won't cause a vertex buffer rebuild, and the tree will never be rendered. If the node were to actually be deleted, then the vertex buffer would need to be rebuilt, but it won't happen more than once per frame if you delete a whole bunch of them.
