Why is my COLLADA file broken? [Try this]

by mschifter » 17 Jan 2013, 10:46

For Everybody with COLLADA issues:

I found a free tool that checks your .dae file against the standard and reports problems. It's called COLLADA_Refinery, and available under the data conditioners section of the COLLADA.org web site. It's a 5 MB download, and WARNING: It contains a virus file. Before running it, after installation, you'll want to delete the following file (I've already contacted the webmaster regarding this problem):

Scan type: Auto-Protect Scan
Event: Security Risk Found!
Security risk detected: Backdoor.Graybird
File: C:\PROGRAM FILES\COLLADA\COLLADA_Refinery\update.exe
Location: Quarantine
Computer: ORL-039
User: schifterm
Action taken: Quarantine succeeded
Date found: Thursday, January 17, 2013 9:49:58 AM

Then run the app, and you will see the following:

Refinery 1.jpg


Double-click the Input 1 triangle and browse to your .dae file.

Double-click the output 1 triangle and browse to a destination folder, and give it a name. This will be a collada output file.

Then go to the conditioners menu and select the coherency test. Then click in the black circle from the input1 triangle and drag to coherencytest, and from coherency test to the output1 triangle as follows:
Refinery 2.jpg


Then you can click "Execute". My current model, a "sapling" creation with armature, exports with different errors using the default COLLADA exporter vs. Jack's COLLADA exporter, but neither have valid skincontroller settings because C4 won't load the file with a skin controller attached:

Re: Why is my COLLADA file broken?

by mschifter » 17 Jan 2013, 13:43

My results: Using both the built-in COLLADA exporter and Jack's exporter, I got two different sets of errors that were in mutually exclusive areas. So I copied one of the files to a new name, and replaced Jack's file's bad sections with areas from the Internal exporter's file, and removed another error area, then tried the file -- still no skin controller. Ah, well -- this app still might help somebody else.

EDIT2: I pushed further and reapplied the Armature to the model and I started getting a skin controller in the output and ONLY WITH JACK'S EXPORTER and with that file I got a skin controller showing up in C4. GetNextNode() now finds the bones. The GetInfo dialog for the tree model defaults to "Skin" on the controller page, meaning there's a skin controller in there somewhere.
