by zebeste » 27 Sep 2012, 17:14

Eric Lengyel wrote:The mod function can also be implemented as frac(a/b) * b, which only uses 3 shader nodes.


Thanks for the tip, it's definitely a better alternative to the formula I found. Also while working on my latest shader, I realized that not using a modulus process means I can swap out the division for a multiplication when b is a constant that I can precalculate the reciprocal of.

Anyway, I have a new version of the Sierpinski carpet to show. The original one that I posted used the more typical method using recursion, and to accomplish it, I had to basically unroll the loop, meaning that the amount of detail you could see as you zoomed in was limited.

However, I found a way that does not involve any loops or recursion, so the detail is no longer limited in that way. This was done by using the texture coordinates in base 3 (ternary), and performing some logic on that. The downside is that with such high detail and no form of subsampling within the shader itself (or whatever the term is), artifacts start to appear (it's possible to fix, it would just be more complicated). Currently, there are 2187 points mapped to the 0-1 texture coordinates, so to view the entire thing at a 1:1 zoom ratio would require a monitor with a width and height of 2187 pixels, and it is trivial to increase this (by powers of 3) for almost no additional performance cost. Enjoy.
