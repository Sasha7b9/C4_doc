Re: Problem with timeout

by Eric Lengyel » 01 May 2012, 00:32

The server can't force a client to timeout. A client will timeout if it doesn't get a response for something like 30 seconds to a minute, but never any shorter than that, except on the initial connection, which times out after about 5 seconds.

We'll have to get an internet test server set up so that we can play games over high-latency connections.

Re: Problem with timeout

by CodeNewt » 01 Jun 2012, 10:13

DjSt3rios wrote:I didn't really get it, did you find any solution on this problem? :s

I found the issue is when you send too much data at once that is required to be reliable, then a larger % of packets would not be received by the server. I demonstrated this by sending a String<10> object once per frame as its own message, and increased the size. As I increased the size, the client timed out faster.

So, the end result for me was to keep messages small, and only send 'reliable' messages when I absolutely have to.
