by Eric Lengyel » 12 Nov 2008, 00:31

MoooseGuy wrote:1. Do you need to buy a physical server?


No, C4 networking will work without a master server. But you'll probably want to put something together that tracks current games so that people can find running game servers on the internet.

MoooseGuy wrote:2. Does the C4 Engine support online networking?


Yes.

MoooseGuy wrote:3. What is the most it can handle?


It depends on the game, how much information you need to send to the players, and what your bandwidth is. There are no internal limits in the engine.

MoooseGuy wrote:4. How do I get started with using multiplayer networking in C4?


That's actually a little bit of a tough one. Our demo supports multiplayer, but it is very complex for an introduction. We are working on a simple networking tutorial, but it is not ready yet, unfortunately.

Re: Online multiplayer for fps

by Benjamin Dobell » 12 Nov 2008, 09:13

Interpolation is when you estimate a data point based on surrounding data points.

Clients can't wait to receive data from the server every frame before they render as they're rendering much faster than the server is able to send out information. In C4 interpolation (it could be seen as extrapolation depending on how you look at it) is used by clients to estimate the position of a model based on the last information they received about that model. This essentially means that clients are able to guess where a model will be based on it's velocity and how much time has passed since the last time a frame was rendered. This minimises bandwidth and results in smoother gameplay.

by rainchild » 13 Nov 2008, 03:12

Depends on the distribution method you want to use -- central server vs peer to peer.

If you want all your players to connect to a centralized server farm (eg, World of Warcraft) then yeah, you're going to need a fangoriously expensive server.

If you go the peer to peer option, you can probably get away with some kind of "dreamhost" $10/month plan where you basically say "Hi, I'm Rainchild, my IP is blah.blah.blah.blah and I have room for 2 more folks in my game"... think more like ye olde Battle.net where you had a lobby which talked to the central server, and the games itself were hosted by the players.

by kobaltic » 06 Mar 2009, 11:45

I do some work for a company and here is how they handled it.

They made a demo of a game and got the gamespy sdk.

Got a publisher to fund the project.

Gamespy hosts the master server (and still does to this day, six years later).

The company does not pay one cent to gamespy for hosting the master server.

The company built in a server list in the game. You don't even know that it is gamespy running it.

Gamespy also allow for webpages to show up to date server lists so you don't even have to start the game to see the servers.

Clients don't even need to install gamespy.

Gamespy also has cd-key protection for games.

All in all I think a master server should be towards the end of the list you should get a demo out first.
