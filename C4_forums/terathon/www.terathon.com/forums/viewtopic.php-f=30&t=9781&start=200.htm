Re: Wingball 0.5.3 Released

by Adam Golden » 26 Oct 2010, 14:56

Amo wrote:No problem my friend. Btw. How did you do the loading percentage when starting a level?

I figured someone would ask eventually.. I first tried to load everything on a secondary thread so I could use the main thread for effects and whatever during load, but background loading isn't supported so I ran into a lot of problems trying that. The next idea I had (which is there now), was to do a certain % of the work and then pause for 1 frame to render a progress update before continuing. This technique is sufficient for a simple loading progress until actual background loading is implemented in C4 2.x (based on the official roadmap).

by Adam Golden » 14 Dec 2010, 08:57

Haven't posted in a while so here's some rough shots of what to expect in the 0.6 update. Everything shown is implemented and functional - still have some more stuff to do before I'll package this up, but it's definitely still on schedule per the history/roadmap page on the site. Controls is done too except for some joystick stuff.

Performance is now centered around the frame rate. You decide a "target framerate" and while you're playing, the game will automatically reduce or increase the draw distance to maintain it. This means you can set options like foliage density way up, choose a realistic frame rate for your system, and get optimized draw distances in real time as you play (updated 4 times per second at the moment). There's also a "particle density" slider that let's you change how many particles of an effect will be shown at once (for example, the number of raindrops in rain). The "particle collision radius" just means how far away from the active camera (typically the player) will particles interact with objects and terrain (such as raindrops creating ripples on puddles).
