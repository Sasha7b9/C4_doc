Hi ska,

Sorry for the delay in response.

There is an advantage to using the C4 voxel editor in that you get a direct mapping for the voxels in the C4 engine to polygons. This uses Eric's efforts to create the optimal set of polygons to represent any feature, such as holes in the terrain.

For Bryce, you get a slider to select the number of polygons your output will use, and so that uses an optimization algorithm internally. Bryce uses procedural algorithms (essentially equations) to generate both the polygons and the textures. This can include dozens of equation types. I recommend you check a few YouTube tuts on Bryce terrain to see the tools in action. Nobody wants to work with heavy math to create art, but you don't really have to understand heavy math to use Bryce effectively.

With regards to making caves -- I don't recall any special support, however you can integrate any 3d model that you can run through the importers, and that's for any polygonal shapes.

With regards to texture stretching/issues, I've seen terrain geometry edges that "melt" down the outside rectanglular border of the terrain. I dropped the polygon resolution from 500,000 polys down to 30,000 and that removed most of it. The rest was fixed in blender. Other than that, I've never seen any texture stretching problems. The generated mesh is made of quads.

Hope this helps,

Matt

Re: "Actions" hidden requirement

by mschifter » 26 Oct 2012, 11:56

Tip:
Problem: If you want to move Action registrations (such as TheInputMgr->AddAction(&<actionname>);) to another section of your code, the app may crash.

Reason:
The input.cfg file used to bind input controls to action is called just after the application construction.
If your actions were not registered at this time, the binding will fail.

To fix this, you can re-call the input.cfg at the end of your function code:
Code: Select all
if (!ExecuteFile(C4_INPUT_CONFIG_FILE, TheResourceMgr->GetConfigCatalog()))
     ExecuteFile(C4_INPUT_CONFIG_FILE);


credit goes to "nore" for the solution.

If you find that the World Editor's yellow checkered volume representing a selected light source's range of influence bugs you because it interferes with your ability to actually see the effect of the illumination on your scene's geometry while you're manipulating the light node, you can simply replace the volume texture used by the editor with something less obstructive.

The light texture in particular resides in Data/Tools/WorldEditor/volume/Light.tex and it's an 'intensity format' texture with no alpha, 256^2 pixels. White is rendered opaque and black becomes nearly transparent. After renaming the original file to 'Light.old' (just in case you change your mind later), it can be replaced with something else, like the little black 32^2 thing I've attached to this post.

Tip for animated models from Blender

by mschifter » 29 Oct 2012, 14:09

Tip:

If you are using Blender, you should be using Jack's BlenderToC4 Python converter script. It covers the model, skin, materials, rigging, and animation.

Also, if your animations don't appear correct in C4 (problems with scale or missing or misplaced mesh components), ensure your model's meshes all have normalized transforms. Do this by switching to object mode, selecting an object, and from the Object Menu, pick the Apply menu, and then Rotate and then Scale. Be sure to start with the model file, then the animation files.

Tip for setting up translucent (alpha-blended) meshes

by mschifter » 29 Oct 2012, 14:10

Tip:

Got translucent meshes not showing up? In the World Editor, import the model file, then double-click a transparent mesh, and click the "Render geometry in effect pass" selection. Click the light-bulb on the toolbar (tooltip: full lighting) to off/dark mode to see that mesh in translucency. In the Model Editor, select the same translucent mesh, and under the flags tab, activate two-sided rendering. This should do the job.

Tip: using cloth simulation

by mschifter » 15 Nov 2012, 09:12

Tip:

Dynamic cloth as of 2.9.1 is limited to a rectangular main shape. It is set up entirely within the World Editor. You can attach it to any geometry in your scene or just a small portion of the scene as a world file "prefab". Once your cloth is drawn out, assign any material in the material editor. You can use Alpha testing (ie, selective full transparency) to create a shape for your cloth, but it will still be a flat piece of geometry. Then add a "Box field" from the Physics page, and surround the cloth with it. Ideally, you want to cover the cloth to the extreme of its motion in any wind direction.

Then add these nodes to a world instance and you are ready to drop instances of this into your main world.

Well actually the solution could be found in the wiki but still it's only mentioned as a sideline:

When a file is named: DATA/A/B/C/d.ext then the complete name to load the resource is B/C/d and not C/d

Most samples only use one path element before the filename and that gives you the impression it's always just the lowest directory that is part of the file designator, but thats probably only because the samples are not organized with a deep directory structure.

Again, this may sound silly and simple but when you don't know it, you easily run into this trap like I did.

When rigid bodies are in contact with those geometries, they see this velocity and transfer it to themselves. - Eric
