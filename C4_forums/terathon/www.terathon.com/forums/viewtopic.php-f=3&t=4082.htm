Pack and Unpack are used when saving an object in a file and loading it, respectively. They are called to serialize and deserialize the data stored in an object.

Re: Pack / Unpack

by dasplund » 04 Jan 2008, 00:13

To add to what Eric said, they let you save/load the game (by serializing the objects), and store data in the world editor. If you don't need those things than you can skip pack/unpack.

Beware of changing pack/unpack code, you will corrupt your world files. You have to build, run, and save all worlds with just the new PACK code, then exit, add UNPACK code, and build, run, and save all worlds. Otherwise the engine will try to unpack the new code, which was never packed, and will crash. Another option is to remove all instances of that controller or object from your worlds, save them, do all the code, then place them back in the worlds.

Re: Pack / Unpack

by David Vasquez » 04 Jan 2008, 00:34

That's not quite accurate. If code is using the chunking facility correctly, it will only unpack what's actually in the file to begin with. If a chunk isn't present, the code to unpack it simply won't be called. As long as your objects have proper constructors with reasonable default values, that shouldn't be a problem.

The only issue that comes up is if you change the order or type of fields in an existing chunk. That's why it's better to deprecate chunk types when they change (leave the old code alone), and define new chunk types when a change needs to be made. After the new chunk type is working correctly, you can then delete the deprecated chunk code, and the next time the chunks are serialized in, the chunking support code will silently skip over the unrecognized chunks.

The .pak files are actually something different from the Pack/Unpack functionality described by this thread. The Pack() and Unpack() functions are used when saving and loading individual resources composing any kind of file, like .wld or .mtl. The "pack" console command combines all the resources in a directory into a single .pak file.

The resources for our game The 31st are intentionally stored inside a .pak file to deter theft, and it is intentional that there is no unpack command. One of the benefits of the previously-existing "professional" license of the C4 Engine was that you were able to see the unpacked resources from The 31st in order to learn more advanced techniques. This license is actually still available, though not publicized, and you can upgrade from inside your account. (But we can't make the resources available in the standard version because it would be unfair to people who've already paid more.)
