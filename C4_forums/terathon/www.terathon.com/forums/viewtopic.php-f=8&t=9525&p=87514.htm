Re: Some questions about UI (graphics settings)

by David Vasquez » 27 Jul 2010, 23:50

Niteen, this is fairly straightforward to implement, but it's a bit of work, so here goes.

Please study the existing code for the GraphicsSettings window class, (in "MGConfiguration.cpp") for adding the UI portion of your "Default" button (we called it the "Optimize" button), adding a new case to the GraphicsSettingsWindow::HandleElementTrigger function to handle the click. (Check out how the "Apply" button is added.)

To determine the best settings for the user's system, call TheGraphicsMgr->GetCapabilities, and then switch on the value of the GraphicsCapabilities::hardwareGeneration, which returns an integer value that is larger for more powerful GPUs - the mappings look something like this:

0: NVidia 5x00 or ATI 9x00
1: NVIdia 6x00 or ATI Xx00
2: NVidia 7x00 or ATI X1x00
3: NVidia 8x00 or ATI 2x00
...
(etc., etc.)

For the popup menu, you would add it to the UI in the constructor, and add another case to the GraphicsSettingsWindow::HandleElementTrigger, to call a function that sets the controls according to the selected group of settings (we call these "profiles").

The tedious part in the implementation is making your popup menu match the current settings, or to display "Custom", when the window is first opened. We did this by adding a function that is called at the end of the GraphicsSettingsWindow constructor function, which compares all of the current settings against the settings of the selected profile, and only if they match, is the popup menu set to that profile.

You'll also want to ensure that when the user changes a setting to a value that results in a custom profile that doesn't match one of the existing profiles, that the popup menu will change to "Custom", but if they change the setting back again, that the popup menu changes back to show the matching profile name.

By the way, we implemented a feature like this a few years ago and shared the code in the Programming Topics section of the forum over here:

"Graphics Settings profiles" feature (source code)

That code is somewhat obsolete now (although a lot of it still applies), so I'll see if I can post an updated version that works with C4 2.1.

(By the way, Graphics Settings management was one of the examples that I initially wanted to include with the Beginner's Guide, but it's more of an intermediate-level topic that isn't typically tackled by beginners or hobbyists.)

Re: Some questions about UI (graphics settings)

by jwatte » 28 Jul 2010, 06:37

The problem is that the generation isn't all that matters. A lot of features are fill rate bound, which mainly means width and frequency of the memory bus.
The GeForce 8800 GTX will still outperform a low-end modern parts like the G210 or whatever.
There are a bunch of different places where a graphics card can get bottlenecked, and it varies by implementation. Compare the Xbox EDRAM implementation with the PS/3 banked RDRAM implementation with a dedicated PCI-Express GPU with an integrated unified-RAM chipset like the GeForce 9400M. Even along the integrated chipsets, there's a big difference. I think the 9400M has sixteen shader cores, whereas the Intel Extreme has on the order of four.
Also, the DX10 parts have unified shaders, whereas the DX9 SM 3.0 parts generally have separate vertex and pixel shader cores.

So, what you really want to know to do an OK job of selecting default is:
1) read memory rate (texturing)
2) write memory rate (filling)
3) shader computation rate (shader cores)
4) whether the memory is shared/unified or dedicated

This is separate from detecting what can be done at all with a card -- if a card doesn't have the right shader support for some advanced technique, you can't turn that on, even if the card has throughput galore among what it can actually do.

All games I know about actually contain long lists of PCI vendor and device IDs, which map to specific implementations (more or less), and set the defaults based on this information. Creating such a list requires a lot of research and testing. Also, you have to figure out what to do when a chip comes up that you don't know anything about. Typically, you'll set defaults to "medium" for ATI and NVIDIA parts, and "lowest" for any other part in this case

Re: Some questions about UI (graphics settings)

by jwatte » 29 Jul 2010, 06:39

FWIW, the "defaults" I use are:
960x600
2 samples/pixel AA
High texture detail
Anisotropic filtering 2
Enable high-quality bump mapping
Enable terrain bump mapping
Use high-detail terrain textures
Enable glow and bloom effects
Enable distortion effects

I have tweaked these to run the demos OK (but not great) on a GeForce 9500M, which is like a 9400M but with a few more shader units AFAICT.

I find that the full-screen motion blur is very expensive, and that high amounts of anisotropic filtering can be surprisingly expensive. Texture detail is largely a memory question, and most graphics systems these days have lots of RAM, and/or use unified memory where there's tons of RAM available. Also, the user off the street generally equates texture detail with quality, more than anything else.

The next two things to turn off if you want it to run faster is probably glow/bloom and anti-aliasing.
