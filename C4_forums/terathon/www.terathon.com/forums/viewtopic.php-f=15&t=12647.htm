Blender To Drop Support For COLLADA? No Need To Panic

by mschifter » 12 Feb 2013, 15:18

FYI....this is an article excerpt I just found online... It looks like COLLADA might effectively be going away from Blender:


The Mesh Forum has a post from Masami Kuramoto pointing to a mailing list discussion, which suggests that Blender, the hugely popular open source 3D creation tool, may soon drop support for COLLADA in release builds, if you’re unsure what any of this means, COLLADA is the format that users export their creations to from within Blender to make it Second Life compatible in terms of Mesh. The opening to the discussion reads:

“Hi,

As everybody noticed current collada importer/exporter is very buggy which seems to make this format almost useless in Blender. And what’s much worse — we don’t actually have developer who maintains this area.

We discussed this already with Campbell and found that OpenCollada itself isn’t actually maintaning — there are only few commits in several months. Ofcourse it doesn’t mean this library is useless and all bug from our tracker is related on that issues, but still.. Maybe the time have come to re-think this importer/exporter (investigate if it’s possible to fix issues in clear way, check if design is good enough — not sure, haven’t touched this code deep myself)?

Here’s our proposal: – Move all collada-related issues into it’s own tracker. Like it was done with BGE, it might help finding volunteer to fix them. Also, people will see that it’s not actually core stuff and that it’s community-supported. – Disable collada in release builds. It’s not useable and only seems to be making artists disappointed.

More optimistic targets would be find volunteer to pick up this stuff who will make it usable (maybe rewritting this stuff from scratch..)

– With best regards, Sergey Sharybin”

by Eric Lengyel » 12 Feb 2013, 22:32

I'm not a fan of having to link to an external library in order to read somebody's file format. They should release a specification from which we can interpret the file contents ourselves without having to rely on third-party code.

I would like to create our own open file format for 3D models and then create export plugins for various modeling packages that can write that format. We'll publish a detailed specification that would allow anyone with the requisite coding skills to write exporters for any software that supports them. We will most likely write an exporter for Blender that serves as an example implementation.

by Grognard » 13 Feb 2013, 16:19

He might be the man but only in some very limited scope. Because the convoluted file formats are the problem.

It IS easy, extremely easy to do the exporting part. Getting the data you need out of maya is very easy. You can also make it very easy to get data into C4, like it is in Ogre. Being able to do it in code with NO intermediate file format is the easiest way. And yes...it is easy. In maya they basically have an exporter written for you as a starting point.

The problem is these file formats aren't really for games, they are for everything under the sun, and extensible. So they are very complicated. You don't need 1/10th that complexity for game engines, though. Even though ogre does less for you than C4 in some sense the art pipeline is actually easier at this point.

There's basically no point to support file format like collada. What people need is a fixed target on the other end and then the exporter is easy (and once it's done it's done), eric wouldn't have to do any of them or he could do them for the most popular like maya and max (I mean really, it's not like this will take months let alone years). I did it for ogre with maya and it was a couple days. I spent that long just to have some idea what was going on in collada files, enough to realize it was a giant waste of time and give up on it.
