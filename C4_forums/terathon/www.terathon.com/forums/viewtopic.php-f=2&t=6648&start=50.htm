by rijkaard » 12 Feb 2009, 05:19

I think there's a little bit of confusion here.

DirectX and OpenGL are "simple" low-level APIs ( Ok, DirectX it's not so simple nowadays and has some high level features )
on the top of which 99% of 3D engines running on PC are built in top of.
( for example PS3 doesn't use neither DirectX nor OpenGL but a low level API very similar to OpenGL ).

The only programmers responsable for their internal implementation, are the programmers who wrote the DirectX or OpenGL driver for the chipset you are running. Typically an NVDIA/ATI/INTEL chipset.

So theoretically there shouldn't be significative differences or advantages from an API over another, at least if the board manifacturer wrote the drivers with the same accuracy.

The reason why most developers choose DirectX for game engines over openGL are often that directX has an Huge SDK that comprises not only rendering calls, but also DirectInput, directSound etc... so you can manage many more game areas ( sound, joypad, network etc... ) making a lot easyer to prototype something , or to build an engine in top of it.
Yes, you can do like Eric and mix the 2 APIs ( openGL for rendering and DirectInput for input for example )
but it's a personal choice.

Regarding the benchmark for the same call ( i mean something like DrawPrimitive VS glVertex3f or glList or something... )
i am not a low-level API guru, but i have seen several time the same software ( not only games, but also 3d content creation tool ) performing better with DirectX API on some hardware and performing better with OpenGL driver on some other.

Also, there are A LOT of factors that can influence rendering speed.
These include material complexity, the number and type of shadows, and other effects like skinning, post processing etc..

So if someone says "Engine X uses DirectX and its Demo/TestLevel ABC is 15% slower than Engine Y demo/testLevel DEF that uses openGL" this is totally nonsense and really tells you nothing on the capability and rendering power of an engine.

Companies/projects develop with DirectX because Microsoft provides for their developers like a mother provides for a 1 year old child. Microsoft discovered that if they could keep most, hopefully all, developers developing with Microsoft tools, they could ensure that software would only run on Microsoft systems. This would induce a Microsoft monopoly created by third party entities.

If you use DirectX as your rendering API, you're going to produce results faster. Microsoft has ALWAYS been about releasing a stable product that runs on many platforms. However, there are trade-offs. You will notice that OpenGL's committee takes ungodly amounts of time to release new versions/specifications of the API; however, OpenGL's API remains universally usable.
