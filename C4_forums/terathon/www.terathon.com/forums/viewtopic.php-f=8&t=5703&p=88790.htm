Re: Creating New Window with Elements

by Eric Lengyel » 08 Oct 2008, 15:48

salchichasa wrote:I got (2) to work as well. It seems you need to have the EditableTextElement inside a Window. you can't just add it as an element to TheInterfaceMgr like this TheInterfaceMgr->AddElement(my_EditableTextElement). Why is this?


Events get sent to windows, so elements that are just sitting around by themselves can't get input.

salchichasa wrote:As for (3), if I use your method to load the world, the menu bar won't be there, but I still have the same problem as before, where I can't give anything else focus since the window takes the focus. Until I close the window, only then can I click on other things. What I'm trying to do is have a window open with text that gets updated while the user is playing.


There are two things you can do:

a) specify the kWindowNoInput flag when you create your window. This tells the Interface Manager not to route input events to your window, and it will let the Input Manager stay in gameplay mode while your window is visible.

b) Instead of creating a Window, create an Interface. An Interface is an extra-light version of a window and does receive any input. You can use it as a container for showing other elements. The demo game uses interfaces for showing things like your score and weapon ammo.

When your override gets to the point where it just wants the normal functionality to take over, you should insert the following code:

Code: Select all
return (EditableTextElement::HandleKeyboardEvent(eventType, key, modifiers));

Re: Creating New Window with Elements

by Eric Lengyel » 28 Oct 2008, 12:08

salchichasa wrote:When adding a new window via the interface manager, my application loads and runs correctly, but when it is closed, an access violation error occurs.

I have the following line in the constructor of my Application sub class (Game):

TheInterfaceMgr->AddElement(new myWindowClass);


This loads a window when the main program loads.

When the application exits I get an 'access violation' error resulting in the ListBase::Purge method in the C4List.cpp file. Whis is this happening?

Salchichasa


The problem is that your application is exiting before the window it created is being destroyed. At the time the destructor for your window class is called, the actual code for that destructor has already been removed from memory because your game DLL has been unloaded. What you need to do is keep track of the windows you've created and make sure you delete them all in your application subclass's destructor. The demo game subclasses all of its custom windows types from GameWindow, and these are all stored in a list. The Game class destructor purges this list so that the windows are destroyed before the DLL is unloaded.

by Mr. Bowser » 02 Sep 2010, 12:37

Try replacing the line:
Code: Select all
TheInterfaceMgr->AddElement(pText);


with:
Code: Select all
AddSubnode(pText);



TheInterfaceMgr->AddElement adds the element passed into it as an interface, but what you want is to have the TextElement added as a control/element to the window/interface. So by using AddSubnode you're adding the element passed in as a child element of the interface.
