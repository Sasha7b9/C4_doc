by DrVonBraun » 20 Jun 2013, 00:48

I have an object that represents a character. This object has a material with two textures. A skin texture and a decorative texture that is alphablended

Now I clone this object to show the character in a window with worldview widget.
Doe to the problems I am describing, I even went so far as to create a complete new material because I thought it is material related but it isnt.

Now, I create a new overlay texture and assign it to the right texture attribute in the character that is shown in the window.

I then call Neutralize and Preprocess on the geometry node because otherwise the next render call would crash this (found this out by searching through the forum, thanks Mack for your old post)

Now the situation is that the character in the window is correctly rendered. The character in the world however, from which the one shown in the window was cloned with the Clone() call is distorted. It has nothing to do with the texture in the original one, I did some experiements, the texture is unaffected. It seems that the texture coordinates are getting messed up. This seems to affect both textures in the original character, which is why I believe the texture coordinates must be messed up (however strange it would be to have only those affected)

I checked the Neutralize() call which I thought would only affect the node, however it also neutralizes the shared geometryobject like so:
Code: Select all

When I set a breakpoint there and jump over that call of neutralizing the object, everything looks as it should. the clone in the window shows the nex decorative texture and the original model in the world is unaltered.

Is this expected behaviour?

Re: Strange Problem When updating a texture

by Eric Lengyel » 20 Jun 2013, 01:28

Instead of calling Neutralize() and then Preprocess() for the geometry, you should just be able to call InvalidateShaderData(). Even that shouldn't be necessary if the material is replaced before the geometry is rendered for the first time, but only if you change the material after it has been rendered.

Yes it has been rendered. This is a change that happens during the scenario, when a wound is added to the character for instance. When I call nothing, the next render call crashes somewhere with invalid Opengl data, presumably using the non-existing texture or so. Here is my solution I came up with. It seems to work.


Code: Select all
                              if (geometry->GetMaterialObject(a) == mpc_new_material_object)
                              {
                                 // --- PATRIC 2013/06/19 ----
                                 // ----------------------------------------------------------------------------------------------------------------------------------------------------------------
                                 // This is a nasty hack. the original Neutralize() functio that should be called here, also calls Neutralize() on the geometryobject which is shared
                                 // across all clones and will create weird effects. I collected all the calls that were made in the Neutralize() chain up to the C4::Node baseclass and
                                 // placed them here manually. Of course this is dirty but at the present time this seems to be the only solution
                                 // ----------------------------------------------------------------------------------------------------------------------------------------------------------------
                                 //
                                 //geometry->Neutralize();


                                 geometry->SetDynamicArrayFlags(0);
                                 geometry->SetNullPaintEnvironment();
                                 geometry->InvalidateShaderData();
                                 Zone *zone = geometry->GetOwningZone();
                                 if (zone) geometry->ExitZone(zone);
                                 if (geometry->GetController()) geometry->GetController()->Neutralize();

                                 geometry->BreakVisibility();
                                 geometry->SetActiveUpdateFlags(geometry->GetActiveUpdateFlags() & ~C4::Node::kUpdatePostTransform);


                                 geometry->Preprocess();
                                 return;
                              }
