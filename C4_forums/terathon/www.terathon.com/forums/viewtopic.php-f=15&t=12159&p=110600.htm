by a2k » 29 Aug 2012, 18:35

I'm going to probably state the obvious for those attempting, but I just want to start *somewhere*. Also, I haven't imported a model with textures in a while, so it may actually have been changed or broken.
For me:
The key to getting the textures to automatically import is, in the DAE file, your texture refs should contain the directory name "Import" in them, which serves as the search point of the base path to which your models and textures are stored.

That last statement is loaded with a lot of stipulation as to how you can work with your file paths.

- To start with, this means that, it doesn't actually matter what the parent directories beyond this is.
It could be "d:\myimages\Import\...", or "d:\downloads\textures\Import\...", etc.
However, to ease any problems with this, I typically:
- have the C4\Import directory as my working art directory,
- specify absolute paths when exporting DAEs. (I'm using Maya with ColladaMaya)

- The more important item to follow is of course, the subdirectory tree.
Supposing you have "d:\C4\Import\Game\models\model.dae" which references "D:\c4\Import\Game\textures\tex1.tga"
Clearly, tex1.tga must be in C4\Import\Game\textures\...
This is another reason why I have C4\import as my working art directory.

If things haven't changed in a while, this should still hold.

On a semi-related note, developers may be curious about using C4\Import\Game as the working art directory, because if you have numerous projects, you'll have C4\Import\Game1..., C4\Import\Game2.., C4\Import\Game3\..., all in the same source control repository, where it would be more intuitive to have those source art files separated by project. Well, I actually map the C4\Import\<Game> directory to a different tree in Perforce //depot/<Game>/art/Import/... This way, the Perforce tree is separated by project rather than lumped together as C4 projects.

Please take this with a grain of salt though, because again, I haven't done this in a while, but may do so when I get home tonight.

by a2k » 30 Aug 2012, 11:10

This seemed to work for me.

What I used:
Photoshop CS5
64x64 Texture -> saved to D:\a2k\c4\Import\a2k\tex\face.tga

Maya 2012
Simple cube
Lambert Material with Image Name "D:\a2k\c4\Import\a2k\tex\face.tga"
Planar map
-> Export Selection, DAE_FBX export (I used to use ColladaMaya, but I haven't gotten it working with Maya 2012 yet, nor do I think it will work).
saved as D:\a2k\c4\Import\a2k\mdl\madface.dae

The DAE has a node in it as such:
Code: Select all
  <library_images>
    <image id="file1-image" name="file1">
      <init_from>file://D:/a2k/c4/Import/a2k/tex/face.tga</init_from>
    </image>
  </library_images>


C4 2.9.1
Import Scene, with Import Texture Maps

I admit that the test may be a lot more simple than your guys' models, but I can be sure that this at least works.
