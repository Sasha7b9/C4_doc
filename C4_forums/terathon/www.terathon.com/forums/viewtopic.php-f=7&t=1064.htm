by Eric Lengyel » 28 Sep 2006, 01:21

Currently, the server has the same requirements as the client. (And yes, we are planning to have a dedicated server that doesn't render anything, but that won't be in build 128.) The CPU and bandwidth requirements for an eight player game shouldn't be a concern -- we have no problems with that many players here on middle-of-the-line CPUs. There is no master server code yet, so if you're not on the same LAN, you need to know the IP address of the server that you want to connect to.

by Miwa » 06 Oct 2006, 17:14

If you have the ogl stuff ripped out, dealing with no HWND isn't really much of an issue.

Just change code from main() to WinMain(). Compile as windows app, and alloc yourself a console (if there isn't one... different things happen if you run from cmd line and start menu).

Then just create a hidden window, and have it route msgs. It'll look like a console app, and act like one.

Ideally, you'd fake out the server to think the user had opened the console, and then output all the stuff that goes there out to stdout.
