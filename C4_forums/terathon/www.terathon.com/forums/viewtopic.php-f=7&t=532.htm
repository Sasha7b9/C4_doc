Re: What is ConstructMessage doing?

by Eric Lengyel » 03 Jul 2006, 18:04

Ludi wrote:Hi,

I'm currently playring around with C4s multiplayer part. I found these two functions, which I don't quite understand.

Code: Select all
Message *MultiplayerMgr::ConstructMessage(MessageType type, Decompressor& data) const
ControllerMessage *FighterController::ConstructMessage(ControllerMessageType type) const


Are they part of the replication system?


The MultiplayerMgr::ConstructMessage() function is the override of this:

http://www.terathon.com/c4engine/doco/M ... ssage.html

This function is called when an application-defined message has been received from another machine. It lets the application construct a new Message object of the correct type. It should only construct the message object and do nothing else.

There are particular types of messages that are sent directly to specific controllers, and the corresponding Message classes are subclasses of the ControllerMessage class. When one of these is received from another machine, the Controller::ConstructMessage() function is called so that the controller can construct a new ControllerMessage object of the correct type.

No ConstructMessage() function is called when a message is sent from the server to itself.

After a message object is constructed, the Message Manager decompresses the data into it. The data can also be validated at this stage, and any message failing validation is thrown out. After decompression, either the PlayerMgr::ReceiveMessage() function or the Controller::ReceiveMessage() function is called to handle the message, depending on whether it's a controller message or not.

Re: What is ConstructMessage doing?

by Eric Lengyel » 06 Jul 2006, 06:27

Ludi wrote:
Eric Lengyel wrote:No ConstructMessage() function is called when a message is sent from the server to itself.


And when the client and server are the same process. Is it possible to disable this default behavior?


The only reason ConstructMessage() exists is so that the correct Message subclass can be constructed when a message is received from another machine and all you initially know is the message's type. It's not a default behavior, but the only behavior. If it were to be disabled, you wouldn't be able to receive messages across the network.
