Re: arm animation

by mwituni » 25 Feb 2013, 17:43

I was thinking along these lines recently, and the more I thought about it, the more complex it became. Basic movements may be possible using a few controllers, but to get realistic motion would be a lot harder.

My 5c is : I think the way to do this is to build 'controlled joints' around bone joint and move the endpoint (ie hand) controller, with code to get the others to interpolate while following based on their ranges. While that may be 'smooth' it may be too smooth, so you'll want to get some deviation (like giving say the elbow a random directional 'shove' to make it more natural).

Ideally physics jointed objects could be used, but I don't think C4 joints are ready yet.

It sounds like inverse kinematics is what you're looking for. There is actually an example animator in the demo game called WeaponIKAnimator that moves the player's arms so that the hands reach given points on the weapon. It's not a general solution, but it might give you a starting point for something of your own.

Re: arm animation

by Eric Lengyel » 03 Jan 2015, 17:34

GameWizard wrote:Blender can apparently create an inverse kinetics animation. Would that be exported in the ogex file?


Yes, but you would probably need to check the "Force Sampled Animation" box in the exporter options to see it. This doesn't actually export the IK information itself, but just the results created in Blender.

GameWizard wrote:is there C4 animation code that can use that animation file so that if I find and move a hand or finger node in my character with the mouse, the attached arm will move accordingly?


There isn't a generic IK animator in the engine, but you've found the IK code used to put the player's hands on the weapon. This animator is actually pretty generic and could be used for other purposes. We might bring something like this into the core engine in the future.
