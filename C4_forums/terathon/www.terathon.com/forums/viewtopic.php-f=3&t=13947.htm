Re: Terrain Height

by Rastar » 01 Nov 2014, 00:21

A heightmap simply has pixel values between 0 and 1 (or rather, in the case of a 16bit heightmap, its values range from 0 to. 65535 which are scaled to the 0-1 range during import). The pixel height is simply multiplied with the max height that you specify during import.

So Jesse is right, the heightmap contains relative heights, which are transformed to absolute heights when importing it into the engine.

by datalol-jack » 01 Nov 2014, 03:05

Like Rastar and Jesse said, you are interpolating: approximating a continuum from a discrete set of values. In many CS applications, this often just means taking a particular kind of weighted average repeatedly to fit your data to some constraints. If you skim a few intro sections on articles regarding interpolation and linear interpolation particularly, you should have a reasonable idea of what's going on. From there you can either go and learn the formal mathematical justification for the approach or reach for a more pragmatic computer graphics article on terrain generation.

Re: Terrain Height

by Rastar » 01 Nov 2014, 12:25

If your pixel values really are 20 to 200 (out of a possible range from 0 to 65535), then

assuming you set a maximum terrain height of 200 during import

- a pixel value of 20 will result in a height of 20/65535 * 200 = 0.06m, and
- a pixel value of 200 will result in 200/65535 * 1000 = 0.6m

If, however, you mean by the range that your heightmap generation tool (e.g. World Machine) treats 200 as the maximum value and write a 65535 for every pixel >= 200m, then

- your tool will encode a height of 20m as 20/200*65535 = 6554
- encode a height of 200m as 65535
- during import (max height at 200m) this will then be 20m and 200m respectively.

Hope I'm not confusing you further...
