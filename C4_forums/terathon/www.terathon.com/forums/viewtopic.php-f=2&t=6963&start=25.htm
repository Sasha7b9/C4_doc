Re: Version 1.5.5 Now Available

by Eric Lengyel » 29 Mar 2009, 23:38

gogo wrote:I've noticed a BIG drop in framerate when running 1.5.x, compared to
previous versions. I ran the simple test of compiling each build "Optimized",
loading the Tech Demo world, and just standing there. I'm running on a
MacBook Pro (specs below).


By running on a MacBook Pro, you instantly have two big things working against you:

(1) Apple's OpenGL implementation is slow and buggy. In order to get the shadow mapping working correctly in version 1.5 on the Mac, we had to implement a hack that disables a major hardware optimization. Apple claims to have fixed this issue in MacOS 10.5.7, but I have not verified that yet.

(2) You're on a laptop with slow memory, and the textures got a lot bigger in version 1.5.x. You should reduce your texture quality to medium in the Graphics Settings dialog. It would also help to turn off anisotropic filtering (move the slider to 1), motion blur, glow/bloom, high quality normal mapping, and maybe terrain normal mapping. Experiment a little and see which ones help the most.

In addition to these, note that the terrain is completely different in version 1.5 and later, even in the demo levels that existed before. The shader used on the terrain is far more complicated, and the GeForce 9400M only has 16 stream processors to run it, compared to 112 stream processors in the 9800M. Using the new terrain shader is not required on the voxel terrain, however -- it's still possible to use a simple 2D texture map and get back to a faster shader for the terrain.

Re: Version 1.5.5 Now Available

by Eric Lengyel » 07 Apr 2009, 02:47

If you change the size of the shadow space after the light is linked to it, then you need to invalidate the light in some way in the editor in order to see the change in shadow resolution in the editor. In addition to moving the light, you can invalidate it by selecting the light, hitting Ctrl-I for the info window, and then just hitting OK. The reason it doesn't happen automatically is because nodes don't know what's connected to them, just what they connect to. (But this will probably change in a future release.)
