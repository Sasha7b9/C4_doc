Final C4 Pre-purchase questions!

by Staples » 24 Jan 2009, 19:17

Well we had our team meeting last night and went over the engines, we have all but decided on using the C4 Engine! Once the roadmap is complete it should be quite suitable for us - at least for now we will use it to do our prototyping.

I just want to recap and make sure all of this is possible/easy enough with C4 at the moment, obviously I will need to get my hands dirty with the source code but that's the fun of it!

So. Are all of these items available out of the box, or easy to implement without to many complications?

1. Any sort of character movement (jumping, melee combat, climbing walls, grabbing onto ledges, dodging, swimming etc) - I don't think there should be any problems here?

2. Does C4 do blended animations? We will probably need to use these for combat etc.

3. Day/Night cycle with shadows changing as the light source moves. Also the ability to change the sky (clouds, less clouds, stars) during runtime - I have seen a video of day/night cycle so that should be fine I believe, not sure about changing the sky but you can probably create multiple skyboxes or at least change the skybox material at runtime?

4. Are there any restrictions on GUI/Interface. We wan't your standard RPG stuff like action bars, inventory, character sheet, compass, minimap, quest log etc. - We haven't done much with the GUI so I'm not what the limitations are, does all Gui need to be done via source or something? Is the Unified GUI Editor what I think it is, a way for you to create the player GUI in the world editor?

5. Gui Drag & Drop. The ability to drag and drop things around your inventory, and abilities into action bars etc. Is this possible?

6. Casting spells - I doubt there are any issues with this

7. A Loading Screen with a progress bar, if possible the ability to play a movie or show/change pictures in the background while it's loading. - Is this possible? I've read some things that make me think a loading bar is currently not possible. If not is it in the roadmap?

8. Mounting, for example riding a horse. Not really sure what the restrictions on this are, probably one of the more difficult things the same as the point below.

9. Changing player armor, equipping different weapons - Weapons should be straight forward I imagine, armor as discussed could be a bit more complicated. Worst case you have to mesh hide everything, best case you can somehow mount armor to the player and have it move with him.

10. Will all movement from point 1 'just work' in multi-player as is, or do we need to add things for this. For example if we add the ability for players to swim and climb walls (i assume in the controller), then all clients should show the same result

11. Connecting to a database server for things like inventory - I don't see why this would be a problem

12. Running game logic on a headless server, ideally we want an authoritative client/server setup - this means all combat and even collisions would need to be handled server side. - I'm assuming C4 can't run on linux, can it be made to if it is run headless?

13. Extending on the previous point, is interpolation built in or to we have to do this our selves?

14. Music, can we change the music during runtime (for example different music when in combat) - This should be pretty straight forward I would imagine

15. Sounds, can we play different sounds depending on what type of material we are walking on (water, wood, gravel, metal) - This is probably fairly straight forward as well?

16. Lightning with a full screen effect - I know lightning is possible, but is it possible for example to do a full screen effect such as making everything black & white when the lightning strikes?

17. Options menu. Can we have video options at run time to turn shadows off, change the quality/level of shadows, change the model quality, change the texture quality etc? Just the basic things you find in games to fine tune performance.

18. Key binding. Can we have an options menu where players can bind their own keys to anything, be it movement, opening their spell list, binding it to a slot in an action bar etc.

19. I know the foliage system isn't in yet, but can you still place multi directional billboards in the world and set it up in the way that games generally use billboards for grass and other things? What are the options for populating a world with grass at the moment (granted this isn't a big problem at the moment, as long as there is some way to test it in a small area)

20. Shorelines, is it possible to have nice shorelines where you have a beach? For example you might have a bit of foaming at the edge of the water and have it nicely fade out into the terrain.


So overall, is there anything here that C4 would have trouble with or would take significant work to get going. Obviously when you have the source you can 'technically' do anything, but can all of the above be done without running into limitations of the engine as is?

Re: Final C4 Pre-purchase questions!

by Eric Lengyel » 24 Jan 2009, 20:55

Staples wrote:1. Any sort of character movement (jumping, melee combat, climbing walls, grabbing onto ledges, dodging, swimming etc) - I don't think there should be any problems here?


If you can animate it in an external program, then it will play in the engine. Melee combat will be a little hard to do until our new physics system is released (next big update). Nevertheless, a game with melee combat has already been published (Quest of Persia 2), so it's definitely doable.

Staples wrote:2. Does C4 do blended animations? We will probably need to use these for combat etc.


Yes, there is explicit support for animation blending.

Staples wrote:3. Day/Night cycle with shadows changing as the light source moves. Also the ability to change the sky (clouds, less clouds, stars) during runtime - I have seen a video of day/night cycle so that should be fine I believe, not sure about changing the sky but you can probably create multiple skyboxes or at least change the skybox material at runtime?


All shadows in the engine are dynamic. If you move any light source, the shadows it's casting update correctly. You can also change the skybox at runtime.

Staples wrote:4. Are there any restrictions on GUI/Interface. We wan't your standard RPG stuff like action bars, inventory, character sheet, compass, minimap, quest log etc. - We haven't done much with the GUI so I'm not what the limitations are, does all Gui need to be done via source or something? Is the Unified GUI Editor what I think it is, a way for you to create the player GUI in the world editor?


There are no restrictions, but yes, currently GUIs need to be created in code. However, we are expanding the current panel editor so that it can be used for general dialogs very soon.

Staples wrote:5. Gui Drag & Drop. The ability to drag and drop things around your inventory, and abilities into action bars etc. Is this possible?


Yes, this can be done.

Staples wrote:6. Casting spells - I doubt there are any issues with this


That's all up to your game code. You shouldn't run into any problems.

Staples wrote:7. A Loading Screen with a progress bar, if possible the ability to play a movie or show/change pictures in the background while it's loading. - Is this possible? I've read some things that make me think a loading bar is currently not possible. If not is it in the roadmap?


This will be possible in the next release. We have already implemented a new multi-threading system, and it lets you do stuff like this.

Staples wrote:8. Mounting, for example riding a horse. Not really sure what the restrictions on this are, probably one of the more difficult things the same as the point below.


This should actually be rather easy. You just need to define an attachment point on the horse, and then stick another model there in the right position.

Staples wrote:9. Changing player armor, equipping different weapons - Weapons should be straight forward I imagine, armor as discussed could be a bit more complicated. Worst case you have to mesh hide everything, best case you can somehow mount armor to the player and have it move with him.


Attaching/removing rigid objects from character models is very easy. You just need attachment points on your model and calls to AddSubnode() in your code.

Staples wrote:10. Will all movement from point 1 'just work' in multi-player as is, or do we need to add things for this. For example if we add the ability for players to swim and climb walls (i assume in the controller), then all clients should show the same result


If your movement uses the appropriate controller messages, then yes, it will just work in multiplayer.

Staples wrote:11. Connecting to a database server for things like inventory - I don't see why this would be a problem


This is up to your game code. The engine won't get in your way when doing things like this.

Staples wrote:12. Running game logic on a headless server, ideally we want an authoritative client/server setup - this means all combat and even collisions would need to be handled server side. - I'm assuming C4 can't run on linux, can it be made to if it is run headless?


C4 does not run on Linux, but is can run headless on Windows or Mac.

Staples wrote:13. Extending on the previous point, is interpolation built in or to we have to do this our selves?


Interpolation is built into the character controller, but prediction is not. We're planning to add general client-side prediction soon.

Staples wrote:14. Music, can we change the music during runtime (for example different music when in combat) - This should be pretty straight forward I would imagine


Yes, this is extremely easy.

Staples wrote:15. Sounds, can we play different sounds depending on what type of material we are walking on (water, wood, gravel, metal) - This is probably fairly straight forward as well?


This can be done, but right now it would be somewhat tedious. This is something I consider to be a high-priority feature to be implemented soon.

Staples wrote:16. Lightning with a full screen effect - I know lightning is possible, but is it possible for example to do a full screen effect such as making everything black & white when the lightning strikes?


Black and white, no, but it would be something that we could easily add to the post-processing system. Currently, it would be easy to light everything up by either changing the ambient color (like in the Cemetery demo) or by changing the post-processing scale and bias colors.

Staples wrote:17. Options menu. Can we have video options at run time to turn shadows off, change the quality/level of shadows, change the model quality, change the texture quality etc? Just the basic things you find in games to fine tune performance.


You can't turn off shadows, and we are not going to add the ability to do so. (It would make everything terribly ugly, and light would shine through to a lot of places you don't want it to.) There are currently several settings in the demo that allow you to adjust texture quality and turn various features on or off. See the Graphics Settings dialog.

Staples wrote:18. Key binding. Can we have an options menu where players can bind their own keys to anything, be it movement, opening their spell list, binding it to a slot in an action bar etc.


Yes, see the Control Settings dialog in the demo.

Staples wrote:19. I know the foliage system isn't in yet, but can you still place multi directional billboards in the world and set it up in the way that games generally use billboards for grass and other things? What are the options for populating a world with grass at the moment (granted this isn't a big problem at the moment, as long as there is some way to test it in a small area)


The only thing you can do for grass right now is hand-place transparent quads and then copy/paste them all over the place.

Staples wrote:20. Shorelines, is it possible to have nice shorelines where you have a beach? For example you might have a bit of foaming at the edge of the water and have it nicely fade out into the terrain.


We do not currently have support for foam, but it's something we're going to add soon.

Staples wrote:So overall, is there anything here that C4 would have trouble with or would take significant work to get going. Obviously when you have the source you can 'technically' do anything, but can all of the above be done without running into limitations of the engine as is?


I think overall, everything looks like it will be very straightforward. The problems you'll run into in the current release are melee combat, grass, and shorelines. Our new physics system in the next release will take care of melee combat, the new foliage system coming soon will take care of grass, and shorelines will probably appear in between those.

by mwituni » 25 Jan 2009, 10:16

Guess its all down to way of dealing with the lag issue, with different coders trying different options. In most cases you'd probably not want to wait for the server result though, else the target will fall dead late every-time, so probably more acceptable to do the client calculation and result based on that and play the animation, and if he wasn't supposed to eg. die let him stagger to his feet with some screen blurring etc after the server corrects it - shouldn't be long after the animation for going down completes. Makes for some extra falling and maybe a bit more apparent damage than usual (in laggy conditions), but most might find that more acceptable.

Might help to smooth over things to code in some "prediction" algorithm too with a slight influence (weight) on the outcome - the influence of that could be a fine-tuning parameter.

For roll-of-the-dice prediction type outcomes a good idea is to roll the dice before its required (as opposed to when its required) - create a 'random' stack if required ... ie .. the 'next' roll-of-the-dice (random) value is 72 (/100 eg) - that way the server and client already have it in synch when its needed and a more accurate/synchronized outcome can be played.
