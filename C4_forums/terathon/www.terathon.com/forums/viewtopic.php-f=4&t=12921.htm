What exactly is necessary for QueryCollision() ?

by DrVonBraun » 18 May 2013, 02:19

I've been fiddling with this all day long now and I just cant get it right. I have a model that I loaded from a file and I am trying to detect it with QueryCollision().

I know I need a rigidbodyController for that, so I attached one, but collision doesnt work. Then I figured out it also needs a shape, so I attached a box shape around it. Now it seems that it detects collision with the box shape, not with the geometry, I made the shape deliberately bigger and the collision is reported when I shoot the ray aside the geometry where it still hits the shape.

What do I need to do to use QueryCollision() to detect an object that is a rigidbody?

Edit: I tried this in different ways and I am absolutely sure now that the shape is used to detect the collision not the geometry when you have a rigid body. Is there no way to get the collision point for the geometry when a rigid body is detected?

Re: What exactly is necessary for QueryCollision() ?

by DrVonBraun » 18 May 2013, 04:55

If anybody else runs into similar problems, here is what I found out and how I solved it. First the problem:

I don't use the C4 physics system. So I need to be able to detect collisions and distinguish between terrain and other geometry from the environment, characters and items which can be placed and picked up by characters like tables etc. I also need to have exact collision data for items since I want the character to be able to walk on items which are low enough or be blocked from those which are too high.

In my case, collision with characters are detected as collisions with RigidBodies, because they have a rigidbody controller and a capsule shape.

The collision with items work basically and they are treated like static geometry, which works fine to determine a point on which a character can walk, but when performing a ray pick to detect which item the player clicks, it breaks down because they are indistinguishable from static geometry here. I could add a box shape which makes them roughly pickable, but then they can not be used to walk on top anymore because the box will represent the outer hull and now the character will mostly hover above the item.

So my solution is to create a helper class derived from Node like so:
Code: Select all
         class Item_Node : public C4::Node
         {
         private:
            Item      *mpc_node;
         public:

            Item * Get_Item_Ptr()
            {
               return mpc_node;
            }

            Item_Node(Item *pc_node) : C4::Node(D_ITEM_NODE_TYPE)
            {
               mpc_node   = pc_node;
            }
            ~Item_Node()
            {

            }

         };

with "Item" being my own type that contains all the functionality of a dynamic item a character can manipulate. Create an C4 Model for an item in this way:
Code: Select all
         void Item::Materialize()
         {
            mpc_item_root_node   = new Item_Node(this);

            mpc_item_root_node->AddSubnode( CLIENT::SYSTEM::Model_Register::Get_Singleton().Get_Model( Get_Item_Type() ) );

            CLIENT::WORLD::Game_World::Get_Singleton().Add_Object( this, Get_Server_World_Position(), Get_Server_World_Rotation() );
            mpc_item_root_node->Invalidate();
         }

(which contains quite some types of my system but I think it is understandable what is happening here). Now, when the QueryCollision() function returns kCollisionStateGeometry, one can distinguish between static environment geometry from the editor and Item types which must be selectable like so:
Code: Select all
               U32         u32_node_type = pc_geometry_node->GetNodeType();
               C4::Node   *pc_testnode = (C4::Node *) pc_geometry_node;
               while( pc_testnode != nullptr )
               {
                  pc_testnode   = pc_testnode->GetSuperNode();
                  if( nullptr != pc_testnode)
                  {
                     u32_node_type = pc_testnode->GetNodeType();
                     if( u32_node_type == D_ITEM_NODE_TYPE )
                     {
                        rpc_clicked_item   = static_cast<CLIENT::WORLD::OBJECTS::Item_Node *>(pc_testnode)->Get_Item_Ptr();
                        return 2;
                     }
                  }
               }

with D_ITEM_NODE_TYPE being the type of the new helper node. This node can be placed in the world etc since it's a normal node.

Now, when I click in the main window, I get a distinction between Terrain, dynamic items and a rigidbody
