Oh! Jonathon had the same idea I had a couple of days ago, laying a widget across the screen to capture mouse input. It doesn't work, and would be pointless. What you really want to do is register a Mouse Event Handler in the engine to capture mouse input. This works best if the engine's input is kept in Interface mode, because when the InputMode is set to kModeMouseActive, the Input goes straight to actions and the mouse handler doesn't grab any of the mouse input.

Then, basically, when the user clicks test to see if any widgets were hit, if none were then they are clicking in the world view. From there you can send the mouse input to whatever you want to handle the world input.

Re: Windows vs boards

by Jonathon Ogden » 28 Feb 2011, 07:14

Hi CodeNewt, if I have understood you correctly, you don't have to inherit from the FrustumViewport widget to set the camera; if you are using a viewport widget then you can set its camera up by calling GetViewportCamera then adjusting the properties of the returned camera object. The returned camera object can be set as the worlds camera then.

You need to set the worlds flags to contain kWorldViewport for it to render in your viewport.

Sorry if its not the answer you were looking for.
