Re: Problem with timeout

by Mussi » 24 Mar 2013, 08:15

cbken wrote:Hmm ok so UDP packets are sent till they are confirmed then? Not sure how that works exactly. What about if the confirmation gets lost? Is a confirmation of the confirmation necessary? What if that one gets lost? Where does it end??

Can you really make a UDP packet reliable?


If the confirmation gets lost you'll keep resending, unless you timeout. Basically a confirmation of a confirmation is implicitly done by sending new data with increased sequence numbers. Reading up on TCP will do a better job at explaining this than I could in a short post so I recommend doing that as well.

As for your second question, I'm sensing a misunderstanding or misinformation, my apologies if I was wrong. You can't make a single packet reliable, this is true for any protocol. You can send multiple packets to get some form of reliabilty and this is what's built-in in the TCP protocol, it sends a stream of packets until everything is confirmed to be sent.
UDP does not have this built-in mechanism, but you can add some extra reliability data to your packets to build a lightweight reliability protocol on top of UDP that's more suited for games.

This is a good read on TCP vs UDP and how to build such a reliabilty protocol on top of UDP: http://gafferongames.com/networking-for-game-programmers/

I've made a bit more testing:

1.) The problem does not happen, when both client and server are in the same subnetwork, even when external IP is used.

Situation:
1.) My home PC hosted server on external API (I've NAT based internal network) bound to one of network interfaces
2.) I've run client on VMWare virtual PC which I connected to home PC via second network interface (VMWare emulated one)
3.) I've connect from client to home server using Network Provider external IP (so packets were sent via NAT and had to pass router with no port forwarding to client enabled)

The problem does not happen, everything went smoothly

2.) The problem happens, when both client and server are in different subnetworks (ie. different Network Providers). Tested on two different examples with this scenarios:

1.) Hosted on my home PC, with port forwarded on router
2.) Client PC behind NAT
3.) Client PC works, but after several seconds received timeout event

Edit Now that's weird!
The problem completely disappear when I removed SetPortNumber and SetBroadcastPortNumber before calling BeginMultiplayerGame(false)
