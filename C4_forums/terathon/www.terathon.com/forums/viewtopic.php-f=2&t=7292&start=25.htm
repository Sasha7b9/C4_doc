by TheRhinoDude » 03 May 2009, 14:28

At many of the "cheaper" hosting providers, it often doesn't matter if dedicated hardware is used or not when determine top download speed, as the sites are typicallty bandwidth throttled independently of server load. It's a dirty little secret among these providers, and some don't even put it in the fine print.

For example, at with hostmonster.com, you could be parked across the street from their data center with a very short 6 route hop and dedicated server, and you would still never see > 80kbps sustained transfer rate, because they web server is bandwidth throttled. Otherwise, they wouldn't be able to support tens of thousands of sites on their meager bandwidth, and therefore their business model would never fly. The top dozen or so active sites would bury them.

This is how they are able to offer "ulimited storage, unlimited bandwidth" for $6 a month. It's all about scaling out to massive amounts of customers, and making the sites consume as little simultaneous bandwidth as possible. The throttles make the sites run great for typical web surfing usage, but as soon as you start downloading massive files, the throttles become immediately apparent.

Re: Version 1.5.9 Now Available

by Eric Lengyel » 07 May 2009, 16:34

ethanc wrote:At any rate, I'd much rather find a solution to the thing i originally posted about with the armor becoming an unanimated pile on the floor both with and without "do not apply model animation" on.


Let me make sure you've gone through the right steps:

1) Import the character model itself into an empty world.
2) Open a new empty world and import the armor model.
3) Select the geometry nodes in the armor model and copy with Ctrl-C.
4) Close the armor world without saving.
5) Paste the armor into the character model's world with Ctrl-V.
6) At this point, the armor should appear skinned correctly against the character's skeleton.
7) With the pasted armor nodes still selected, hit Ctrl-I and check the "Do not apply model animation" box under the Node tab.
8) Save this world as a model resource.
9) Close the world, and open the model you just saved in the model viewer.
10) Import an animation for the character model.

S3TC vs others


Putting X/Y into S3RC A/G is a great trick, because it takes the normal map down to 1 byte per pixel of actual VRAM, with minimal loss of precision. If you don't necessarily need extreme detents in your normal maps, you can get the precision loss down even more, by scaling from, say, -0.5 .. 0.5 instead of -1 .. 1.
The NVIDIA Photoshop plug-in to save DDS files has supported this format for a long time (as DXT5_NM), and I've been a big fan in general. Glad to see C4 is doing it, too!
