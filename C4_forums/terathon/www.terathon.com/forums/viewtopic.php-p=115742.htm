Re: C4 Engine 3.0 development release 3 now available

by Eric Lengyel » 09 Mar 2013, 04:18

The code and binaries for version 3.0 have been updated to fix the performance issue. The data files have not changed.

The problem was that Visual C++ had been generating code that was reading back data that had just been written to write-combined memory represented by data structures declared volatile. (The engine writes to WC memory when filling mapped vertex buffers.) In my expert opinion, no programmer would have reasonably expected the data to be read back in the particular case at hand, but the C++ standard underspecifies this situation and lets the compiler do whatever it wants.

Re: C4 Engine 3.0 development release 3 now available

by Eric Lengyel » 09 Mar 2013, 05:05

Jesse Meyer wrote:Does the SSAO operate on normals maps without SSAO? If it does, it's too faint to notice.


There is no interaction between SSAO and normal maps.

Here's a good way to see the difference that SSAO makes: Enter the following command into the console (copy and paste):

Code: Select all
bind , "$renderAmbientOcclusion=0";bind . "$renderAmbientOcclusion=1"


Then you can use the < and > keys to turn SSAO off and back on again as you're playing a world. (SSAO first needs to be enabled in the Graphics Settings if not already.)
