Re: Using the MessageManager and NetworkManager simluatenously

by Eric Lengyel » 03 Nov 2010, 20:43

If you use the network manager while you're also using the message manager, then you'll be interfering with the way that the message manager uses the network manager, and all hell will break loose.

We are planning to add some TCP/IP abstraction for doing things like connecting to a master server. Right now, the only safe way to do it is to open your own TCP socket through the OS.

Re: Using the MessageManager and NetworkManager simultaneously

by Eric Lengyel » 04 Nov 2010, 00:30

1. The domain name resolver transforms a text address into an IP address, so you don't need it when you already know the address. (You probably know this and are just using 127.0.0.1 as a temporary stand-in.)
2. The resolver does not complete immediately, and you can't call GetAddress() for it until it does complete (see docs).
3. You should use a port number in the "registered ports" range (1024-49151). Port 80 is reserved for HTTP.
4. The server needs to call NetworkMgr::SetPortNumber() to establish its port, and it should be the same as the port you're trying to connect to.
