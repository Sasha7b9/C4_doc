Poker Game using C4 Script only

by jimbobjames » 21 Oct 2008, 14:46

Attached below is a game of video poker made using C4 scipt only. No custom coding was required, although some of the exisiting custom methods of the demo "Game" were used for a surprise at the end, if the player loses. The "Display" method was also used to help with debugging.

Here is a screenshot:

DrawPoker.jpg


It is assumed the player is running the demo "Game" application which ships with the engine ($applicName = "Game"; in Data/Engine/variables.cfg).

Place the world under data/Tutorial/world. It uses a sound called "Beep1", which it expects to find under data/Demo/sound. Release 1.4.10 ships with that sound file in that directory already.

Notes:

*The main script is triggered by the "Deal" button on the Panel
*A workaround for the modulo function was used
*I could probably compress the script some more using "&" and "|" inside some of the expressions, but I feel it is also nice to "see" the data flow from expression to expression on the script canvas
*A couple of "Display" methods have been left in so that debug text can be added if needed.
*I've also attached a picture ("DrawPoker.jpg") which shows at a high level what the various parts of script do.

I was planning to make other script-based (multiplayer) card games, like BlackJack etc. Might be cool to play with friends who are abroad or away from home etc... I'd also add detailed explanations as to how to go about making these.

Would anyone be interested in that kind of tutorial?

DrawPoker.rar

Anyway, I hope you like it. Have fun!

by Eric Lengyel » 23 Oct 2008, 17:06

jimbobjames wrote:I made a sphere and assigned a script to it which changes the color of the sphere every (random) x seconds. Now when I copy that sphere, I hoped the random value would be different for the copy, but it was the same as for the original. I thought that by making the random variable local scope, the copy would'nt have the same value.


The reason this is happening is because the two spheres are sharing the same material. If you change the material for one of them, you're changing it for both of them. To get around this, duplicate the material in the material manager, and assign the copy to one of the spheres.
