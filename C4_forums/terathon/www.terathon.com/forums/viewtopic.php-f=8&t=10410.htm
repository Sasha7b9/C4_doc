Foreign input

by BlindLuke » 22 Feb 2011, 11:47

C4 supports Unicode, but I have a problem with Unicode input.
My system keyboard is set to "polish(programmers)"

My text input widgets don't support polish letters, even after setting them a proper font. (though copy/paste works like charm).

After some searching in C4 sources, I found, that "Text::WriteGlyphCodeUTF8" function receive "code".

When I press letter "a with tail" (unicode: 0x105, win1250:0xb9),
function Text::WriteGlyphCodeUTF8 writes to table "text" two bytes {0xc2, 0xb9} instead of [0xC4, 0x85].

Reason:
Parameter "code" is in ansi(win1250 codepage) -> should be unicode.
Setting "Use unicode character set" in project properties does nothing, because there is "#undef UNICODE" in engine sources.

My "quick and dirty" solution:
Change CreateWindowExA function to CreateWindowExW <- and change some parameters to compile it successfully.


My question:
Why does C4 use WinApi function with "A" suffix? If it supports Unicode, I think there should be "W" everywhere, or at least for input.

just change in control panel the language of Your keyboard to "Polish programmers".

I've got two revisions, old and new.
On old one, I put breakpoint in C4Engine.cpp, line 1090 (eventData.keyCode = wparam):

I press "Latin small letter a with ogonek" Unicode: 0x105 (Right alt + "a")
wparam = 0xb9 (it's ansi-Win1250, not unicode)

When I press "Latin small letter n with acute" Unicode: 0x144: (Right alt + "n")
wparam = 0xf1 (same as above, not unicode)

Function Text::WriteGlyphCodeUTF8 obviously returns bad UTF-8 when parameter "code" is not in unicode.
