Re: Hardware skinning

by Eric Lengyel » 02 Oct 2012, 13:24

Skinning is done using high-performance multi-core algorithms on the CPU. It's still faster this way for most hardware when you need to render skinned meshes multiple times per frame. As DX11 hardware grabs more of the market share, we plan to use GPU compute shaders to do this work.

There's this from 2009:

Eric Lengyel wrote:Here's a screenshot of the 100 skinned character demo that I was talking about before.

Goblins.jpg


This image is 1280x1024 pixels in size and was rendered with all graphics features enabled, 4X multisampling, and 4X anisotropic filtering. Each of the 100 goblins is being rendered with ambient + point lighting, stencil shadows, and motion blur, meaning that the mesh data is actually being rendered four times per character per frame. Each character is skinned on the CPU once per frame using the new job-based, SIMD-optimized skinning code in version 1.5.9. The goblin model has three LODs composed of 3362/2010/1095 vertices and 4954/2620/1354 triangles. As shown in the image, the frame rate is just over 30 FPS.

The image was rendered on the following hardware:

CPU: Intel Core2 Quad CPU Q6600 @ 2.40GHz
GPU: Nvidia GeForce 8800 GTX

The weapon in the player's hands is the new Quantum Charger that will appear in version 1.6.

Original post: viewtopic.php?f=30&t=7595&p=67146&hilit=goblin+skinning#p67146

There used to be lots of limitations to skinning models on a GPU; for example an approximate limit of 80 bones per model, and the fact that if you skinned the models on the GPU you have skin them once for each pass. The CPU based skinning was a good choice based on the technology... wow you should see the lengths I went to to get good skinning performance in my C#/XNA game engine a few years back

However, these days graphics cards have improved a lot, in particular GPGPU is now becoming quite common. It's now just really a matter of deciding when is it appropriate to drop support for older hardware.

Juggernaut wrote:So since animation is still done on CPU does it not impact the frame rate when a large number of characters ( ~ 4000 polys each ) needs to be visible at once on screen ?


Don't you think the GPU would go slower, too? (The correct answer is yes.) Running something on the GPU does not magically make it infinitely fast, and it takes away from the performance of other rendering tasks. Almost all computers have extra processor cores sitting around doing nothing, so putting the skinning work there makes a lot of sense.
