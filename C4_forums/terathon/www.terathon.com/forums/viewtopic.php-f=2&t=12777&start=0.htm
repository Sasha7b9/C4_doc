Re: C4 Engine 3.0 development release 4 now available

by Eric Lengyel » 02 Apr 2013, 23:55

ca$per wrote:I've just reviewed the release notes and one thing caught my eye:
(In release 4) The separate tabs for ambient and light shaders have been eliminated, and there is now a single shader graph containing output nodes for both the ambient and lighting passes. Separate passes for existing shaders are automatically merged, and any redundancies due to common calculations in both passes are automatically unified.

Was wondering, what was the reason for this? Is multipass rendering still present?


There are a few reasons for this. Here are two of them:

1) Shaders tend to have some of the same input values (colors, texture maps, numerical parameters) and calculations for both the ambient pass and lighting pass. To change one of these, you previously had to make the change in both shader graphs, which was a pain. It just wasn't generally good to have all that redundant stuff in there. Now the engine just sees one shader graph, and the engine's shader compiler eliminates the parts that is doesn't need for either the ambient pass or lighting pass.

2) Now that stencil shadows are not used for infinite lights, we can unify the ambient pass and light pass for the main light source (e.g., the sun) in an outdoor scene. This will reduce the amount of work done by the GPU and provide a large performance boost.

Re: C4 Engine 3.0 development release 4 now available

by Eric Lengyel » 03 Apr 2013, 16:38

miken wrote:Are you still re-submitting the geometry for each light affecting an object, or are you generating permutations of shaders for each supported combination of lights? Or is only the 'first' light combined with the ambient pass?


The ambient pass will be combined with the "primary" lighting pass only, where the primary light is an infinite light that generally affects the whole outdoor scene. Additional local lights are not combined for a variety of reasons, including the fact that shadows have to be generated separately, and the minimal geometry affected by each of those lights is re-submitted.
