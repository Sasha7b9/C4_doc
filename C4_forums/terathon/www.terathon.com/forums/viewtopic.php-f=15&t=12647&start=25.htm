Re: Blender To Drop Support For COLLADA? No Need To Panic

by Eric Lengyel » 13 Feb 2013, 19:20

cboyce wrote:Would it be feasible to write up a specification for the WLD file format?


No, it's not possible. The WLD format is not constant, and changes are frequently made to it. You don't notice this because the engine is designed to handle these changes transparently. Furthermore, the WLD format is not designed to be an interchange format like Collada is, and it wouldn't be appropriate to write directly to the WLD format from any external application.

cboyce wrote:I know we could deduce it from reading the collada importer code.


The importer does not generate a WLD file. It creates the scene in memory and sends it to the editor. The WLD file is created when the scene is saved in the editor.

Re: Blender To Drop Support For COLLADA? No Need To Panic

by Robert » 16 Feb 2013, 08:21

The (plain and simple) way i see it, it's really a matter of stuff being or being not practical.
Right now, every model needs to be translated twice. Once on import, once on export.

blender -> COLLADA -> C4
maya -> COLLADA -> C4
...

With the big disadvantage that some features which are supported by the creative tools and the engine are not or poorly supported by COLLADA, OR an exporter is buggy or lacks a feature, and so on. One has to reshape everything on export,tweak a lot of settings, and on import again. And then re-add what's missing.
I think it sounds much easier having it this way:

blender -> C4
maya -> C4
...

Some other engines have the approach to have lots of importers, so they can read directly from blender files and from others. Such would require a lot of maintenance work to keep up with the file shape versions of other tools.

So, having the ability to have an exporter-plugin in the different creation tools that spits out a file which:
- has all the info C4 needs in one file
- can directly go into the import directories
- won't need much or any setting-tweakage or transforming or this-or-that-way-importing-and-exporting or manual-reconfiguring...

I'd raise a glass on such a thing.
And if no exporter exists, you can still try to get it into COLLADA.
