Just to let you all know, if you do not wish to upgrade to Vs2008 you can always arbitrarily convert the solution and project files down to VS2005 with a simple little change. JTLYK. You open C4.sln in notepad and change the "Format Version 10.0" to "Format Version 8" and then open up each vcproj file, like for example: Engine.vcproj, under the VisualStudioProject tag change 'Version="9.0"' to 'Version="8.0"' and then you should be able to open them all in the previous versions.

I haven't tested this specifically with C4, but I have done it with so many different solutions and projects because my school's old computers all used VS2003 and I had VS2005 at home so I'd always have to convert them between the comps.

bryced wrote:
neonic wrote:Oh, yeah, also a feature of the VS2008 Pro that I am looking forward to is the Unit Testing. Oh my god, finally some support for easy unit-testing. This looks like a god send if it operates at least halfway decent. I am going to have to do some testing later.


Sorry to drag this even further offtopic, but this makes me curious. Usually the FEWER features something like an IDE has the happier I am but how does this work? It generates out test code for you, or what?


A unit testing framework and support therefore in an IDE basically allows you (the creator of a game or engine) to write unit tests, which are basically bits of code that call functions and such on objects (or, instances of a specific class). That way, you can put the expected behaviour of a class and its methods in stone (okay, code), so that each time you make an addition or adaptation to your code (or codebase), you can be semi-certain that all the previous features still work as expected. This is especially useful in a multi-user environment, or in a program with a large amount of code and classes. As a side effect, unit tests will also make you detect so-called 'code smells' easier - design flaws, basically, or unexpected or unpredictable behaviour.

Look up terms like 'unit tests' and 'test-driven development' up on Wikipedia, they have pretty good articles about the topic. I don't think unit testing is used a lot in the C++ world, but it's getting quite common in the Java world. I personally think that unit tests can be a valueable addition to software. In my previous assignment, a 20-week internship at a large insurance company, I was introduced to unit testing and at the end, I had written unit tests that covered about 45% of the code of my program - which is supposedly quite high.

I'd say that adding unit test support to VC++ is a good addition, as long as it's properly used and applied.

by jwatte » 20 Mar 2008, 12:56

Actually, "pure" unit tests don't concern themselves as much with the public API, as with the implementation. A "pure" unit test will be a friend of the class, and test various conditions like "if I'm in state A, and event B happens, I should transition to state C." It can test this by poking data straight into the instance of the class under test.

Testing the public API is more the realm of a functional test or acceptance test. If we're picky

However, given that functional tests exercise most of the code paths anyway (hopefully), then a good suite of functional tests can serve much the same purpose as a unit test when it comes to post-development validation. During development, however, you could write a unit test for each if() inside your code if you wanted -- maybe even before you write that if() statement.
