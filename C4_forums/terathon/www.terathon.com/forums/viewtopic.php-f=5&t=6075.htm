Re: Hardware skinning

by Eric Lengyel » 03 Dec 2008, 20:40

There are two things in progress for skinning now:

1) Hardware skinning in the vertex program with transform feedback to dynamic VBOs.

2) Multithreaded skinning on the CPU.

Depending on what CPU and GPU you have, the engine will choose one of these by default, and you'll be able to override it if you want.

Re: Hardware skinning

by Eric Lengyel » 08 Mar 2009, 19:48

rijkaard wrote:Does C4 support Hardware skinning?
If Not, will ever support it?

I am saying this because i am wondering if it's normal that in a scene with only 3 mid-poly characters ( about 4-5000 polys each ) textured and with dyn shadows enabled, the frame rate is 60 fps in debug and drops to 15 if character number raises to 10.

1) the scene geometry it's only a simple floor.
2) No physic thread involved in the performance, only rendering thread ( with physic enabled, however, performances are nearly the same... LOL )
3) Graphic card: ATI HD 2600 Pro XT

P.s: On the same card, and using same characters, a test program built by me, using Havok demo framework ( which supports HW skinning ) frame rate is 50-60 fps ( debug ) with 15 characters in the scene( the scene, again, it's only a simple floor ).


There are very good reasons why hardware skinning has not been implemented in C4:

1) C4 renders in multiple passes (ambient + n lights + motion blur if enabled). If hardware skinning were used, then each model would have to be re-skinned on every pass in which it were rendered. This would likely be slower than skinning on CPU and caching the result for all passes, especially on a graphics card like the Radeon 2600. However, if your hardware supports transform feedback, then the results can be saved in graphics memory for subsequent passes, but this only helps hardware that is already fast.

2) Hardware skinning can't be used with stencil shadows because the CPU needs the skinned mesh in order to calculate the shadow volume. If you use shadow mapping, then this problem goes away, but shadow mapping isn't available for all light types in C4 yet (it will be).

3) With hardware skinning, you will be limited to about 60 bones and no more than 4 weights per vertex. These limitations don't exist on the CPU.

rijkaard wrote:P.s: On the same card, and using same characters, a test program built by me, using Havok demo framework ( which supports HW skinning ) frame rate is 50-60 fps ( debug ) with 15 characters in the scene( the scene, again, it's only a simple floor ).


Were your characters casting shadows in your demo program? Were you recalculating normals and tangents as well as vertex positions so that bump mapping could be done? Did you render each character three times (motion blur pass, ambient pass, and lighting pass)? It's very likely that C4 was doing a lot more computation in order to enable more features, so this isn't even a remotely fair comparison.

Let me ask you some standard questions concerning the performance of your characters:

1) Are you running C4 in optimized mode? There's a big difference in skinning performance between debug and optimized.
2) How many bones does your character have?
3) How many levels of detail does your character have, and how many vertices does each level have?
4) How is the performance affected if you disable shadows for the character?

You'll be happy to know that CPU skinning is being made into a job manager task for the next release (version 1.6). This means that on an n-processor machine, n characters can be skinned simultaneously. (However, you probably won't see an n-fold performance increase due to memory bandwidth saturation.)
