He spawns when you have completed some objective in another world file and return to this one. Also, what if the NPC is in multiple world files?

So far what I've done is made a str table that stores an NPC's modelpath, and animation paths for basic things such as 'Stand', 'Walk', 'Run', and stores all the dialogue that the NPC can say and all the things that you can say to the NPC.


If you have him spawning you really don't want him in any world files at all, but to be dynamic.

In C4 you have a sort of MVC system, in fact it's actually called a model and a controller. The npc's mesh model which is controlled by the controller, which is called upon every frame to update the model.

Your player code, the code where you store stats and stuff should probably either own a controller or be a controller itself. If you don't have something like this, how are you even talking to the guy? How do you get what dialog he has to say?

So by dint of the fact you ARE talking to the guy, you must have access to his object in the dialog, and for things to work this NPC's object simply has to be able to look at its controller as well. The only thing a script could do is to communicate with the controller, it does the stuff. You can't just do a bunch of stuff in scripts like run to the closet because you are bound to the current frame. So to get anything done you are going to use controllers.

So instead of using the script just use it directly.

It's easy to get caught up using the scene graph, especially in C4 because it is very geared to the one true path in that respect as it were, but you really want to have your data driving the scene graph not the other way around. If everything is completely tied in to everything else it's going to be a huge mess, and eventually every time you upgrade the engine it's going to feel like a disaster.
