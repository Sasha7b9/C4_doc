None of this has disappeared, but sometimes things get renamed. We try to make upgrades as easy as possible under the condition that we like to improve the API by replacing things with non-optimal naming or functionality. Re: Flickering Marking Effect

by Eric Lengyel » 26 Jun 2014, 15:27

So for the markings, the engine uses a depth-offset technique to render them on the surfaces to which they're attached. As is the case in all engines, depth offset cannot work for all situations all the time without some tweaking. Right now, the engine chooses a random offset within a small range of values so that opaque markings applied to the same area tend not to fight each other, but that isn't perfect either. You can see where this happens in the MarkingEffect constructor where the markingDepthOffset gets initialized. Increasing the value here, and making it not randomized, will help your situation. We're going to expose this in the MarkingData structure in version 4.0 so that you don't need to change the engine source. Also, now that the stencil buffer is available for other uses, we're planning to use stencil IDs on opaque markings so that we no longer need the randomization at all.
