Deadlock in VertexBuffer update

by aubrey.r.jones » 25 Jul 2013, 10:16

I have a BatchJob which updates one of tentacles of my player character, and I split out each tentacle onto its own parallel batch job. (I do this because their update is extremely expensive.) This all worked just fine in C4v2.

In 3.0, debug drawing is causing what appears to be a deadlock. I have a debug drawing harness based off of this technique (http://www.terathon.com/wiki/index.php/ ... bug_Output). I have a function that looks like this:

Code: Select all
   C4::Renderable *r = NewRender(curLoopCloseRender, loopCloseRenders, C4::kRenderLineLoop);
   C4::VertexBuffer *vBuf = BufferFor(r);
   volatile B2DebugVertex *restrict vert = vBuf->BeginUpdateSync<B2DebugVertex>();
   for (int i = 0; i < vertexCount; i++){
      vert->position = convB2Point(vertices[i]);
      vert->color.Set(color.r, color.g, color.b, 1.0f);
      vert++;
   }
   vBuf->EndUpdateSync();
   r->SetVertexCount(vertexCount);
   AppendRender(r);


If I call that function from my BatchJob, then the Batch the job belongs to will never finish. Basically, in this code:

Code: Select all
   C4::Batch tentacleBatch;
   for (int i = 0; i < kTentacleCount; i++){
      TentacleUpdateJob *job = new TentacleUpdateJob(this, i);
      C4::TheJobMgr->SubmitJob(job, &tentacleBatch);
   }
   
   C4::TheJobMgr->FinishBatch(&tentacleBatch);


The program will hang forever at the FinishBatch call.

In C4v2, I didn't use the vertex buffers--instead, I just used attribute arrays. I'm pretty sure that the problem is that the BeginUpdateSync() and EndUpdateSync() are implemented as jobs, which aren't playing nice with my jobs. Any ideas on how I can fix this?

Re: Deadlock in VertexBuffer update

by Eric Lengyel » 25 Jul 2013, 15:45

Since all OpenGL calls have to be made from the main thread, there's a mechanism in the Graphics Manager that allows other threads to queue up calls that they need to have made on the main thread. This queue is serviced once per frame, so another thread has to wait while the main thread continues to advance until this point is reached. The mechanism is not intended to be used directly from jobs that must finish in lockstep with the main rendering loop, but from threads/jobs that run completely asynchronously, like a loading thread. You're seeing a deadlock because you're blocking the main thread, but the EndUpdateSync() function is waiting for the main thread to reach a certain point.

This doesn't mean that you can't fill vertex buffers in jobs. You can, and the engine does exactly this when it updates things like particle systems and skinned meshes. What you need to do is call BeginUpdate() from the main thread, then submit a job to fill the buffer, and finally call EndUpdate() from the job's finalization function. The BatchJob constructor takes a pointer to a finalization function as well as the job's main execution function. The finalization function is called on the main thread when you call FinishBatch(), so everything works out perfectly.

The C4Particles.cpp file contains a bunch of examples. Each type of particle system has a RenderParticles() function and a FinalizeParticles() function. The RenderParticles() function is called on the job thread, and the FinalizeParticles() function is called on the main thread from inside FinishBatch().
