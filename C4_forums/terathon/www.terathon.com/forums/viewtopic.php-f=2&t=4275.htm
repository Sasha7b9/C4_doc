Re: Build 146 Beta Now Available

by Eric Lengyel » 06 Feb 2008, 20:39

Jonathan wrote:Out of curiosity, it should be possible to apply full lighting on geometry set to render in the effect pass as well right? If it is, could you add a flag for it in the get info dialog in the editor, Eric?


This would be equivalent to not rendering the geometry in the effect pass. An object can either be rendered in the lighting passes or in the effects pass. Setting the "Render in effect pass" flag for a geometry moves it from the lighting passes to the effect pass. Lighting an effect does the reverse -- an effect is rendered in the lighting passes instead of the effect pass.

Re: Build 146 Beta Now Available

by Eric Lengyel » 07 Feb 2008, 00:15

jwatte wrote:What do you do if you want to light something that is translucent?


The only mechanism in the engine for doing this is using a remote portal to render into the refraction buffer and then applying a refractive material to an object. If translucent objects were rendered in the main buffer, they would need to write to the depth buffer to receive shadows, but that would obliterate the depth values for any objects behind them, which also need to receive shadows. It's a tough problem.

Re: Build 146 Beta Now Available

by jwatte » 07 Feb 2008, 00:30

It's a tough problem.


Agreed. A middle ground might be to allow translucent objects to receive lighting without stencil shadows. You could still use depth or projected shadows on them.

For windows, which clearly delineate "there" from "here," you can do it, though -- render everything on the other side of the window first, with a clipping plane at the window. Then render the window into the depth buffer, and make it receive shadows. Then render any effect hither of the window. You probably need to render reflection for the window, too. While this is not a general purpose solution, I believe that windows are an important enough special case to warrant a special solution.
