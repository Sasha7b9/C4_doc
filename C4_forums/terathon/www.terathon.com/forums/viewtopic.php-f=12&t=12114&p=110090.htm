Re: what i realy miss: sun/godrays and ambient occulsion

by jwatte » 11 Aug 2012, 12:49

C4 does static ambient occlusion in two ways.

First, it can bake surface-level ambient occlusion into a texture channel from your bump map. This is an option in the texture importer. You then need to actually use this in the shader you build for it to actually work.

Second, the world editor has an option to calculate ambient occlusion for geometry. This is a checkbox for geometry nodes in the world editor.

What it doesn't do, is ambient occlusion for moving objects.

Many engines try to do this in screen space. However, I don't personally like this very much, because it has pretty severe artifacts in many cases, such as when a vertical tree trunk or lamp post crosses the screen.

You can fake ambient occlusion in C4 by adding a not very strong landscape light that shines from straight up, and then make objects cast and receive shadow map shadows. This will create a shadow underneath each object, which is an approximation of the ambient occlusion from sky illumination you'll get in the outdoors. The shadow will likely have a little too much definition, so if there was a way to soften/blur this, that would probably help.

Finally, a source license for C4 is very cheap. A source license for Cry Engine is not. If you can afford the Cry Engine license, that might be a better option for you.

As I said: C4 already has support for two kinds of ambient occlusion: Geometry-based, and surface-based.
If you want to render ambient occlusion into your models (in 3ds Max or similar) and map that as a separate map, you can also build a shader for that.
If you want ambient occlusion, you can already have it. If you have actually done all that can be done with the current tools, and there is still some ambient occlusion effect you can't get, then please post screen shots and details.
