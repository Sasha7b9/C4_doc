Re: Gremlin Invasion: Survivor

by Eric Lengyel » 27 Apr 2012, 20:21

Jack wrote:While looking into the code what could cause those issues I think there is a problem when input device get lost in DirectInputDevice::ProcessEvents. The function ResetActions is called whitch calls also Action::End. Take a look at that.


This does not explain the problem for two reasons. First, the DIERR_INPUTLOST error is returned only under exceptional conditions, like the engine got switched to the background or the user unplugged the device. Second, when ResetActions() is called, it automatically makes End() calls on any actions that are currently active (e.g., because a button was still being pushed). When I see input get lost, the gun can be stuck in a firing state or the player can be stuck running in a certain direction, and this cannot happen if ResetActions() is called. Therefore, the DIERR_INPUTLOST or DIERR_NOTACQUIRED error is not being returned in these cases.
