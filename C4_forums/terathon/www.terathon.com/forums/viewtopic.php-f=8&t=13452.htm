Re: Transparent WorldViewportWidget?

by Eric Lengyel » 16 Jan 2014, 20:46

The viewport widget is doing the clearing automatically. What you need is a flag that would change the parameter passed to the first call to the SetGraphicsCamera() function inside the ViewportWidget::Render() function. Setting the parameter to false will just cause the viewport's world to simply be drawn on top of whatever is in the background.

Re: Transparent WorldViewportWidget?

by Eric Lengyel » 06 Feb 2014, 18:58

Cameron wrote:Just so I'm clear could you describe how kRenderTargetDisplay and kRenderTargetPrimary are used. It appears the game world is rendered into the kRenderTargetPrimary (as well as a few others) then the result is copied into kRenderTargetDisplay before the interface manager starts rendering into kRenderTargetDisplay.


Right, the world is rendered into the primary render target, and then the final post-processing phase uses that for input and writes the results to the display target. Then the GUI is rendered on top directly in the display target.

Cameron wrote:When a world viewport is rendered what causes it to display on screen without copying it into a texture and rendering the texture? Are the display and primary render targets somehow composited again?


Yes, an independent post-processing pass runs for the world in the viewport, and the output is restricted to the viewport's bounding rect.
