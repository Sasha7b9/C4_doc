Frank Skilton wrote:It's a good feature, pretty standard too. There definitely should be a way to assign control to a camera that follows a path, without the need to code, using only the editor. Super useful.

http://www.terathon.com/bugs/view.php?id=784


Thank you Frank. I made something similar in other engines without a path. I used an animation editor. It is a time line where I can add key frames. At each key frame I can store parameters of the selected object. So I can just move the camera to a new position, rotate it and store all this information at this frame. The positions between two key frames can be interpolated, maybe by curves or in a linear way. But curves just work better to have a smooth transition.
The advantage of something like this is: I can use it for everything else like flickering lights, changing particles, moving doors, platforms or changing colours, moving bones, ect.

But I agree, following a path would be a first, fast and easy solution that is enough for a simple and smooth walk through of a camera.

I improved this pack further to work perfectly in real game environments. So I made collision geometry like the following for all corridor models and props.



I did not "feel" any difference as I did my first check. But now I checked it with a profiler tool and I found this:



As you can see it reduces the usage of scripts for collision detection a lot, not just a tiny bit, it reduces it significantly. So there is more room for other scripts, rendering, effects, whatever.

So from what I see it is highly recommended to use extra lowpoly models only for collision detection like I did. Although I did this profiling in another engine, I can imagine it is somewhat similar in C4.

Re: New Sci-Fi Textures WIP Thread

by mwituni » 30 Aug 2010, 22:23

One issue here is the current LOD system does not allow lower LOD stages to have less nodes (meshes+textures) ... so a 1000 mesh model would still have 1000 nodes at it's lowest LOD - which can be used for collision.

That's not very efficient, as the model in the distance still has 1000 nodes/meshes and textures to load - when perhaps 20 could have been enough. Luckily textures have their own internal LOD which helps, but still not ideal.

I added a feature request ( http://www.terathon.com/bugs/view.php?id=771 ) in May to have the option of creating lower LOD's with less nodes and therefore less meshes and textures. So a 1000 mesh model at LOD00, may have 100 meshes at LOD01, and say 10 at LOD02 - which may be the meshes used for collision.

Eric Lengyel wrote:The most important thing is that you split the meshes into small parts for collision detection. For example, the floor, ceiling,each wall, each of those beams, each pipe, and each electrical box on the walls should be a separate collision mesh.

Very basic shapes like cubes and cylinders with minimum faces to 'approximate' the collision volumes would help. Also, consider the types of collision ... under 2m-3m there's character collision, but normally above that not ... so it may not be necessary to have many surfaces / details on the high walls and ceilings just to deflect bullets accurately etc.
