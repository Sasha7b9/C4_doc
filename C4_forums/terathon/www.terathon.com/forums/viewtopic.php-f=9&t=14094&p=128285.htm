In order to get it compile with the 2015 Max SDK:

simply had to comment out this line in MorphR3.h:
Code: Select all
      //RefResult NotifyRefChanged(Interval changeInt,RefTargetHandle hTarget, PartID& partID, RefMessage message);

Seems that NotifyRefChanged is now "sealed" - some newfangled feature in C++. This gets it to compile fine and I don't think it has any effect on the exporter.

I've looked at the exporter code that actually writes the normals and I have to say it looks sane:
Code: Select all
   const Face *triangle = mesh->faces;
   for (int i = 0; i < triangleCount; i++)
   {
      int k1 = triangle[i].v[0];
      int k2 = triangle[i].v[1];
      int k3 = triangle[i].v[2];

      const Point3& v1 = vertex[k1];
      const Point3& v2 = vertex[k2];
      const Point3& v3 = vertex[k3];

      Point3 n = (v2 - v1) ^ (v3 - v1);
      DWORD smooth = triangle[i].smGroup;

      vnormal[k1].AddNormal(n, smooth);
      vnormal[k2].AddNormal(n, smooth);
      vnormal[k3].AddNormal(n, smooth);
   }

   ExportVertex *ev = exportVertex;
   for (int i = 0; i < triangleCount; i++)
   {
      unsigned int k1 = triangle[i].v[0];
      unsigned int k2 = triangle[i].v[1];
      unsigned int k3 = triangle[i].v[2];

      ev[0].index = k1;
      ev[1].index = k2;
      ev[2].index = k3;

      ev[0].position = vertex[k1];
      ev[1].position = vertex[k2];
      ev[2].position = vertex[k3];

      DWORD smooth = triangle[i].smGroup;
      ev[0].normal = Normalize(vnormal[k1].GetNormal(smooth));
      ev[1].normal = Normalize(vnormal[k2].GetNormal(smooth));
      ev[2].normal = Normalize(vnormal[k3].GetNormal(smooth));

      ev += 3;
   }

Re: Hello! And some OpenGEX exporter questions

by princec » 09 Feb 2015, 05:34

So, I've discovered a bug in the way normals are calculated: they need to be normalised before they're added together:
Code: Select all
   const Face *triangle = mesh->faces;
   for (int i = 0; i < triangleCount; i++)
   {
      int k1 = triangle[i].v[0];
      int k2 = triangle[i].v[1];
      int k3 = triangle[i].v[2];

      const Point3& v1 = vertex[k1];
      const Point3& v2 = vertex[k2];
      const Point3& v3 = vertex[k3];

      Point3 n = (v2 - v1) ^ (v3 - v1);
      n = Normalize(n);
      DWORD smooth = triangle[i].smGroup;

      vnormal[k1].AddNormal(n, smooth);
      vnormal[k2].AddNormal(n, smooth);
      vnormal[k3].AddNormal(n, smooth);
   }


That fixes all the normal problems I'm afraid I don't know how to get you a 2014 Max version of the file so you'll have to trust me there!

Another couple of modifications I should need to make to the exporter are:
- to only export objects marked as renderable - we have helper gizmos in our models that shouldn't be a part of the export and it's a minor pain having to manually deselect them;
- to notice when we've manually specified normals and use those instead of recalculating them in the exporter. This technique isn't often used but we do use it on stuff like vegetation.

Just FYI: To compile for Max 2015, Instead of commenting out that line, you can also view the function description to see how to alter it. Basically:

Code: Select all
RefResult NotifyRefChanged(Interval changeInt,RefTargetHandle hTarget, PartID& partID, RefMessage message);


Becomes:
Code: Select all
RefResult NotifyRefChanged(Interval& changeInt,RefTargetHandle hTarget, PartID& partID, RefMessage message);
