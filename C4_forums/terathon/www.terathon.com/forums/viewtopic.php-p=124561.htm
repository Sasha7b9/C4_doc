The first development release of C4 Engine version 4.0 is now available to users of the Professional Edition. It can be found beneath the current final release on your account page.

Some preliminary release notes for this build can be found here:

http://www.terathon.com/wiki/index.php/ ... ersion_4.0

Re: C4 Engine 4.0 development release now available

by Eric Lengyel » 31 May 2014, 17:17

ca$per wrote:I've noticed that one of graphics settings has changed. There was "hight quality bump mapping" and now instead of that there is "ambient bump mapping". Can you give some details on this?


These are unrelated settings. High quality bump mapping is always enabled now, and basically just means that normals read from a texture are always renormalized in a shader. On some very old hardware, being able to turn this off made a performance difference, but not any more. Ambient bump mapping is the ability to consider per-pixel normal vectors when applying radiosity in the ambient lighting. This can make a large visual difference, but it does cost a bit more in the shader to use it.

ca$per wrote:And another question is will "unified ambient/infinite lighting" make it into release version of 4.0 ?


Yes, definitely.

by Eric Lengyel » 31 May 2014, 17:40

Jesse Meyer wrote:Issue: I can cause the barrels in the physics demo the twirl on their circular base indefinitely by launching a rocket at the bunch of objects.


Ah, the spin friction was not set properly for some of the barrels. For Barrel1-A through Barrel1-E, then spin friction should be 0.1, but it's 0.0 in the dev build.

Jesse Meyer wrote:I've also had boxes land on their edges and remain that way.


We've tested the hell out of the physics here, and I've never seen that. Is it something you can reproduce? It this happening with the stock assets?

Jesse Meyer wrote:The flashlight shadow map looks great, although it does dip performance quite a bit more than the stencil shadows.


There are a lot of factors that determine the difference in speed here. The flashlight now casts shadows for a lot more objects (e.g., stencil shadows were never cast for leaves), and the shadow maps are currently rendered at pretty high resolution. You are probably GPU limited now, where with stencil shadows, you might have been CPU limited.

Jesse Meyer wrote:I'm surprised by the amount of polyhedron code now added to the engine to figure out the new shadow mapping stuff.


Yes, there's quite a lot of new geometrical calculations to make things as efficient as possible.

Jesse Meyer wrote:Do you have any plans to implement specular reflections based on radiosity lighting? I know specular lighting isn't really being leveraged a lot in the 31st for some reason, but it is in scenes I operate with a ton. Relying on cubemaps for specular ambient lighting is a hassle, esp now seeing how far your radiosity solution is coming so quickly.


The radiosity spaces store information with an extremely low angular frequency, and it simply can't replace environment maps for any kind of specular reflection.
