How To best assemble a character

by DrVonBraun » 01 Jun 2013, 06:36

I am now reaching the point where I'm going to put clothes on my character models. I wont go into details here, but the general way I am doing this (and did in my old Ogre client) is to put the different cloths meshes on the character at runtime. They all have bone weights and morph information etc, so that's not a problem.

What I would like to ask is, are there any pitfalls I should avoid when assembling a rigged character with multiple textures/geometry objects? I will explain what I did in Ogre in order to minimize state changes during the render process.

I have one skin texture obviously for the character body which is 1024 pixels. All clothing textures are 512*512. I grouped 4 pieces of clothes together and created one texture of 1024 for the 4 clothes with their textures making up the 4 corners of the combined texture. Then I did that for up to 14 additional textures of this kind for a maximum total of 15*4 = 60 different clothes which the character could wear at the same time. These 15 textures and the body texture for a total of 16 were then combined into one batch that was sent to the DirectX renderer. Again, the purpose was to minimize state changes with multiple clothing textures per characters.

I don't assume I have to go through all that nitty gritty stuff with C4 and I dont even know if it's possible (or if it's possible if I wanted to do it) so my question is, do I need to worry about the number of state changes for characters that wear clothes made up of different textures? Is there anything I should optimize? Or should I just assemble the geometry objects, attach them to the skeleton node and dont worry?

Thanks

Re: How To best assemble a character

by Eric Lengyel » 01 Jun 2013, 23:55

If you have different variants of any one clothing item, like a bunch of different shirts the character can wear, then those are good candidates for using array textures. You can create an array texture by making a terrain palette that contains all of the clothing items for which only one is visible at a time. For example, you can put all the shirts in one palette and all the pants in another palette. You can choose which clothing item to use in the shader by specifying 3D texcoords for an ordinary texture map lookup (not the terrain texture lookup), where the third coordinate is the zero-based index into the palette. You can use the Merge 3D process to combine the 2D texcoords with a third parameter.

Re: How To best assemble a character

by Eric Lengyel » 02 Jun 2013, 04:07

DrVonBraun wrote:What is a safe texture size to use?


All DX10-class GPUs support textures of at least 4096x4096. That's everything manufactured since 2006.

Even if you were to use a texture larger than the maximum size supported by the hardware, C4 will simply drop the highest-resolution mipmaps to make it work with the current hardware. You won't break the engine or crash the graphics drivers by using a texture larger than what's supported by the GPU.

This may not address your particular concern but:
C4 should be able to handle a lot of different textures as materials on different modeIs.
I don't have any hard benchmarking data on the best ways to implement your system though.
We did some very simple benchmarking for how many models we could display at one time but we did not vary texture size or apply a unique texture for each "model".

So, the question that comes to my mind is are you gaining a benefit from combining the textures in this way?
I do wonder if it might be more work to implement than it is worth just to combine some textures that may not prove efficient if your system will not utilize custom shaders.

The power of the C4 Shader system is somewhat hidden because it is easy to get used to just adding directly to the material manager.
If there was one thing anyone should be doing it is taking advantage of custom shaders.
So, perhaps there is a benefit in using your approach with a custom shader that can utilize more of the engine's capability.
