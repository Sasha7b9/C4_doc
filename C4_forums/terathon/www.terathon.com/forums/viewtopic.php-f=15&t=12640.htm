Re: Character model hierarchy and animation issue

by mschifter » 11 Feb 2013, 17:54

It sounds like you are setting things up correctly, but let's be sure and take a look at both export and import steps...

If you are seeing no animation frames whatsoever, it's possible that the problem is in the export process.

First off, what I do is cut the animation frames down to the minimum -- that is, I dedicate an animation file for each animation to be played back. For example, Jack's exporter doesn't downselect animation frames to be exported based on the "action" editor -- it exports everything for the selected character.

When you export, be sure to select the "selected animation" instead of "selected objects" drop-down option (lower left) and drop your output into a subfolder of the import folder.

You should be able to open the model in the model viewer at this point, and click the import button and select your animation file.

Then select the animation that imported, and you should be able to playback.

That's the standard import process I used. Is anything here seem new to you?

Re: Character model hierarchy and animation issue

by mschifter » 21 Feb 2013, 10:19

OK Dalus,

I think I know what is plaguing you. Make sure that you have normalized the rigging, without which you will likely see distortion problems. If you set up your rigging using automatic weighting, this will go quickly. In object mode pick Object:Apply:Rotation Scale should normalize -- add :Location normalization off the same menu if you feel you need it.

Here's how to reapply rigging (the only valid way): Select the skeleton in Blender object mode. ALt-P in Blender to undo skeleton -- choose "clear and keep transformation." Shift-right-click the mesh then bones (you should be in Rest and X-ray Modes). The mesh should be dark orange outlined, and the bones light orange outlined. Then switch from object to Pose mode. The rigging should be completely highlighted in blue, and the mesh outlined in dark orange. Use CTRL-P to bring up the parentage selection dialog and pick with automatic weights. THIS is the only state you should be exporting from.

Export both a model and a sample animation, andd try it in the model viewer process again. This should clear the distortions.

by mschifter » 25 Feb 2013, 09:24

Hi Dalus,

I too had a higher number of frames importing than I started with, however that wasn't an issue for me.

If you only really have 1 frame of animation repeated 50 times, it's possible that not all the animation frames were selected before exporting using Jack's exporter. Use 'a' to select all the animation frames and of course select the model and skeleton. To select all the frames using 'a', open up the dopesheet and move the mouse over that window before typing 'a'. The diamonds up top, representing animation frames, will turn from white to orange. Ensure that during export, you pick "selected animation" and try it again.

With regards to the broken model add-ons, make sure you are in a t-pose at the time you normalize each add-on. So basically I'm saying you must have the armature in Rest Mode when setting up a normalized add-on. I recommend you do this with one selected add-on first just to get the procedure working.

Hopefully this is going to bring you improved results.

Okay, I think I finally get it now. I wanted to see if I could identify any sort of problem with the file export, so I re-imported it into Blender. It looked odd, but I could at least identify what looked to be the the main issue.

My soldier's armature consists of three different bone layers - deform, origin, and IK. IK influences origin, and origin influences deform. It was the simplest setup I could do, while retaining the complete range of motion that I needed for the character. The problem I saw from opening the COLLADA file in Blender, was that the IK bones were animating, but not the origin or deform bones. I already knew Blender used bone constraints to copy transforms from one bone to another, but I had assumed the animation keyframes were passed on to those bones as if it was their own.

I went around randomly searching online for anything pertaining to Blender's COLLADA exporter and animation that might alleviate this issue, and I found some posts talking about baking the action. As I stated previously, I had tried this before, but I think I was missing one key option. In the Bake Action menu, there's a check box for "clear constraints", which removes the constraints from the bones and relies on visual keyframing instead. I tried it, and I was finally able to view the animation from within C4. It's not perfect yet, but the entire walk cycle did at least import properly and plays correctly.
