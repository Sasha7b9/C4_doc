RPG Networking

by null72 » 18 May 2010, 12:46

Hello everyone, I have a few questions about networking that pertain to a MMORPG style game. Now I know that the general answer is "unless you have a huge team, don't bother" but I'm under the impression that if one guy can make an engine, 5 can make at least good progress on an MMORPG.

Now to questions about networking. My plan is to use the current C4 networking engine for client-server communications that involve persistance, I'm not sure how well it will handle it but I figure that modifications can be made to optimize it for my specific needs. Things that I can think of that need to be done via client-server are, characters, attributes for characters, items on characters, persisted locations and some of this would only be used on character loading. I guess my question is here, how well will the C4 networking engine handle these messages?

Now the more difficult task is the peer to peer commuications. I would like to create my own networking engine for this to fit my own needs, as daunting of a task as it may be. I'm hoping someone can give sight on who to send messages to and where. Meaning, if I have player A B C in zone X and players D E F in zone Y how easy would it be to create a system that only receives messages from players A B C while a player is in zone X. If I had seperate servers per zone to handle the amount of players, would I need seperate servers for each one; and would there need to be loading screens to handoff a player from one server to the next? How hard would it be to create an engine capable of rendering 50 players in a zone? From my logic it doesn't seem...impossible to accomplish this, it would just take some good restrictions (as annoying as it may be) and a good amount of servers to load balance. My concerns are creating a "boundry" if you will so that network messages arn't being received from across the entire map and having some sort of overlap on zones so that a player can see another player in a different zone if they're close enough.

My second option here if this doesn't pan out, is stick with a D2 style where 12 or so players can each join a game; though I'd much prefer the MMORPG style.

RedDwarf Server is free and handles persistance and messaging, although its scalability has yet to be proven. There are also commercial products available, including SmartFoxServer and NetDog.

Yeah I wrote a replacement message manager for C4 using NetDog when I worked on Divergence. NetDog has some nice functionality but you'll find that a lot of data ends up being duplicated as NetDog likes to keep it's own copy of objects that require networking, C4 obviously also needs a copy. As a result integrating into C4 isn't as straight-forward as if you'd built an engine around NetDog. To be honest I found little functionality in NetDog that was better than C4's in-built networking. NetDog has the potential to handle a lot of stuff for you but integrating it in C4 requires you to partially re-create that very functionality, in which case you may as well just use C4's networking.
