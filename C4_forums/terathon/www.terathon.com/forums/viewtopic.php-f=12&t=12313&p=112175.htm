Re: General questions

by Eric Lengyel » 26 Oct 2012, 22:45

migizi wrote:2. What version of OpenGL is being used? I've searched but I can't find what version it targets or if you can tell it to target a specific version.


C4 does not target a specific version of OpenGL. There are a lot of drivers out there supporting a mixture of features that don't really correspond to a particular version number, so C4 just requires a very basic OpenGL version plus a list of specific extensions. You can find that list of requirements on this page:

http://www.terathon.com/wiki/index.php/FAQ

migizi wrote:3. I'm an avid Linux user and want to know how the Linux support has been since it was introduced.


All core engine features are fully supported under Linux. All of the tools that ship with C4 are fully supported under Linux. There are a couple external plugins that are not supported, as noted on the Features page. The engine ships with generic makefiles and NetBeans projects for Linux development, and these are kept up to date.

migizi wrote:4. Are the OpenGL calls used in the engine actual OpenGL calls or engine specific calls that wrap around OpenGL calls?


The engine calls directly into OpenGL. You, as the game programmer, would not touch OpenGL at all because the engine isolates the game code from any platform-specific details. We could get rid of OpenGL altogether and reimplement all of the graphics using DirectX, and your game code wouldn't change in the slightest bit.

migizi wrote:5. How large is the dev team that works on C4? I don't want to move to an engine that will become unsupported.


I am the only programmer who works on C4 (but we have other people working on our game, The 31st). I have been working on this engine for 13 years, and I am not going to abandon it. C4 will not become unsupported.

migizi wrote:6. How easy is it to learn or pick up? I love C++ and have been teaching/reading about making game engines and using OpenGL.


I'll let the community answer that one.

migizi wrote:7. If I make the plunge should I get the book or will I learn what I need from online guides?


It depends on you. The book has a lot of useful information in it, and if you prefer step-by-step guides that show you how to accomplish something, you'll love it. If you prefer plain reference materials instead, then the wiki and API documentation might suit you just fine. You always have the option of asking questions here on the forums, and there are extra sections that become visible when you have a license. You'll find that the community is very good at providing helpful and fast responses.

Hey,

Unity and C4 both have their advantages and disadvantages which ultimately depend on what you're attempting to accomplish. I tend to use Unity to prototype ideas quickly (I'm not a very fast C++ programmer so Unity's scripting system is a benefit in that regard though C4's scripting system is arguably more robust and faster at run-time), and eventually port what works to C4. by Eric Lengyel » 27 Oct 2012, 18:27

C4 makes heavy use of inheritance and is strongly OO in many ways. I think what Grognard means is that the engine doesn't go crazy with a lot of the unnecessary OO design patterns used elsewhere, like overusing templates and wrapper classes. We prefer to structure things in a way that feels natural and make things only as complex as necessary.

You can find a small glimpse of what programming for C4 feels like by examining the source code for the SimpleBall and SimpleChar tutorial projects here:

http://www.terathon.com/wiki/index.php/SimpleBall

http://www.terathon.com/wiki/index.php/SimpleChar
