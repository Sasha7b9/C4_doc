Re: New Sci-Fi Textures WIP Thread

by MachineryFrank » 23 Feb 2011, 04:11

I just want to update this thread.

I continue my work and researches all the time and here are some interesting findings:

I played with light mapping in different engines, C4 among them, as you can see from the attached images. I have best experiences with directional light-mapping (some call it radiosity normal mapping). It allows to have spec and bump effects even from many baked static lights. But a mixture of real-time lighting and a light-map that contains only indirect lighting can also work. Unfortunately I am not experienced enough to create a good C4 shader for that. My experiments did not look very good. That is why I attached only an unlit image.

But here is an interesting finding I made in terms of C4 work-flow: Some of you might remember that there is a problem with mirrored geometry in C4. UV vertices of some polygons are connected and cause lighting problems. While preparing meshes for light-mapping I found a way to identify these spots easily:

When I create non-overlapping uv map for light-mapping I use a packing function in Modo. This function moves, scales and rotates uv-patches in a way,that they are all laid out without overlapping, with good proportions and without wasting space. But the parts that are connected still overlay each other and are coloured in red. So I can select them and move the mirrored parts. This splits the vertices on the problematic edges.

By the way: I made a bigger game map to test scene management, lightmapping and realtime lighting with a bunch of connected corridors. You can find more details, images and the content here. It also contains a folder with DAE files tested in C4:
http://www.dexsoft-games.com/models/sci ... s_map.html

Next time I plan to use C4 a bit more for my presentations.

Re: New Sci-Fi Textures WIP Thread

by MachineryFrank » 25 May 2012, 09:18

I also don't see a problem to get a light-map working. But especially in a sci-fi environment it needs some convincing bump and spec effects. A good mechanism for that is a bit more complicated than creating a new shader. Directional light-mapping as an example reads lighting directions as well as light intensity data from textures and can create some convincing spec and bumps effects only from light-map data. Also a volumetric (voxel-like) data tree is needed to illuminated dynamic moving objects from static lighting data.

But the advantage is that you will have indirect lighting (global illumination), soft shadows and just more realistic looking scenes in the end.
