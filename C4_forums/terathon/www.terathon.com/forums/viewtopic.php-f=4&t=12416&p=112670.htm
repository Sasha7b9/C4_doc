Working with and maintaining multiple external plugins

by cboyce » 01 Dec 2012, 17:50

I have a main project I'm working on which is all under version control. There are several plugins that I want to use, some that I maintain (and thus have in their own source control tree) and others that I don't (from contributors on the board). Is there any sane way to keep the code separated while working on the main project? I was thinking of having the plugin code and solution in its own separate directory (outside the main C4 dir). This would mean I'd have to update the paths in that plugins' solution so that it looked for code in the right place, and copied the binaries correctly, but in theory it seems like it would work. The only downside is that solution would have my main project path hard-coded, so it'd be harder to share that plugin. Also, there are the files in the Data and Import directory. I was playing with some sort of hard link solution, so that from a plugin's source control view, it saw only it's own resources and code, but the resources were then linked into the main project, so it had access to everything. Has anyone had to come up with a similar solution?

Re: Working with and maintaining multiple external plugins

by a2k » 01 Dec 2012, 19:38

cboyce wrote:Has anyone had to come up with a similar solution?


Yes.

Whereas I have my C4 stock solutions and projects in:
Code: Select all
a2k/C4/VisualStudio2010, and a2k/C4/EngineCode, a2k/C4/GameCode, etc


I contain my project code in a different directory
Code: Select all
a2k/projects/Game1, a2k/projects/Game3, etc


And although I don't write many plugins, I have mine in
Code: Select all
a2k/projects/_SANDBOX/C4/RecastNav, a2k/projects/_SANDBOX/C4/SGNav, a2k/projects/_SANDBOX/C4/CombatRTS, etc


I also have a common library where I put code that I share among all my projects in
Code: Select all
a2k/projects/common/Lib_C4Common


And lastly, I have an external library for putting code that I have acquired rather than written myself
Code: Select all
a2k/projects/external


I typically group source code into the respective project directory. Any solution, then simply draws in the required libraries by specifying any additional include and library directories for the main project in a solution (specified relatively, not absolutely).

All of this is under source control under their specific paths, obviously with "a2k" as the source root.

Now, the Data and Import directories are also under source control, but not directly in the a2k\C4 path.
Although on the client computer, those directories map to a2k\C4\Data and a2k\C4\Import, they are mapped to their respective projects in source control. An example mapping of this would look like this in Perforce:

Code: Select all
   //depot/projects/game1/art/Data/... //<client>/c4/Data/game1/...
   //depot/projects/game1/art/Import/... //<client>/c4/Import/game1/...

This way, I don't have massive amounts of data in the a2k\C4 tree for all the projects, but rather have each asset group stored in the respective project tree.
