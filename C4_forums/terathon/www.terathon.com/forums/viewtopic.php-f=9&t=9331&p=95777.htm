Bleh... I was in a pretty bad mood last night when I wrote this, so I apologize. A lot of the problems with that tool stem from a generalized problem with picking in the World Editor. It is very hard to work around the geometry in your scene because of the way C4 picks "closest" to the camera. This leads to a lot of clicking trying to get to the object you want, and then toggling masks to try to eliminate what you don't want to select. If the object you want to select is hidden by another object of the same kind, the masks don't work and you have to start doing a bunch of hiding.

I think it would be better if an object wasn't considered "closest" if none of the verts that make up the object are visible in the viewport. In otherwords, if you zoom in close enough to the object you really want to select, the verts for other objects "on top of them" would be out of the viewport and thus the blocking object would not be picked.

Sorry for the negativity. Selecting is sometimes very, very frustrating... feeling like it takes 10 clicks to select the geometry I really want to work with. The more developed the scene, the worse the problem gets. For outside environments, I guess this isn't as much of a problem. But inside closed rooms, it is murder.

by TheRhinoDude » 17 Jun 2010, 19:26

For most of the commonly invoke UI interactions, everybody will have their favorite solution that leads to maximum personal productivity, and it is important if possible to cater to most of them through bindings, as this will lead to the most overall productivity.

Unfortunately, it's the most complex solution to build, and a PITA to maintain, and it clearly adds a new layer of complexity to dealing with UI-related support incidents. In short, it's the kind of feature that could eat up a lot of the working day, despite how nice it is.

But once you have this, you can easily build a "select-a-binding" settings file feature, so that the community and make and share binding templates that mirror their favorite applications (Maya bindings, 3DS bindings, etc.), and users can easily select between multiple bindings, and even use different bindings for different workflow scenarios with a way to quickly switch between them via drop-down in the toolbar.

This feature would be a huge selling point among developres who care about their productivity, and I can see it used heavily. Over time Terathon could choose to support a few "official" bindings, within reason. Having the ability to save your bindings to a single template file also allows you to minimize the impact of the support incident issue. When submitting a UI bug, people would either state the official binding they are using, or post their binding settings file.

Not suprisingly, the features that are the big wins are the ones that take a lot of time. This feature would add a ton of polish, I think it would be quite welcome, but it sure would be a lot of work over time...

The logical time to add this type of support would be as part of 2.1 since that's all about the new GUI system, or at least it would ideally need to be taken into account during all of the UI redesign work that is going into 2.1.

Re: Paths and curved geometry

by Javier Moya » 22 Jun 2010, 06:06

One thing that may help is to implement something similar to the 3DS Max snapping tool behavior. This tool allows you to make transformations precisely using multiple elements (grid, mesh sub-objects...). It has a value called 'Snap radius'. You can type here a number of pixels which is the radius of an area around the element you want to work with, the grid for example. When the cursor is in that area, it moves automatically to the closest appropiate element. And as it is in pixels, it doesn't matter what level of zoom we have.
Another thing that may help is to lock the path with the lock tool (ctrl+k) but leaving the handles free. This way, if you want to modify the handles, don't loose the selection, and if you want to move the path just use the transform gizmo (the colored arrows I mean).

And speaking about the level editor, remember that we have the 'Selection Mask' and 'Visibility' tools, which are a great general filter. We can select any group and hide their elements (ctrl+down, ctrl+h), including terrains. The same can be done with zones. We can make temporary groups just for keeping the thing well organized. And you can select objects with the same material too. For precise selections I use the perspective viewport.

Hope it helps.
