by JustSid » 05 May 2012, 17:35

Grognard wrote:Don't have to go that far, just google andrew tannenbaum linux kernel for the thoughts of torvalds's teacher. The basic design is flawed, and basically just because.

Tanenbaum wasn't right either. At that time it really looked like Microkernels were the future because they had some serious advantages, but as it turns out doing userspace/kernel context switches is really expensive and a Microkernel requires, by design, A LOT of them. Its not like there weren't tries to build a great Microkernel, with Mach probably being the most prominent, but they turned out to be way too slow for real world usage.
But its not like a big fat monolithic kernel is the solution either, mostly because their size and the requirement to have anything and everything hardware related in the kernel. They are much harder to debug and if one part fails, chances are that the whole kernel panics instead of one module just crashing.

Modern kernel design resolves around building hybrids out of the two models trying to combine the most advantages of both worlds into one kernel.

Edit: I'm not sure if Tanenbaum was really Linus teacher, as far as I remember he told Linus in the usenet discussion about Linux that if Linus was his student he would give him a bad grade. Not sure about that though (and too lazy to read it all over again)

Re: Linux support coming in next release

by Eric Lengyel » 12 May 2012, 05:13

Once you have Linux installed and the standard libraries set up, you can build C4 and all games/tools by typing this into a command console while in the <C4>/Linux/ directory:

Code: Select all
make


Or for the optimized build:

Code: Select all
make optimized


Instructions for installing various libraries with the "sudo apt-get install" command are widely available on the internet. You'll need X11, Xrandr, and ALSA.

You may need to modify the include directories in the Include.mk file if you're running a version of gcc different from 4.6.1.
