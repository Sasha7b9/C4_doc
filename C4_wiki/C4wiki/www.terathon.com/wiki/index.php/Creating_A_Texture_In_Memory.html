Creating A Texture In Memory

From C4 Engine Wiki

Jump to: navigation, search

In order to create a texture in RAM you need two parts, a texture header, that tells C4 how to assemble the texture and a chunk of memory with the pixel data. Let's define the header first.

Defining The Texture Header

The texture header defines how your pixel data are organized and what sort of texture C4 should generate from it. Here is an example: 

C4::TextureHeader				*ps_texture_header	= new C4::TextureHeader;
U32								*pau32_image_data;
 
ps_texture_header->textureType				= C4::kTexture2D;
ps_texture_header->textureFlags				= 0;
ps_texture_header->colorSemantic			= C4::kTextureSemanticDiffuse;
ps_texture_header->alphaSemantic			= C4::kTextureSemanticTransparency;
ps_texture_header->imageFormat				= C4::kTextureRGBA8;
ps_texture_header->imageWidth				= D06ANIM_DECORATION_TEXTURE_SIZE;
ps_texture_header->imageHeight				= D06ANIM_DECORATION_TEXTURE_SIZE;
ps_texture_header->imageDepth				= 1;
ps_texture_header->wrapMode[0]				= C4::kTextureClamp;
ps_texture_header->wrapMode[1]				= C4::kTextureClamp;
ps_texture_header->wrapMode[2]				= C4::kTextureClamp;
ps_texture_header->mipmapCount				= 1;
ps_texture_header->mipmapDataOffset			= 0;
ps_texture_header->auxiliaryDataSize		= 0;
ps_texture_header->auxiliaryDataOffset		= 0;

You can check the various flags in the C4 source code. Here I am creating a texture that is used as a diffuse texture (kTextureSemanticDiffuse) as opposed to a emission map for instance, that contains transparency in the alpha channel (kTextureSemanticTransparency) and that uses a 32-bit RGBA format (kTextureRGBA8), meaning that the Alpha channel is in the highest 8 bits.

Since I have no mipmaps, the mipmapCount field is set to 1. I haven't actually done any manual texture with mipmaps so I cant say how those would have to be organized in RAM.

Instead if kTextureClamp you could also use kTextureRepeat or any of the other texture coordinate flags, check the source code for a list of valid flags.


The Texture Pixel Data

There is not much to say here except that your data must be a rectangular array of pixel where each pixel is in the order given by the imageFormat flag in the header, for instance kTextureRGBA8. The texture must be oriented row by row. Beware that under some circumstances you may have to assemble bottom up, depending on your source format, if you read in an external file, for instance BMP pics are oriented bottom up.


Assembling The Texture

The final step is to instruct C4 to create a texture like so: 

C4::Texture *pc_decorative_texture = C4::Texture::Get(ps_texture_header, pau32_image_data);

With the respective pointers to the texture header and the image data, and you have a texture that you can use as if it were loaded from the C4 resource system.


Final Thoughts And Cleanup

Now, the question remains what to do with the texture header and the image data and I discussed it in this forum thread that you should read: [1]

In my application I have no problems so far deleting both data like this: 

delete[] pau32_image_data;
delete ps_texture_header;

but according to that forum post above you shouldn't do this in case the basic rendering parameters change like the screen size and other global parameters. In that case C4 might need access to the data to assemble the texture again. If you don't allow this, then it should be OK to delete the data. However if you run into inexplicable crashes when the screen parameters are changed or in general the texture seems to be missing, you might want to think about a solution here.

If your texture is a permanent one or you control the geometry object that uses it and it's lifetime and know when the object is deleted etc, you may be OK with deleting the raw data, otherwise you have to keep it in RAM and probably wont be able to delete it as long as there is a possibility that the texture could be used.
