Figure 1. The Physics Page contains tools for creating several types of physics-related nodes in a world.

The Physics Page is a tool page in the World Editor that can be found under the Object tab.

As shown in Figure 1, the Physics Page contains tools for creating several types of physics-related nodes in a world. These are summarized in the following list:

  • A physics node enables the physics simulation, and exactly one of these nodes needs to be present in any world that uses the built-in physics functionality.
  • A physics space defines the boundary for the physics simulation. Special action is taken whenever any rigid body leaves the volume that it encloses.
  • Shapes define the volumes of rigid bodies controlled by the physics simulation.
  • Joints connect rigid bodies to each other or to the static environment in specific ways.
  • Force fields define volumes inside which rigid bodies experience certain forces.
  • Blockers specify volumes of space that rope and cloth objects are prohibited from entering.


Physics Node

Placing a physics node in a world tells the C4 Engine to use its own built-in physics simulation in that world. If a physics node is not present, then no built-in physics simulation is run by the engine, and any rigid bodies in the world will not move. If you are using an external physics library, then leaving the physics node out of your worlds effectively disables the built-in physics functionality in C4. (When the C4 physics simulation is disabled, it has zero performance cost.)

A single physics node should be placed in the infinite zone of any world for which the built-in physics simulation should be enabled. This is done by selecting the physics node tool in the Physics Page and clicking in the scene with the infinite zone set as the target zone. The physics node can also be placed in the infinite zone by selecting the physics node tool and then clicking on the infinite zone node in the scene graph viewport.

A physics controller is automatically assigned to the physics node, and this should not be changed. The physics controller holds global simulation settings that can be accessed in the Node Info window. Currently, the only global setting is the acceleration of gravity, and its default value is 9.8 m/s2.

Physics Space

A physics space may be added to a world in order to specify the absolute boundary for the physics simulation. If a rigid body ever leaves the volume enclosed by the physics space (as determined by its node position), then the Physics Manager calls the rigid body's HandlePhysicsSpaceExit() function. This function can be overridden by subclasses of the RigidBodyController class to take whatever special action is necessary. The default implementation calls the HandlePhysicsSpaceExit function for the current World object, and its default implementation simply deletes the rigid body.

A physics space is useful for removing objects from the world once they've gone outside the playing area so they no longer use processing time. For example, if a box is blown far off the level by an explosion, then it should be deleted once it falls below the horizon and can no longer be seen by the player. A physics space typically extends very high above the playing area and very far beyond the sides of the playing area so that objects don't abruptly disappear from view. The bottom side of a physics space is typically closer to the lowest point in the playing area since the disappearance of objects there won't normally be visible.

After a physics space has been added to a world, the physics node needs to be connected to it before it will have any effect. To do this, add the built-in %Physics connector to the physics node and then connect it to the physics space.

Shapes

A physics object is created by assigning a rigid body controller to a node and creating one or more shapes as subnodes of that node. The shapes define the volume occupied by the physics object as seen by the physics simulation, and they are always fixed relative to each other within a single object. Each shape can have a different density, and the engine automatically calculates properties such as the center of mass and the inertia tensor.

Shape nodes are created by selecting one of the available shapes in the Physics Page and drawing it in the scene. Each shape should be dragged the scene graph viewport to be made a subnode of the node to which the rigid body controller is assigned.

The shape density is specified in the Node Info window. The density is measured in units of kg/dm3 (kilograms per cubic decimeter), which is equivalent to Mg/m3 (metric tons per cubic meter). The density setting displays the volume in m3, so the density for a given mass in kilograms can be determined by dividing the mass by 1000 and then dividing by the volume.

Joints

Rigid bodies can be connected to each other or to the static environment by using joint nodes. Each joint node has two connectors called %Body1 and %Body2, and these should be connected to the rigid bodies that are to be joined. If only one rigid body is connected, then the joint is static, meaning that it attaches the rigid body to the static environment. Otherwise, the joint attaches two rigid bodies together.

For those types of joints that have an axis of rotation (such as the revolute joint), rotation is allowed about the joint's local z axis. This is represented by the blue arrow shown on the gizmo in the World Editor.

Force fields

A field node represents a volume inside of which a force can be applied to physics objects. Forces are applied to objects in a field through the extensible Force class. After a field has been created in the World Editor, a force can be assigned to that field in the Node Info window.

There are three forces built into the engine, a gravity force, a fluid force, and a wind force.

  • The gravity force exerts a downward pull relative to the field orientation (where down is the negative z direction). This force is applied in addition to the global gravity specified in the settings for the physics controller.
  • The fluid force applies buoyancy and drag, and it can be configured to simulate a current.
  • The wind force applies air drag for a wind current.

Custom forces can be defined by creating subclasses of Force and registering them with the engine.
