Creating A Skinned Mesh Manually

From C4 Engine Wiki

Jump to: navigation, search

One of the most important tasks for many users to create a mesh manually, load a skeleton from disk and attach the mesh to it so that it can be animated. This is because the creation of customized meshes on the fly, as opposed to loading a pre edited model, can be useful when morphing a character or altering it completely. To do this it is necessary to assemble the geometry information in ram and also the skeleton information, if the mesh is to be rigged on a skeleton as done in this tutorial. This example however assumes that the skeleton comes from a .mdl file from disk. This is reasonable because in most cases skeletons will not be altered on the fly (where would the necessary animations come from after all)

This HOWTO does NOT include the necessary data objects. It is more a theoretical tutorial than one you can copy and run, but I tried out the code and it works well here (C4 version 2.9.1). You can easily add the missing data yourself. All you need is an empty world you create in the World Editor, a skeleton in a .mdl file and an animation made for that same skeleton in an .anm file. The skeleton must be edited in the world editor in such a way, that the rootbone in the skeleton hierarchy is directly under the infinite zone node and there are NO other nodes parallel to the bone root node, especially no mesh nodes, and no parallel bone nodes like for example from a IK solver in 3DS or anything like that. Everything else is in the code.

The code consists of some code I took from other tutorials mainly the stubs for controller, world camera and the application main class. Also, I simplified the design so that everything happens in the application constructor. This is for demonstration purposes after all and my main concern was to keep the code simple, not to show how use all the C4 design constructs like controllers correctly. The interesting part happens in the second half of the CPP file, everything else is mostly standard setup for the C4 engine.

That said, I think the comments in the code speak for themselves and explain everything sufficiently, at least I hope :) I also don't follow the C4 coding guidelines, so nevermind my coding style please. It's old fashioned Hungarian Notation like stuff since I'm and old time Microsoft guy :P You can basically take the simple HelloWorld Tutorial and modify it to create a simple working project and then replace the .H and .CPP files with these

SpinController::SpinController() : Controller(kControllerSpin)
{
    // Set a default value for the spin rate of one revolution per 10 seconds. I believe the "rate"
    // is basically how many radians to rotate per millisecond
    spinRate = (K::two_pi / 1000.0F) * 0.1f;
    spinAngle = 0.0F;
}
 
SpinController::SpinController(float rate) : Controller(kControllerSpin)
{
    spinRate = rate;
    spinAngle = 0.0F;
}
 
SpinController::~SpinController()
{
}


void SpinController::Pack(Packer& data, unsigned_int32 packFlags) const
{
    Controller::Pack(data, packFlags);
 
    // Write the spin rate
    data << spinRate;
 
    // Write the current angle
    data << spinAngle;
 
    // Write the original transform
    data << originalTransform;
}
 
void SpinController::Unpack(Unpacker& data, unsigned_int32 unpackFlags)
{
    Controller::Unpack(data, unpackFlags);
 
    // Read the spin rate
    data >> spinRate;
 
    // Read the current angle
    data >> spinAngle;
 
    // Read the original transform
    data >> originalTransform;
}


void SpinController::Preprocess(void)
{
    Controller::Preprocess();
 
    // Grab the original transform of the target node
    const Node *target = GetTargetNode();
    originalTransform = target->GetNodeTransform();
 
    // Set the kGeometryDynamic flag for any geometry nodes
    const Node *node = target;
    do
    {
        if (node->GetNodeType() == kNodeGeometry)
        {
            // Node is a geometry, so grab its object
            GeometryObject *object = static_cast<const Geometry *>(node)->GetObject();
 
            // Set the kGeometryDynamic flag
            object->SetGeometryFlags(object->GetGeometryFlags() | kGeometryDynamic);
        }
 
        // Iterate through entire subtree
        node = target->GetNextNode(node);
    } while (node);
}



void SpinController::Move(void)
{
    Matrix3D    rotator;
 
    // Calculate the new spin angle based on how much time has passed
    float angle = spinAngle + spinRate * TheTimeMgr->GetFloatDeltaTime();
 
    // Make sure it's in the [-pi, pi] range
    if (angle > K::pi) angle -= K::two_pi;
    else if (angle < -K::pi) angle += K::two_pi;
 
    spinAngle = angle;
 
    // Now make a 3x3 rotation matrix
    rotator.SetRotationAboutZ(angle);
 
    // We'll rotate about the center of the target node's bounding sphere
    Node *target = GetTargetNode();
    const Point3D& worldCenter = target->GetBoundingSphere()->GetCenter();
    Point3D objectCenter = target->GetInverseWorldTransform() * worldCenter; 
 
    // Make a 3x4 transform that rotates about the center point
    Transform4D transform(rotator, objectCenter - rotator * objectCenter);
 
    // Apply the rotation transform to the original transform and
    // assign it to the node as its new transform
    target->SetNodeTransform(originalTransform * transform);
 
    // Invalidate the target node so that it gets updated properly
    target->Invalidate();
}


int32 SpinController::GetSettingCount(void) const
{
    // There's only one setting
    return (1);
}
 
Setting *SpinController::GetSetting(int32 index) const
{
    // Is it asking for the first setting?
    if (index == 0)
    {
        // Yes, return a new text setting and set its value in revolutions per second
        return (new TextSetting('rate', Text::FloatToString(spinRate * 1000.0F / K::two_pi),
            "Spin rate", 7, &EditTextWidget::FloatNumberFilter));
    }
 
    return (nullptr);
}
 
void SpinController::SetSetting(const Setting *setting)
{
    // Are we setting the spin rate?
    if (setting->GetSettingIdentifier() == 'rate')
    {
        // Yes, grab the value from the setting and convert it back to radians per millisecond
        const char *text = static_cast<const TextSetting *>(setting)->GetText();
        spinRate = Text::StringToFloat(text) * K::two_pi / 1000.0F;
    }
}

    spinAngle = 0.0F;
}

bool TestController::ValidNode(const Node *node) 
{ 
	// This function is called by the engine to determine whether
	// this particular type of controller can control the particular
	// node passed in through the node parameter. This function should
	// return true if it can control the node, and otherwise it should 
	// return false. In this case, the controller can only be applied
	// to model nodes. 
	 
	return (node->GetNodeType() == kNodeModel); 
}

void TestController::Preprocess(void)
{
	// This function is called once before the target node is ever 
	// rendered or moved. The base class Preprocess() function should
	// always be called first, and then the subclass can do whatever
	// preprocessing it needs to do. In this case, we set the ball's
	// coefficient of restitution.
	
	RigidBodyController::Preprocess();

	SetRestitutionCoefficient(0.95F);
	SetLinearVelocity(Math::RandomUnitVector() * 2.0F);
}

	  WeightedVertex				*aps_weight_table[3];


	  aps_weight_table[0]					= new WeightedVertex;
	  aps_weight_table[0]->boneCount			= 1;
	  aps_weight_table[0]->boneWeight[0].boneIndex		= 0; 
	  aps_weight_table[0]->boneWeight[0].weight		= 1.0f;

	  aps_weight_table[1]					= new WeightedVertex;
	  aps_weight_table[1]->boneCount			= 1;
	  aps_weight_table[1]->boneWeight[0].boneIndex		= 1; 
	  aps_weight_table[1]->boneWeight[0].weight		= 1.0f;

	  aps_weight_table[2]					= new WeightedVertex;
	  aps_weight_table[2]->boneCount			= 1;
	  aps_weight_table[2]->boneWeight[0].boneIndex		= 2; 
	  aps_weight_table[2]->boneWeight[0].weight		= 1.0f;


	  s_skinData.weightDataTable				= aps_weight_table; 



	  // --- patric ----
	  // ----------------------------------------------------------------------------------------------------------------------------------------------------------------
	  // Fill in the hash values for each bone. The hashvalue is a quick way of comparing bone names instead of using a full string compare. The order in which
	  // we access the bones to acquire their hash values must be the same order we use to index bones in aps_weight_table[x]->boneWeight[y].boneIndex
	  // ----------------------------------------------------------------------------------------------------------------------------------------------------------------
	  unsigned_int32	*pau32_hash_values;
          int                   s32_index;

	  pau32_hash_values	= (unsigned_int32 *) s_skinData.nodeHashArray;
          for( s32_index = 0; s32_index < s_skinData.boneCount; s32_index ++ )
               pau32_hash_values[s32_index]	= mpc_animated_skeleton->GetAnimatedNodeTable()[s32_index]->GetNodeHash();



	  // --- patric ----
	  // ----------------------------------------------------------------------------------------------------------------------------------------------------------------
	  // Fill in the inverse transformation matrices. Thankfully the bones provide these :)
	  // The model should consist only of bones but in case there are other nodes attached, we make sure we can cast to the Bone class before we do it. Actually I 
	  // believe we would run into trouble here if there were any non bone nodes since that would cause a gap in the array but since in my particular case I can 
	  // guarantee that a model will only contain bones when it is loaded, I didn't research this potential problem
	  // ----------------------------------------------------------------------------------------------------------------------------------------------------------------
	  Transform4D			*pau32_inverse_bind_transform_array;

          pau32_inverse_bind_transform_array	= (Transform4D *) s_skinData.inverseBindTransformArray;
          for( s32_index = 0; s32_index < s_skinData.boneCount; s32_index ++ )
          {
		  if( mpc_animated_skeleton->GetAnimatedNodeTable()[s32_index]->GetNodeType() == kNodeBone )
		  {
			  pau32_inverse_bind_transform_array[s32_index]	= Inverse( ((Bone *)mpc_animated_skeleton->GetAnimatedNodeTable()[s32_index])->GetModelTransform() );
		  } // if
          }









	  // --- patric ----
	  // ################################################################################################################################################################
	  // Create the mesh node which creates the associated geometry at all LODs. We have only one LOD here.
	  // ################################################################################################################################################################

	  // --- patric ----
	  // ----------------------------------------------------------------------------------------------------------------------------------------------------------------
	  // Create the mesh geometry node and add it to the model.
	  // The constructor allows for the construction of MeshGeometryObjects with multiple LOD levels. 
	  // - The first parameter is the number of LOD levels
	  // - The second array is a pointer to an array of Lists. Each array element corresponds to a LOD level with the highest detail LOD first. The lists contain all the 
	  //   surfaces of which this LOD level consists of. A surface is basically a group of polygons/triangles that use the same material
	  // - The third parameter is an array of all materials. This array holds as many entries as there are surfaces, NOT LODs! Basically each surface in a LIST of
	  //   surfaces per LOD corresponds to the material at the given index position in the material array. I was not able to find out if lower LOD levels could
	  //   use fewer materials than the highest LOD level. Maybe providing an empty surface with no polygons for the unused material will do the trick,but that is 
	  //   a guess only! In general: Each LIST of surfaces should contain the same number of elements in all LOD levels and the number of entries in each list
	  //   must be equal to the number of elements in the material array
	  // - The skin array holds the skinning data that describes how each vertex corresponds to a bone. If the mesh is not to be attached to a skeleton,this can be NULL.
	  //   This array bascially contains one entry per vertex that was used when assembling the polygons
	  // ----------------------------------------------------------------------------------------------------------------------------------------------------------------
	  List<GeometrySurface>			c_list_surface;
	  const List<GeometrySurface> 		*pc_surfaceTable = &c_list_surface;
	  Array<C4::MaterialObject *> 		apc_material_array(1);

	  c_list_surface.Append( & c_surface_lod_0 );
	  apc_material_array.AddElement(mpc_material_object);


	  pc_custom_node	= new MeshGeometry( 1, & pc_surfaceTable, apc_material_array, & ps_skinData ); 
  
	  // --- patric ----
	  // ----------------------------------------------------------------------------------------------------------------------------------------------------------------
	  // The boneweights can be deleted now since the constructor copied them. Actually, everythign can be deleted since the node/geometry copied all data :)
	  // We call Release() on the material here since we don't need the material in our application and the model geometry (object?) holds a reference tio the material 
	  // as well, so deleting the mesh later will delete the material.
	  // If your applicaitn needs access to the material as well, keep a reference but release it when you delete the mesh node or the model 
	  // ----------------------------------------------------------------------------------------------------------------------------------------------------------------
	  delete aps_weight_table[0];
	  delete aps_weight_table[1];
	  delete aps_weight_table[2];
	  c_list_surface.RemoveAll();
	  mpc_material_object->Release();
	  delete [] s_skinData.nodeHashArray;
	  delete [] s_skinData.inverseBindTransformArray;



	  // --- patric ----
	  // ----------------------------------------------------------------------------------------------------------------------------------------------------------------
	  // This flag MUST be set or the mesh node is treated like a bone by the animator which will make it crash since then the number of bones in the model which was
	  // loaded earlier without the geometry will not be equal to the number of subnodes of the model (which are all bones plus the attached geometry node). In short,
	  // the number of subnodes of the model will be NOF bones + 1 (the geometry node) while the animation file only has the NOF bones stored. Each node attached
	  // to the model which is not a bone should have this flag set.
	  // ----------------------------------------------------------------------------------------------------------------------------------------------------------------
	  pc_custom_node->SetNodeFlags( pc_custom_node->GetNodeFlags() | kNodeAnimateInhibit);








	  // --- patric ----
	  // ################################################################################################################################################################
	  // Attach this model to the root scene node, then attach the preapred gemoetry as a child to the model. This will
	  // make the geometry a subordinate node to the model (which has the skeleton) and will allow the skin controller to deform the geometry according to the
	  // bones in the model.
	  // Now as for the Preprocess() calls, I don't know the exact rules for their calling but what I found out is that it is pretty important to call them at 
	  // the right time :)
	  // Basically, a node must be attached to it's parent (not sure about being attached to the world) and then call Preprocess() which is where many internal data
	  // structures are created. Think of it as a call to Create() or Initialize() instead. If a scene does not show the expected results, look into Preprocess() calls
	  // in any case, this might be th reason.
	  // ################################################################################################################################################################
	  pc_world->GetRootNode()->AddNewSubnode(mpc_animated_skeleton);
	  mpc_animated_skeleton->Update();
	  mpc_animated_skeleton->AddNewSubnode(pc_custom_node);
	  mpc_animated_skeleton->Preprocess();
	  pc_custom_node->Preprocess();


	  // --- patric ----
	  // ----------------------------------------------------------------------------------------------------------------------------------------------------------------
	  // Create a skin controller and attach it to the model. This will keep the mesh geometry updates with any animation the model (skeleton) performs
	  // ----------------------------------------------------------------------------------------------------------------------------------------------------------------
	  SkinController		*pc_skin_controller;

	  pc_skin_controller	= new SkinController;
	  pc_custom_node->SetController(pc_skin_controller);
	  pc_skin_controller->Preprocess();
	  pc_custom_node->Preprocess();	// <- This MUST be called again after the skin controller was added!!



	  // --- patric ----
	  // ################################################################################################################################################################
	  // Add a spin controller to the node so that we can see it from all sides
	  // ################################################################################################################################################################
	  SpinController		*pc_controller;

	  pc_controller	= new SpinController;

	  mpc_animated_skeleton->SetController(pc_controller);
	  pc_controller->Preprocess();








	  // --- patric ----
	  // ################################################################################################################################################################
	  // Create a simple animation on the model. This animation was previously created with the Model viewer by importing it from a .DAE file. I'm not very familiar
	  // with those peculiarities so I can't go into details regarding importing models and animations but it seems to be pretty functional and reasonably well
	  // documented so I refere you to other places in the Wiki
	  // ################################################################################################################################################################
	  mpc_frame_animator_walk	= new FrameAnimator(mpc_animated_skeleton);
	  mpc_frame_animator_walk->SetAnimation("TPose_Animation/tpose_female");
	  mpc_frame_animator_walk->GetWeightInterpolator()->SetValue(1.0f);
	  mpc_frame_animator_walk->GetWeightInterpolator()->SetRate((K::two_pi / 1000.0F) * 0.1f); // This should make the animation 10 times as long as it was originally designed, but I haven't figured ou the rate thing yet
	  mpc_frame_animator_walk->GetFrameInterpolator()->SetMode(kInterpolatorForward | kInterpolatorLoop);
	  mpc_animated_skeleton->SetRootAnimator(mpc_frame_animator_walk);
	  mpc_frame_animator_walk->Preprocess();

	  // You could add this for a non loop animation to get a callback when the animation terminates
	  //mpc_frame_animator_walk->GetFrameInterpolator()->SetCompletionProc(&RunComplete, this);


	  // --- patric ----
	  // ----------------------------------------------------------------------------------------------------------------------------------------------------------------
	  // This deforms the skeleton to the first frame of the animation. Thjis function must later be called once per frame to keep the animation going
	  // ----------------------------------------------------------------------------------------------------------------------------------------------------------------
	  mpc_animated_skeleton->Animate();


	}

}


Well, that's all folks. I hope this helps somebody with the same requirements I had :)
